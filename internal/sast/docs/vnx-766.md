title: "VNX-766 – Critical Data Element Declared Public"
description: "Reports Java fields declared public that hold secret material: non-final public password, secret, API key, private key, token or credential fields of a string-like type, public PrivateKey/SecretKey/KeyPair/KeyStore fields, and public final char[]/byte[] secrets."
---

## Overview

VNX-766 maps to [CWE-766: Critical Data Element Declared Public](https://cwe.mitre.org/data/definitions/766.html). It reports a Java class field that is declared `public` and holds secret material:

- a non-final public field of type `String`, `char[]`, `byte[]`, `CharSequence`, a `Map`/`Properties` or a `*Credentials` type whose name says it is a password, secret, API key, private/signing/encryption/master key, token or credential;
- any public field typed `PrivateKey`, `SecretKey`, `KeyPair`, `KeyStore` or `SecretKeySpec`;
- a `public final char[]` or `byte[]` secret: `final` freezes the reference, not the contents.

Not reported: private, protected and package-private fields, `public static final String` constants (these are nearly always parameter or header names such as `PASSWORD_PARAM`), non-secret types (`boolean passwordExpired`, `int tokenCount`), names that describe metadata about a secret (`passwordHint`, `tokenUrl`, `tokenType`), local variables, comments, string literals and test sources.

**Severity:** Low | **CWE:** [CWE-766](https://cwe.mitre.org/data/definitions/766.html) | **Languages:** java

## Why This Matters

A public field has no access control at all: any class in the process, including a plugin, a deserialisation gadget or a logging helper that reflects over objects, can read the secret or overwrite it. A public mutable buffer also cannot be wiped reliably, because the owning class does not know who else holds it.

## What Gets Flagged

```java
public class MailSettings {
    public String password;                                   // flagged
    public static String apiKey = System.getenv("MAIL_API_KEY"); // flagged
    public PrivateKey signingKey;                             // flagged
    public static final char[] MASTER_PASSWORD = {'c', 'h'};  // flagged: contents are mutable
}
```

Not flagged:

```java
public static final String PASSWORD_PARAM = "password";
private String password;
public boolean passwordExpired;
```

## Remediation

1. Make the field `private` and expose only what callers need: a method that uses the secret, or an accessor that returns a copy.
2. Keep keys in a `KeyStore` or secret manager and pass them to the code that uses them rather than publishing them on a settings object.
3. Hold passwords in `char[]` owned by one class and clear them with `Arrays.fill` after use.
