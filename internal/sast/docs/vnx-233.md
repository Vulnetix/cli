description: "Python request parameters (request.GET/POST/args/form/json/get_json()/data/query_params) are unpacked with ** into a call or dict, inline or through a variable, so every extra parameter a client sends is accepted."
---

## Overview

VNX-233 maps to [CWE-233: Improper Handling of Parameters](https://cwe.mitre.org/data/definitions/233.html). It reports Python `**` unpacking of a Flask, Django or DRF request mapping (`request.GET`, `POST`, `args`, `form`, `values`, `json`, `get_json()`, `data`, `query_params`, `params`, with or without `.dict()`, `.to_dict()` or `.copy()`) into a call or dict literal, inline or through a variable assigned from one in the ten lines above.

**Severity:** Low | **CWE:** [CWE-233](https://cwe.mitre.org/data/definitions/233.html) | **Languages:** python

## Why This Matters

The code never decides which parameters it accepts, so it handles extra and undefined ones by passing them on. Into an ORM `filter()` a client can add lookups such as `password__startswith=a` and read a field one character at a time; into a constructor, `create()` or `update()` it can set fields the form never offered (`is_admin`, `owner_id`).

Not reported: explicit keyword arguments, a dict built by a comprehension that filters keys, `serializer.validated_data` and `form.cleaned_data`, `**kwargs` in a `def`, exponentiation, the text in comments and string literals, and test code.

## What Gets Flagged

```python
users = User.objects.filter(**request.GET.dict())
user = User(**request.json)

data = request.get_json()
account.update(**data)
```

## Remediation

Name the parameters you accept, or unpack validated data:

```python
ALLOWED = {"name", "email"}
fields = {k: v for k, v in request.json.items() if k in ALLOWED}
User(**fields)

serializer.is_valid(raise_exception=True)
Invoice.objects.create(**serializer.validated_data)
```
