title: "VNX-578 – EJB Bad Practices: Use of Class Loader"
description: "Reports an Enterprise JavaBean that obtains, creates, replaces or defines classes with a class loader, which the EJB specification forbids."
---

## Overview

VNX-578 maps to [CWE-578: EJB Bad Practices: Use of Class Loader](https://cwe.mitre.org/data/definitions/578.html). The EJB specification forbids a bean to create a class loader, obtain the current one, set the context class loader or define classes. The container controls class loading to keep applications isolated and to apply its security policy; a bean that loads code itself can run classes the container never vetted and reach classes of other deployed applications.

**Severity:** Low | **CWE:** [CWE-578](https://cwe.mitre.org/data/definitions/578.html) | **Languages:** java

## What Gets Flagged

A class counts as an EJB when its file imports `javax.ejb` or `jakarta.ejb` and declares `@Stateless`, `@Stateful`, `@Singleton` or `@MessageDriven`, or implements `SessionBean`, `EntityBean` or `MessageDrivenBean`. In such a file:

```java
@Stateless
public class PluginService {
    public Object load(URL jar, String type) throws Exception {
        try (URLClassLoader loader = new URLClassLoader(new URL[] {jar})) {
            ...
```

```java
ClassLoader previous = Thread.currentThread().getContextClassLoader();
Thread.currentThread().setContextClassLoader(custom);
return getClass().getClassLoader().getResourceAsStream("cart-rules.xml");
ClassLoader sys = ClassLoader.getSystemClassLoader();
```

Instantiating a `ClassLoader` subclass declared in the file, and `defineClass`/`defineHiddenClass` calls, are reported too.

## What Is Not Flagged

- The same calls in Spring beans, servlets and other classes that are not EJBs.
- `Class.forName`.
- A `ClassLoader` subclass that is declared but never instantiated.
- Test code, comments and string literals.

## Remediation

1. Let the container load classes: inject dependencies with `@EJB`/`@Inject` and package plugins as part of the deployment.
2. Read bundled resources through the container (`@Resource`, JNDI) or move the class-loading work into a component that is not an enterprise bean.
