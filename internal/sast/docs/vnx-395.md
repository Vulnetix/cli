## Overview

VNX-395 maps to [CWE-395: Use of NullPointerException Catch to Detect NULL Pointer Dereference](https://cwe.mitre.org/data/definitions/395.html). It reports Java `catch (NullPointerException e)` (including `final`, `java.lang.NullPointerException` and multi-catch `A | NullPointerException e`), Kotlin `catch (e: NullPointerException)` and `catch (e: KotlinNullPointerException)`, and C# `catch (NullReferenceException)` with or without a variable, including `System.NullReferenceException`.

Not reported: throwing `NullPointerException`, `Objects.requireNonNull`, `assertThrows(NullPointerException.class, ...)`, `instanceof` tests, class names that merely contain the word, test files, comments and strings.

**Severity:** Medium | **CWE:** [CWE-395](https://cwe.mitre.org/data/definitions/395.html) | **Languages:** java, kotlin, csharp

## Why This Matters

Catching the null-dereference exception hides which reference was null, costs a stack unwind for what should be a branch, and also swallows null-pointer bugs thrown by unrelated code deeper in the call, so a real defect is reported as "anonymous user" or `-1`.

## What Gets Flagged

```java
try {
    return user.getProfile().getDisplayName().trim();
} catch (NullPointerException e) {          // FLAGGED
    return "anonymous";
}
```

```kotlin
} catch (e: NullPointerException) {          // FLAGGED
```

```csharp
catch (NullReferenceException)               // FLAGGED
```

## Remediation

1. Test the reference for null, or use `Optional`, Kotlin `?.`/`?:`, or C# `?.`/`??`.
2. Validate required arguments at the boundary with `Objects.requireNonNull` or `ArgumentNullException.ThrowIfNull`.
