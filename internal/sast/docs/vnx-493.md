## Overview

VNX-493 maps to [CWE-493: Critical Public Variable Without Final Modifier](https://cwe.mitre.org/data/definitions/493.html). It reports public, writable fields whose names mark them as critical: credentials, privilege flags and money.

**Severity:** Low | **CWE:** [CWE-493](https://cwe.mitre.org/data/definitions/493.html) | **Languages:** java, csharp

## Why This Matters

A public field without `final` (Java) or `readonly` (C#) can be reassigned by any code that can see the class. A static one is shared process-wide. If an authorization check reads `Settings.isAdmin`, or a checkout reads `product.price`, whoever can write the field decides the outcome.

## What Gets Flagged

```java
public static String DB_PASSWORD = System.getenv("DB_PW");   // FLAGGED
static public boolean isAdmin = false;                          // FLAGGED
public float price;                                              // FLAGGED
public static final String PASSWORD_PARAM = "password";         // not flagged
```

```csharp
public static string ConnectionPassword = "";   // FLAGGED
public decimal Price;                            // FLAGGED
public decimal Price { get; private set; }       // not flagged: property
public static readonly string ApiKeyName = "key"; // not flagged
```

## Remediation

1. Make the field `private` and expose a getter (and, only where needed, a validated setter).
2. If the value never changes after initialisation, declare it `final` / `readonly`.
3. Keep credentials out of fields altogether; read them from a secret store when needed.
