## Overview

Reports an <activity>, <activity-alias>, <service>, <receiver> or <provider> in AndroidManifest.xml that declares android:exported="true" and no android:permission (nor android:readPermission/android:writePermission for a provider): any app on the device can start, bind, broadcast to or query it (CWE-926). The finding is on the android:exported line, and the start tag may span several lines. Not reported: the launcher activity (an intent-filter with category LAUNCHER or LEANBACK_LAUNCHER, which must be exported), components that are not exported or protected by a permission, commented-out elements, and XML files other than AndroidManifest.xml. Components exported implicitly by an intent-filter on old target SDKs are not reported, because the target SDK is not known from the manifest line.

**Severity:** Medium | **CWE:** [CWE-926: Improper Export of Android Application Components](https://cwe.mitre.org/data/definitions/926.html) | **Languages:** AndroidManifest.xml

## Why This Matters

An exported component is an entry point any other app on the device can call. With no permission on it, a malicious app can start the activity with crafted extras, bind to the service, send forged broadcasts to the receiver or read and write the provider's data, using the component's own privileges.

## What Gets Flagged

```
<service android:name=".PlaybackService" android:exported="true"/>

<provider
    android:name=".NotesProvider"
    android:authorities="com.example.notes"
    android:exported="true" />
```

## What Is Not Flagged

```
<!-- launcher activity: must be exported -->
<activity android:name=".MainActivity" android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>
</activity>

<service android:name=".SyncService"
    android:exported="true"
    android:permission="com.example.permission.SYNC" />
```

## Remediation

1. Set `android:exported="false"` on every component that only your own app uses.
2. When another app must reach the component, protect it with `android:permission` naming a `signature`-level permission you declare.
3. For a provider, use `android:readPermission`/`android:writePermission` or `android:grantUriPermissions` with per-URI grants.
4. For a confirmed false positive, add a `vulnetix-ignore: VNX-926` comment on the line.
