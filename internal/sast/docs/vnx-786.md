---

## Overview

VNX-786 maps to [CWE-786: Access of Memory Location Before Start of Buffer](https://cwe.mitre.org/data/definitions/786.html). It reports C and C++ indexing that reaches before the start of a buffer when a length is zero or a call failed:

- `X[strlen(Y) - 1]` with no length or first-byte check in the three lines above
- `X[n - 1]` where `n` was assigned from `strlen()` and never checked before the index
- `X[n]` or `X[n - 1]` where `n` came from `read()`, `recv()`, `recvfrom()`, `readlink()` or `pread()`, which return -1 on error, and was never checked
- a literal negative index (`counts[-1]`) on a name whose nearest declaration is an array

Negative indexes on pointers into the middle of a buffer (`p[-1]`) and lengths compared anywhere between the assignment and the index are not reported.

**Severity:** Medium | **CWE:** [CWE-786](https://cwe.mitre.org/data/definitions/786.html) | **Languages:** c, cpp

## Why This Matters

`line[strlen(line) - 1] = '\0'` after `fgets()` writes `line[-1]` when the line is empty (an input starting with a NUL byte is enough). `buf[n] = '\0'` after a failed `read()` writes `buf[-1]`. Both corrupt the byte before the buffer, which is often a saved pointer or another variable.

## What Gets Flagged

```c
line[strlen(line) - 1] = '\0';          // FLAGGED: empty line writes line[-1]

ssize_t n = read(fd, buf, sizeof(buf) - 1);
buf[n] = '\0';                          // FLAGGED: n is -1 on error
```

Not flagged:

```c
size_t len = strlen(s);
if (len > 0 && s[len - 1] == '\n')
    s[len - 1] = '\0';
```

## Remediation

1. Check the length is non-zero before subtracting one from it.
2. Check `read()`/`recv()` results for `< 0` (and `== 0`) before using them as an index.
