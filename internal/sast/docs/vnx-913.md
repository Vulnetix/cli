title: "VNX-913 – Request Data Chooses the File of Code Loaded or Run"
description: "Detects HTTP request data naming a script, plugin or native library file that the process loads or executes, in Java, Python, Node.js and Go."
---

## Overview

CWE-913 is improper control of dynamically-managed code resources. This rule reports one slice of it: HTTP request data that chooses the **file** of code the process loads or runs. A requester who controls the path can point the server at an uploaded script, a world-writable directory or a traversal like `../../tmp/x`, and the file runs with the server's privileges.

The rule follows the request value inline, through string building, or through a variable assigned or destructured from it (and one further assignment) in the 25 lines above the call.

**Severity:** High | **CWE:** [CWE-913](https://cwe.mitre.org/data/definitions/913.html) | **Languages:** Java, Python, Node.js, Go

## Reported Sinks

| Language | Sinks |
|---|---|
| Java | `ScriptEngine.eval(new FileReader(path))` (also `InputStreamReader`, `FileInputStream`, `Files.newBufferedReader`), `GroovyShell` `evaluate`/`parse`/`run` with a `File`, `GroovyClassLoader.parseClass`, `URLClassLoader.newInstance`, JNA `Native.load`/`loadLibrary` and `NativeLibrary.getInstance` |
| Python | `runpy.run_path`/`run_module`, `SourceFileLoader`/`SourcelessFileLoader`/`ExtensionFileLoader`, `imp.load_compiled`, `execfile`, `zipimporter`, cffi `ffi.dlopen` |
| Node.js | `new Worker(path)` from `worker_threads`, `Module._load`, `new vm.SourceTextModule`, vm2 `runFile`, `koffi.load`, `ffi.Library` |
| Go | `syscall`/`windows` `LoadDLL`, `NewLazyDLL`, `LoadLibrary`, `purego.Dlopen`, gopher-lua `DoFile`, yaegi `EvalPath` |

```python
script = request.args.get("script")
result = runpy.run_path(script)            # reported
```

```java
String template = request.getParameter("template");
engine.eval(new FileReader("/srv/reports/" + template));   // reported
```

## Not Reported Here

Constant paths, values from configuration or the environment, a path reduced with `basename`/`secure_filename`/`filepath.Base`/`getFileName`, a value checked against an allowlist or a numeric conversion, a path confined by a prefix check (`startsWith`, `startswith`, `HasPrefix`, `commonpath`, `is_relative_to`), and anything in comments or string literals.

Neighbouring CWE-913 shapes belong to other rules, so a line is reported by only one of them:

- Code strings and file contents passed to `eval`, `exec`, `Function` or `vm`, including `exec(open(path).read())`: [VNX-94](../vnx-94/).
- `System.load`, `Runtime.load`, `URLClassLoader` constructors, `plugin.Open`, `ctypes.CDLL`, `import_module`, `require()`/`import()`, `process.dlopen`, Ruby `require`/`load`: [VNX-114](../vnx-114/) and [VNX-1027](../vnx-1027/).
- Reflection that picks a class, module or method: [VNX-470](../vnx-470/).
- PHP `include`/`require`: [VNX-98](../vnx-98/). Mass assignment: [VNX-915](../vnx-915/).

## Remediation

Never build a loadable path from request data. Map the request value to a fixed set of files:

```python
SCRIPTS = {"nightly": "/srv/jobs/nightly.py", "weekly": "/srv/jobs/weekly.py"}
path = SCRIPTS.get(request.args.get("job"))
if path is None:
    abort(400)
runpy.run_path(path)
```

If a file name must come from the client, reduce it to its last element, join it to a fixed directory, resolve the result and check that it is still inside that directory before loading it.
