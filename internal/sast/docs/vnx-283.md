---
title: "VNX-283 – Unverified Ownership"
description: "Detects C/C++ code that trusts a file because its permission bits for group/others are tight (st_mode & S_IWOTH, & 077, std::filesystem perms::others_*) without ever comparing st_uid with the expected owner."
---

## Overview

VNX-283 maps to [CWE-283: Unverified Ownership](https://cwe.mitre.org/data/definitions/283.html). Programs that load keys, configuration or plugins often refuse a file that group or others can read or write. That check is only half of the test: a file with mode `0600` that belongs to another user still passes, and that user controls what the program loads. OpenSSH, sudo and similar tools check the owner as well as the mode.

The rule reports a mode test against group/other bits (`st_mode & S_IWOTH`, `S_IWGRP`, `S_IRWXG`, `S_IRWXO`, `S_IROTH`, `S_IRGRP`, or an octal mask such as `022`, `077`, `0002`; in C++ also `std::filesystem` `permissions()` against `perms::group_*`/`perms::others_*`) with no `st_uid` comparison within 25 lines.

**Severity:** Medium | **CWE:** [CWE-283](https://cwe.mitre.org/data/definitions/283.html) | **Languages:** C, C++

## What Gets Flagged

```c
struct stat st;
if (stat(path, &st) != 0) return -1;
if (st.st_mode & (S_IRWXG | S_IRWXO)) {   /* FLAGGED: owner never checked */
    return -1;
}
return read_key(path);
```

```cpp
return (info.st_mode & 022) == 0;          // FLAGGED
```

## What Is Not Flagged

- A check that also compares `st_uid` (with `getuid()`, `geteuid()`, `0` or a looked-up user).
- Executable-bit and file-type tests (`S_IXUSR`, `S_ISREG`) and copying a mode (`st_mode & 07777`).
- Comments and string literals.

Ownership verified in a different function is not visible to this rule.

## Remediation

Open the file once, `fstat()` the descriptor, and check owner and mode together:

```c
int fd = open(path, O_RDONLY | O_NOFOLLOW);
struct stat st;
if (fd < 0 || fstat(fd, &st) != 0) return -1;
if (st.st_uid != geteuid() && st.st_uid != 0) return -1;
if (st.st_mode & (S_IRWXG | S_IRWXO)) return -1;
```
