## Overview

CWE-932 is an OWASP Top Ten 2013 category with no code shape of its own; this rule reports the concrete C/C++ hardening signal it was generated for, source that turns off a compiler memory-safety defence for the code that follows: #pragma GCC/clang optimize("no-stack-protector"/"-fno-stack-protector"), __attribute__((no_stack_protector)), __attribute__((optimize("no-stack-protector"))), [[gnu::no_stack_protector]], #undef _FORTIFY_SOURCE that is not followed by a non-zero redefinition, #define _FORTIFY_SOURCE 0, and MSVC #pragma strict_gs_check(off) and __declspec(safebuffers). Not reported: optimisation-level pragmas and attributes (O0, O2, O3; optimize("O0") is the usual secure-zeroing idiom), _FORTIFY_SOURCE set to 1-3, comments and strings, and test or fuzzing code. Build-system flags (-fno-stack-protector in a Makefile) are out of scope.

**Severity:** Low | **CWE:** [CWE-932: OWASP Top Ten 2013 Category A4 - Insecure Direct Object References](https://cwe.mitre.org/data/definitions/932.html) | **Languages:** C, C++

## Why This Matters

Stack canaries, FORTIFY_SOURCE and MSVC /GS stop many buffer overflows from turning into code execution. Switching them off in source silently removes that protection from the code that follows, whatever the build flags say.

## What Gets Flagged

```
#pragma GCC optimize ("no-stack-protector")
__attribute__((no_stack_protector)) void decode(const char *in, char *buf) {
[[gnu::no_stack_protector]] int scan(char *line);
#undef _FORTIFY_SOURCE
#define _FORTIFY_SOURCE 0
#pragma strict_gs_check(off)
__declspec(safebuffers) void copy_name(char *dst, const char *src) {
```

## What Is Not Flagged

```
#pragma GCC optimize ("O2")
__attribute__((optimize("O0"))) void secure_zero(void *p, size_t n);
#undef _FORTIFY_SOURCE
#define _FORTIFY_SOURCE 3
```

## Remediation

1. Remove the pragma or attribute and fix whatever made it necessary.
2. Confine it to code that runs before the stack canary is initialised (early boot, a TLS setup routine) and document why.
3. For a confirmed false positive, add a `vulnetix-ignore: VNX-932` comment on the line.
