---
title: "VNX-462 – Duplicate Key in Associative List (Alist)"
description: "Reports a Python dict literal that names the same string or integer key twice at the same level, where the later entry silently replaces the earlier one."
---

## Overview

VNX-462 maps to [CWE-462: Duplicate Key in Associative List (Alist)](https://cwe.mitre.org/data/definitions/462.html). It reports, in a multi-line dict literal, an entry whose key (a string in either quote style, or an integer) an earlier entry at the same indentation of the same literal already used, and a single-line `{...}` literal without nested braces that repeats a key. The same key in sibling nested dicts or in different dicts of a list, keys that differ only in case, set literals, `dict()`/`update()` calls and computed keys are not reported.

**Severity:** Low | **CWE:** [CWE-462](https://cwe.mitre.org/data/definitions/462.html) | **Languages:** python

## Why This Matters

Python keeps only the last value for a repeated key and raises no error. A security setting written correctly at the top of a configuration dict and contradicted further down is silently disabled.

## What Gets Flagged

```python
SECURITY = {
    "session_cookie_secure": True,
    "hsts_seconds": 31536000,
    "session_cookie_secure": False,   # FLAGGED: replaces the True above
}

# NOT FLAGGED: same key in different nested dicts
SCHEMA = {"user": {"type": "object"}, "group": {"type": "object"}}
```

## Remediation

1. Remove the duplicate entry and keep the value that was intended.
2. Enable a linter check for duplicate keys (for example pyflakes F601) in CI.
3. For confirmed false positives, add a `# vulnetix-ignore: VNX-462` comment on the line.
