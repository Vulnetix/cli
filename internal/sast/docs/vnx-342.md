## Overview

VNX-342 maps to [CWE-342: Predictable Exact Value from Previous Values](https://cwe.mitre.org/data/definitions/342.html). A session id, reset code or token that is the previous one plus one is not a secret: a user who receives their own value knows the value issued just before and the one that will be issued next.

The rule reports an increment (`++x`, `x++`, `x += 1`, `x + 1`, `incrementAndGet()`/`getAndIncrement()`/`addAndGet()`, Go `atomic.AddInt64`/`AddUint64` and `.Add(1)`, Python `next(counter)`, Ruby `.succ`/`.next`) of a variable named as a counter or previous value (count, ctr, seq, last, prev, next, serial, latest, max, id, num) or for a secret, when:

- the incremented variable is itself named for a secret (`$_SESSION['last_session_id']++`, `captchaId++`), or
- its result is stored under, returned as or set as the cookie value of a secret (token, password, session id, reset/confirmation/invite code, OTP, CSRF, API key) on the same line, or
- a standalone increment is followed within four lines by a use of the variable as a secret, or
- the result is assigned to a variable that reaches a secret within six lines.

**Severity:** Medium | **CWE:** [CWE-342](https://cwe.mitre.org/data/definitions/342.html) | **Languages:** java, kotlin, python, node, php, ruby, go

## What Gets Flagged

```php
// FLAGGED: the session cookie is a counter
$_SESSION['next_session_id']++;
setcookie("appSession", $_SESSION['next_session_id']);
```

```java
// FLAGGED
public String newSessionId() {
    return Long.toString(counter.incrementAndGet());
}
String resetToken = String.valueOf(++lastToken);
```

```python
# FLAGGED
session_id = str(next(_ids))
```

```go
// FLAGGED
id := atomic.AddInt64(&sessionCounter, 1)
return strconv.FormatInt(id, 10)
```

## What Is Not Flagged

- Anonymous loop variables (`i++`, `n += 1`) and loop headers.
- Counters used as nonces, IVs, JWT ids or message sequence numbers: they need uniqueness, not secrecy. HOTP/HMAC over a counter.
- Counts, indexes, attempts and other bookkeeping names (`tokenCount++`, `$_SESSION['login_attempts']++`, `this.tokenPos++`), order and request ids.
- A line that also draws from a CSPRNG, test files, and the pattern in comments or string literals.

A secret that mixes a counter with the clock is also reported by VNX-341.

## Remediation

1. Generate each secret independently with a CSPRNG: `secrets.token_urlsafe()`, `crypto.randomBytes()`, `random_bytes()`, `SecureRandom`, `crypto/rand`, `SecureRandom.hex`.
2. Keep sequential ids for database keys and ordering, and never hand them out as credentials.
3. For confirmed false positives, add a `# vulnetix-ignore: VNX-342` comment on the line.
