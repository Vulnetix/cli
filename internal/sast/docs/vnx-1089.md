## Overview

VNX-1089 maps to [CWE-1089: Large Data Table with Excessive Number of Indices](https://cwe.mitre.org/data/definitions/1089.html). A table defined in the project's SQL files that carries more than 8 secondary indices.

**Severity:** Low | **CWE:** [CWE-1089](https://cwe.mitre.org/data/definitions/1089.html) | **Languages:** SQL

## Why This Matters

Every index is updated on every insert, update and delete. A heavily indexed table that grows large slows every write and can be pushed into exhausting I/O. CISQ, which CWE-1089 cites, suggests 3 indices for a table of a million rows.

## What Gets Flagged

One finding per table, at its first `CREATE TABLE` line (or its first index when the table is created elsewhere):

```sql
CREATE TABLE orders (            -- FLAGGED: 9 indices
    id BIGSERIAL PRIMARY KEY,
    ...
);
CREATE INDEX idx_orders_customer ON orders (customer_id);
CREATE INDEX idx_orders_status ON orders (status);
create index idx_orders_created on orders(created_at);
CREATE UNIQUE INDEX IF NOT EXISTS idx_orders_upd ON public.orders USING btree (updated_at);
-- ... five more
```

Counted: distinct index names from `CREATE [UNIQUE] INDEX` across every `.sql` file, so indices added in later migrations count, plus inline MySQL `KEY`/`INDEX`/`UNIQUE KEY`/`FULLTEXT KEY` definitions in the `CREATE TABLE` body.

## What Does Not Get Flagged

- Tables with 8 indices or fewer.
- A `CREATE INDEX IF NOT EXISTS` repeated in a later migration (counted once), and indices removed by `DROP INDEX`.
- The primary key, UNIQUE/CHECK constraints, and columns named `key` or `index`.
- Statements in `--` or `/* */` comments or inside string literals.

A table's row count cannot be known statically, so every table over the threshold is reported. The threshold of 8 is this rule's choice, set above the CISQ figure so the rule points at outliers.

## Remediation

1. Check which indices queries actually use (`pg_stat_user_indexes`, `sys.dm_db_index_usage_stats`, MySQL `sys.schema_unused_indexes`) and drop the unused ones.
2. Replace overlapping single-column indices with one composite index that serves the same queries.
3. For a deliberate exception, add `-- vulnetix-ignore: VNX-1089` on the reported line.
