## Overview

VNX-645 maps to [CWE-645: Overly Restrictive Account Lockout Mechanism](https://cwe.mitre.org/data/definitions/645.html). It reports a statement that locks or disables an account (`user.is_locked = True`, `user.active = false`, `{ locked: true }`) on the line of, or just after, a comparison of a failed-login counter with a threshold, when nothing in the file ever lets the lock expire. It also reports `AXES_COOLOFF_TIME = None` in django-axes settings.

**Severity:** Medium | **CWE:** [CWE-645](https://cwe.mitre.org/data/definitions/645.html) | **Languages:** node, python

## Why This Matters

A permanent lockout turns the lockout into a denial-of-service. An attacker who knows or guesses usernames sends a few bad passwords for each and locks every account until an administrator intervenes.

## What Gets Flagged

```python
if user.failed_attempts >= MAX_ATTEMPTS:
    user.is_locked = True          # no locked_until anywhere

AXES_COOLOFF_TIME = None
```

```javascript
if (user.loginAttempts > 5) {
  user.active = false;
}
```

Not flagged: the same lock with `user.locked_until = timezone.now() + timedelta(minutes=15)` or `user.lockUntil = Date.now() + LOCK_TIME`, `AXES_COOLOFF_TIME = timedelta(minutes=30)`, an administrator deactivating a user, and test code.

## Remediation

1. Make the lock expire: store a lock-until time and refuse logins only until then, increasing the delay on repeated lockouts.
2. Prefer throttling by client (IP address or device) plus CAPTCHA over locking the account itself.
3. Notify the account owner when a lockout happens.
