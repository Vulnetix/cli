## Overview

VNX-1339 maps to [CWE-1339: Insufficient Precision or Accuracy of a Real Number](https://cwe.mitre.org/data/definitions/1339.html). Most decimal fractions (0.1, 0.3, 19.99) have no exact binary floating-point representation. A computed value is almost never bit-identical to the rounded literal, so `total == 0.3` is false for `0.1 + 0.2`, and a branch guarded that way silently never runs (or a `!=` loop never ends).

**Severity:** Low | **CWE:** [CWE-1339](https://cwe.mitre.org/data/definitions/1339.html) | **Languages:** python, node, java, go

## Why This Matters

Exact float comparisons in prices, discounts, rates and balances produce wrong totals, skipped promotions and infinite loops. In financial or safety logic the error is a correctness bug that an attacker can sometimes steer by choosing amounts.

## What Gets Flagged

```python
if total == 0.3:              # FLAGGED
while balance != 0.1:         # FLAGGED
if 0.7 == ratio:              # FLAGGED
```

```javascript
if (sum === 0.3) { ... }      // FLAGGED
```

```java
if (rate == 0.05) { ... }     // FLAGGED
return amount != 19.99f;      // FLAGGED
```

```go
if price*0.9 == 8.99 { ... }  // FLAGGED
```

## What Is Not Flagged

- Literals that are exact in binary: `0.5`, `0.25`, `0.125`, `1.0`, `0.0`, `2.75`.
- Exponent forms (`1e-3`), ordering comparisons (`<`, `<=`, `>`, `>=`).
- Comparisons through a tolerance: `math.isclose`, `pytest.approx`, `toBeCloseTo`, `assertAlmostEqual`, `abs(a - b) < eps`.
- Strings (versions, IP addresses), comments and test files.
- Operand types are not known, so an integer variable compared with a fractional literal is also reported.

## Remediation

1. Compare with a tolerance: `math.isclose(a, b, rel_tol=1e-9)`, `Math.abs(a - b) < EPS`.
2. For money, use a decimal type (`decimal.Decimal`, `BigDecimal`) or integer minor units (cents).
