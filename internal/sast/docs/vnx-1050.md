## Overview

VNX-1050 maps to [CWE-1050: Excessive Platform Resource Consumption within a Loop](https://cwe.mitre.org/data/definitions/1050.html). It reports a Python `for` or `while` loop whose body creates a new connection, pool, engine, session or client although nothing passed to the constructor depends on the iteration, so the resource could be created once before the loop.

Constructors recognised: `connect()` of sqlite3, psycopg2, psycopg, pymysql, MySQLdb, mysql.connector, pymssql, pyodbc, cx_Oracle, oracledb, asyncpg and aiomysql; `create_pool()`; `create_engine`/`create_async_engine`; `MongoClient`; `redis.Redis`/`StrictRedis`/`from_url`; `requests.Session`; `httpx.Client`/`AsyncClient`; `aiohttp.ClientSession`; `urllib3.PoolManager`; `boto3.client`/`resource`/`Session`; `pika.BlockingConnection`; `smtplib.SMTP`/`SMTP_SSL`; `ftplib.FTP`.

**Severity:** Low | **CWE:** [CWE-1050](https://cwe.mitre.org/data/definitions/1050.html) | **Languages:** python

## Why This Matters

Each connection costs a TCP and often a TLS handshake, an authentication round trip and server-side memory. Opening one per item turns a batch job into a connection storm that exhausts database connection limits, ephemeral ports and file descriptors.

Not reported: a constructor whose arguments use the loop variable or a name assigned inside the loop (a connection per host, shard or URI), retry and polling loops (the body breaks or sleeps, or the header names a retry or attempt counter), a resource created before the loop, `open()` of a file per iteration, comments, string literals and test files.

## What Gets Flagged

```python
for cid in customer_ids:
    conn = pymysql.connect(
        host=config.DB_HOST,
        user=config.DB_USER,
        database="sales",
    )
```

```python
for event in events:
    session = requests.Session()
    session.post(WEBHOOK, json=event.to_dict(), timeout=10)
```

Not flagged:

```python
for host in hosts:
    conn = psycopg2.connect(host=host, dbname="metrics")
```

## Remediation

1. Create the connection, session or client once before the loop and reuse it.
2. Use a connection pool when work is spread across threads or tasks.
3. Close the resource after the loop, for example with a `with` block around it.
