## Overview

VNX-627 maps to [CWE-627: Dynamic Variable Evaluation](https://cwe.mitre.org/data/definitions/627.html). When the client chooses the *name* of the variable a program reads or writes, it can overwrite `$is_admin`, a configuration global or the instance variable that holds the current user, or read a secret the page was never meant to show.

Reported:

- **Python:** `globals()[k]`, `locals()[k]`, `vars()[k]` (or `globals().get(k)`) where `k` is a request value (`request.args`, `form`, `values`, `json`, `GET`, `POST`, `data`, `cookies`, `headers`, `query_params`), and `globals().update(...)`, `vars(x).update(...)`, `x.__dict__.update(...)` with request data.
- **Ruby:** `instance_variable_set`/`get`, `class_variable_set`/`get` and `binding.local_variable_set`/`get` whose name interpolates `params`, `cookies` or request parameters.
- **PHP:** `$$name`, `${$name}` and `${$_GET[...]}` where the name is a superglobal or a variable assigned from one.
- **JavaScript/TypeScript:** `global[...]`, `globalThis[...]`, `window[...]` indexed by `req.query`, `body`, `params`, `cookies` or `headers`.

The request value may be inline or reach the sink through a variable assigned from it, a destructuring, a `for` loop or an `each` block in the 10 lines above.

**Severity:** High | **CWE:** [CWE-627](https://cwe.mitre.org/data/definitions/627.html) | **Languages:** Python, Ruby, PHP, JavaScript/TypeScript

## What Gets Flagged

```python
for key, value in request.POST.items():
    globals()[key] = value          # FLAGGED
```

```ruby
instance_variable_set("@#{params[:field]}", params[:value])   # FLAGGED
```

```php
$name = $_GET['var'];
$$name = $_GET['value'];            // FLAGGED
```

```javascript
res.send(String(global[req.query.name]));   // FLAGGED
```

## What Is Not Flagged

- Constant names (`globals()["LAST_LOOKUP"] = name`, `instance_variable_set(:@theme, ...)`).
- Names from function parameters or configuration: there is no cross-function dataflow.
- Ordinary dictionary or object lookups (`HANDLERS.get(name)`, `handlers[req.query.name]`).
- PHP variable variables inside a `foreach` over a superglobal and `extract()`: [VNX-PHP-007](../vnx-php-007/) reports those.
- The sinks inside comments or string literals.

## Remediation

Never let input name a variable. Map the allowed names to values explicitly:

```python
ALLOWED = {"theme", "locale"}
settings = {k: v for k, v in request.form.items() if k in ALLOWED}
```
