## Overview

VNX-378 maps to [CWE-378: Creation of Temporary File With Insecure Permissions](https://cwe.mitre.org/data/definitions/378.html). It reports:

- the name-only temporary file functions `tmpnam`, `tmpnam_r`, `tempnam`, `mktemp` and Windows `_mktemp`/`_tempnam`/`_wtmpnam`/`_wmktemp` (also `std::` or `::` qualified), which return a name without creating the file;
- `open()` or `creat()` of a path in `/tmp/`, `/var/tmp/` or `/dev/shm/` (a literal, or a variable assigned one in the 10 lines above) with a mode that grants other users access (an octal mode whose last digit is not 0, `S_IRWXO`, `S_IROTH`, `S_IWOTH`, `S_IXOTH`) and no `O_EXCL`;
- `fopen()` for writing or appending (not the exclusive `x` mode) of a fixed name in those directories, the path a literal or a variable assigned one or filled by `snprintf`/`sprintf`/`strcpy` in the 10 lines above;
- `fchmod()`/`chmod()` that opens such a mode on a descriptor or template returned by `mkstemp()` in the 10 lines above.

Not reported: `mkstemp`, `mkostemp`, `mkdtemp`, `tmpfile`, owner-only modes (`0600`, `0640`, `S_IRUSR | S_IWUSR`), opens outside shared temporary directories, prototypes and C++ members declared with these names, lookalike identifiers and members (`my_mktemp`, `obj.mktemp()`), read-only opens, comments and string literals.

**Severity:** High | **CWE:** [CWE-378](https://cwe.mitre.org/data/definitions/378.html) | **Languages:** c, cpp

## Why This Matters

A temporary file whose name is chosen before it is created can be created first by another local user, often as a symlink to a file the program can write. A file in a shared directory created readable or writable by others leaks or accepts whatever the program puts in it.

## What Gets Flagged

```c
if (tmpnam(name) == NULL)                                    // FLAGGED
char *p = mktemp(tmpl);                                      // FLAGGED
int fd = open("/tmp/agent.lock", O_RDWR | O_CREAT, 0666);    // FLAGGED
return creat("/tmp/daemon.pid", 0644);                       // FLAGGED
FILE *fp = fopen("/tmp/state.dump", "w");                    // FLAGGED
int fd = mkstemp(tmpl);
fchmod(fd, 0666);                                            // FLAGGED
```

Not flagged: `int fd = mkstemp(tmpl);`, `FILE *f = tmpfile();`, `open("/tmp/x", O_CREAT | O_EXCL | O_WRONLY, 0600)`.

## Remediation

1. Use `mkstemp()`/`mkostemp()` (files) or `mkdtemp()` (directories), which create the entry atomically with mode 0600/0700, or `tmpfile()`.
2. When a fixed path is unavoidable, open it with `O_CREAT | O_EXCL` and mode `0600`, in a directory only the program's user can write.
3. Do not widen the permissions of a temporary file after creating it.
