## Overview

VNX-358 maps to [CWE-358: Improperly Implemented Security Check for Standard](https://cwe.mitre.org/data/definitions/358.html). TLS server identity has a standard (RFC 6125) and every platform ships an implementation of it. This rule reports hand-written replacements that check the identity with a partial string match:

- **Java**: a `HostnameVerifier` `verify(String host, SSLSession s)` method, or a `(host, session) ->` lambda passed to `setHostnameVerifier` / `setDefaultHostnameVerifier` / `hostnameVerifier`, that tests the host with `endsWith`, `startsWith`, `contains`, `indexOf` or `matches` and does not delegate to another verifier's `verify()`.
- **Java**: a certificate subject or issuer name (`getSubjectDN()`, `getSubjectX500Principal()`, `getIssuerDN()`, `getIssuerX500Principal()` then `getName()`), inline or through a variable assigned within six lines, tested with `contains`, `startsWith`, `endsWith`, `indexOf` or `matches`.
- **Python**: a function named like `verify_hostname`, `match_host` or `check_server_hostname` whose host-name parameter is tested with `endswith`, `startswith` or `find`, or is the right side of `x in host`, unless the function also calls `ssl.match_hostname` or another verify routine.

Not reported: exact comparisons (`equals`, `==`, a host looked up in an allowlist), a suffix test combined with a delegated `verify()` call, string tests on ordinary paths and names, Python host checks in functions that never touch a certificate, socket or SSL object (HTTP `Host` header validation is not TLS identity), test files, comments and string literals. A verifier that simply returns `true` is VNX-JAVA-006; switching verification off is VNX-CRYPTO-005.

**Severity:** Low | **CWE:** [CWE-358](https://cwe.mitre.org/data/definitions/358.html) | **Languages:** java, python

## Why This Matters

`evilacme.com` ends with `acme.com`, `api.attacker.net` starts with `api.`, and any public CA will issue a certificate whose subject contains the text `CN=api.acme.com` inside another attribute. A partial match accepts all of them, so an attacker who can intercept traffic presents a certificate for a host they control and the client trusts it.

## What Gets Flagged

```java
// FLAGGED
public boolean verify(String hostname, SSLSession session) {
    return hostname.endsWith("acme.com");
}

conn.setHostnameVerifier((h, s) -> h.endsWith(".acme.com"));

String subject = chain[0].getSubjectX500Principal().getName();
if (!subject.contains("CN=api.acme.com")) { throw new CertificateException("untrusted"); }
```

```python
# FLAGGED
def match_host(cert, host):
    cn = dict(x[0] for x in cert["subject"])["commonName"]
    return cn in host
```

```java
// NOT FLAGGED: restricts the host, then delegates to the standard verifier
return hostname.endsWith(".acme.com") && delegate.verify(hostname, session);
```

## Remediation

1. Use the platform verifier: the default `HostnameVerifier` (or OkHttp's), and in Python an `ssl.create_default_context()` with `check_hostname = True`.
2. To trust a specific server, pin its public key (OkHttp `CertificatePinner`, a pinned `TrustManager`) rather than matching names as strings.
3. If names must be compared, compare the exact parsed name, never a substring.
