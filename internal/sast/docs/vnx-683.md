---
title: "VNX-683 – Function Call With Incorrect Order of Arguments"
description: "Detects C and C++ calls with visibly swapped arguments: memset value and length transposed, copies whose destination is named like the source and the source like the destination, and stdio calls given the stream first."
---

## Overview

VNX-683 maps to [CWE-683: Function Call With Incorrect Order of Arguments](https://cwe.mitre.org/data/definitions/683.html). Many C library functions take several arguments of compatible types, so swapping two compiles and does the wrong thing: a key that should be wiped is left in memory, or a copy overwrites its own source.

**Severity:** Low | **CWE:** [CWE-683](https://cwe.mitre.org/data/definitions/683.html) | **Languages:** C, C++

## What Gets Flagged

```c
memset(s->key, sizeof(s->key), 0);   // FLAGGED: clears nothing
memcpy(src, dst, n);                 // FLAGGED: copies backwards
strcat(input, output);               // FLAGGED
fputs(stderr, msg);                  // FLAGGED: stream goes last
fwrite(fp, buf, 1, n);               // FLAGGED
```

- `memset()`/`wmemset()` with a literal `0` or `'\0'` length after a non-zero value.
- `memcpy`, `memmove`, `strcpy`, `strncpy`, `strcat`, `strncat`, `strlcpy`, `stpcpy`, `wcscpy` and `wmemcpy` whose first argument is named like a source (`src`, `source`, `from`, `input`, `in`, `orig`) and whose second is named like a destination (`dst`, `dest`, `to`, `target`, `out`, `output`).
- `fputs`, `fputc`, `putc`, `fwrite`, `fread` and `fgets` with `stdout`, `stderr`, `stdin`, `fp`, `fh` or `stream` as the first argument.

## What Is Not Flagged

- Correctly ordered calls, and `memset(p, 0, 0)`.
- Copies where only one argument has a telling name.
- Comments, string literals and files of other languages.

VNX-628 also reports the transposed `memset` shape.

## Remediation

Compile with `-Wall -Wmemset-transposed-args` and match each call to its signature: `memset(buf, 0, n)`, `memcpy(dst, src, n)`, `fputs(msg, stderr)`, `fwrite(buf, 1, n, fp)`.
