## Overview

CWE-930 is an OWASP Top Ten 2013 category (broken authentication and session management) with no code shape of its own; this rule reports the concrete device-level authorization signal it was generated for: Java or Kotlin code that launches the su binary to run commands as root, through Runtime.getRuntime().exec("su"), exec("su -c ..."), exec(new String[]{"su", ...}) or exec(arrayOf("su", ...)), new ProcessBuilder("su", ...) or ProcessBuilder(listOf/Arrays.asList("su", ...)), and a command array whose first element is su assigned a few lines before the exec. Whatever the root shell runs bypasses the Android permission model. Not reported: root detection (which su, File("/system/xbin/su").exists(), Superuser.apk checks), other commands, comments and strings.

**Severity:** Medium | **CWE:** [CWE-930: OWASP Top Ten 2013 Category A2 - Broken Authentication and Session Management](https://cwe.mitre.org/data/definitions/930.html) | **Languages:** Java, Kotlin

## Why This Matters

A command run through su runs as root, outside the Android sandbox and permission model. Any part of it built from input becomes root code execution, and the app only works on rooted devices.

## What Gets Flagged

```
Process p = Runtime.getRuntime().exec("su");
Runtime.getRuntime().exec(new String[] { "su", "-c", cmd });
ProcessBuilder pb = new ProcessBuilder("su", "-c", cmd);
Runtime.getRuntime().exec(arrayOf("su", "-c", cmd))
```

## What Is Not Flagged

```
// root detection, not root use
boolean rooted = new File("/system/xbin/su").exists();
Runtime.getRuntime().exec(new String[] { "which", "su" });
Runtime.getRuntime().exec("ls -l /data/local/tmp");
```

## Remediation

1. Use a platform API or a privileged system service with a narrow interface instead of a root shell.
2. If root is unavoidable, never build the command from input, and run a fixed command list.
3. For a confirmed false positive, add a `vulnetix-ignore: VNX-930` comment on the line.
