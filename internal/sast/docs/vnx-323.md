---
title: "VNX-323 – Reusing a Nonce, Key Pair in Encryption"
description: "An IV or nonce generated once (module, package or class level, or in a constructor) and reused by the encryption call for every message."
---

## Overview

VNX-323 maps to [CWE-323: Reusing a Nonce, Key Pair in Encryption](https://cwe.mitre.org/data/definitions/323.html). It reports an encryption call inside a function or method whose IV or nonce argument was created once and is never refreshed there:

- a Python module-level variable assigned from `os.urandom`, `get_random_bytes` or `secrets.token_bytes`, or a `self.` attribute set in `__init__`;
- a JavaScript/TypeScript module-level variable assigned from `crypto.randomBytes` or `getRandomValues`, or a `this.` property set in the constructor;
- a Go package-level variable, or a struct field declared as `[]byte`;
- a Java `byte[]` field, used in an `ENCRYPT_MODE` initialisation.

Sinks: Python `AESGCM`/`ChaCha20Poly1305`/`AESCCM` `.encrypt(nonce, ...)`, pycryptodome `.new(..., nonce=/iv=)`, cryptography `modes.CBC`/`CTR`/`GCM`/`CFB`/`OFB`; Node `crypto.createCipheriv(alg, key, iv)` and WebCrypto `{ name: 'AES-GCM', iv }`; Go AEAD `.Seal(dst, nonce, ...)` and `cipher.NewCBCEncrypter`/`NewCTR`/`NewOFB`/`NewCFBEncrypter`; Java `IvParameterSpec`, `GCMParameterSpec` and `ChaCha20ParameterSpec`.

Not reported: an IV or nonce assigned, filled (`rand.Read`, `io.ReadFull`, `nextBytes`, `randomFillSync`, `getRandomValues`) or incremented inside the encrypting function; decryption calls; test files. Hard-coded constant IVs are [VNX-CRYPTO-010](../vnx-crypto-010/)'s concern. Flows through helpers and across files are not followed.

**Severity:** Medium | **CWE:** [CWE-323](https://cwe.mitre.org/data/definitions/323.html) | **Languages:** go, java, node, python

## Why This Matters

A random nonce generated at start-up is still one nonce. Every message encrypted under the same key reuses it: with GCM, CTR and ChaCha20-Poly1305 this leaks the XOR of plaintexts and lets an attacker forge authenticated messages; with CBC it reveals which messages share a prefix.

## What Gets Flagged

```python
# FLAGGED
NONCE = os.urandom(12)

def seal(data):
    return AESGCM(KEY).encrypt(NONCE, data, None)
```

```javascript
// FLAGGED
const iv = crypto.randomBytes(16);
function encrypt(text) {
  const cipher = crypto.createCipheriv('aes-256-ctr', key, iv);
```

```go
// FLAGGED
func (s *Sealer) Encrypt(dst, src []byte) {
	stream := cipher.NewCTR(s.block, s.iv)
```

Not flagged: `nonce = os.urandom(12)` inside the function before `encrypt(nonce, ...)`, `random.nextBytes(iv)` before `new GCMParameterSpec(128, iv)`, `io.ReadFull(rand.Reader, b.nonce)` before `Seal`.

## Remediation

1. Generate a fresh random nonce for every encryption (or use a counter that never repeats under one key) and send it with the ciphertext.
2. Prefer a misuse-resistant AEAD (AES-GCM-SIV, XChaCha20-Poly1305 with random 192-bit nonces) when nonce management is hard.
