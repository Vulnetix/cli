## Overview

VNX-1056 maps to [CWE-1056: Invokable Control Element with Variadic Parameters](https://cwe.mitre.org/data/definitions/1056.html). It reports a C or C++ function definition with a C-style variadic parameter list whose last named parameter is a format string (a `char` pointer named `fmt`, `format`, `msg` or `message`) and whose body forwards the `va_list` to the printf family (`vfprintf`, `vsnprintf`, `vsyslog`, ...), when neither the definition nor any prototype of the function in the scanned sources carries a printf-style format attribute (`__attribute__((format(printf, n, m)))`, `__printflike`, `G_GNUC_PRINTF` and similar macros).

**Severity:** Low | **CWE:** [CWE-1056](https://cwe.mitre.org/data/definitions/1056.html) | **Languages:** c, cpp

## Why This Matters

The arguments after `...` are not type-checked. Without a format attribute the compiler cannot match them to the format string, so a missing, extra or wrongly typed argument is undefined behaviour that reads the stack, and a caller passing an attacker-controlled string as the format goes unnoticed (CWE-134).

Not reported: prototypes, macros (`#define TRACE(fmt, ...)`), function pointers, C++ variadic templates (`typename... Args`, which are type-checked), variadic functions whose last named parameter is a count or a sentinel-terminated pointer, wrappers with a custom (non-printf) format, wrappers attributed in a header, and comments.

## What Gets Flagged

```c
void log_event(int level, const char *fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    vfprintf(stderr, fmt, ap);
    va_end(ap);
}
```

Not flagged:

```c
int buf_printf(struct buf *b, const char *fmt, ...)
    __attribute__((format(printf, 2, 3)));
```

## Remediation

1. Add `__attribute__((format(printf, n, m)))` (or the project's portable macro) to the prototype, where `n` is the format parameter's position and `m` the position of `...`.
2. In C++, prefer a variadic template or `std::format`, which check argument types at compile time.
