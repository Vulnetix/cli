---

## Overview

VNX-792 maps to [CWE-792: Incomplete Filtering of One or More Instances of Special Elements](https://cwe.mitre.org/data/definitions/792.html). It reports markup sanitising that handles only the first occurrence:

- JavaScript/TypeScript `String.replace()` with a string literal, or a regex literal without the `g` flag, whose pattern is `<`, `>`, `&`, a quote, a `<script`/`<iframe` tag, `javascript:` or an event-handler attribute, replaced with nothing or with an HTML entity
- Python `str.replace(..., 1)` and `re.sub(..., count=1)` with the same tokens

Global replacements (`/g`, `replaceAll`, Python's default replace-all), template substitutions whose replacement is markup, and path or command tokens (reported by VNX-793) are not reported.

**Severity:** Low | **CWE:** [CWE-792](https://cwe.mitre.org/data/definitions/792.html) | **Languages:** node, python

## Why This Matters

In JavaScript, `'a<b<c'.replace('<', '&lt;')` returns `a&lt;b<c`. Only the first bracket is escaped, so a payload that starts with a harmless `<` puts the next one into the page unescaped.

## What Gets Flagged

```javascript
return text.replace('<', '&lt;')        // FLAGGED
           .replace(">", "&gt;");       // FLAGGED
body = body.replace("<script>", "");    // FLAGGED
return s.replace(/</, '&lt;');          // FLAGGED: no g flag
```

```python
return s.replace("<", "&lt;", 1)        # FLAGGED
```

## Remediation

1. Use a context-aware encoder or the template engine's auto-escaping.
2. If you must replace by hand, use `replaceAll` or a `/g` regex, and escape `&` first.
