## Overview

VNX-820 maps to [CWE-820: Missing Synchronization](https://cwe.mitre.org/data/definitions/820.html). Servlets and Spring singletons are shared by every request thread; a field written from a request handler without a lock is a data race.

**Severity:** Medium | **CWE:** [CWE-820](https://cwe.mitre.org/data/definitions/820.html) | **Languages:** java

## What Gets Flagged

```java
public class HitServlet extends HttpServlet {
    private int hits;
    private String lastUser;
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
        hits++;                                   // FLAGGED
        lastUser = req.getParameter("user");      // FLAGGED: one user's value seen by another
    }
}

@Component
public class SessionCache {
    private final Map<String, String> sessions = new HashMap<>();
    public void remember(String id, String user) {
        sessions.put(id, user);                   // FLAGGED: HashMap mutated concurrently
    }
}
```

Not flagged: `ConcurrentHashMap`/`AtomicInteger` fields, writes inside `synchronized`, constructor and `init()` writes, `@Scope("prototype")` beans, locals that shadow the field.

```java
// FLAGGED: a classic servlet Filter shares one instance
public class RequestCounterFilter implements Filter {
    private long served;
    public void doFilter(ServletRequest rq, ServletResponse rs, FilterChain c) {
        served++;
    }
}
```

Not flagged: writes made between `lock.lock()` and `lock.unlock()` on a `ReentrantLock` field.

## Remediation

1. Keep per-request data in locals or the request/session, not in fields.
2. Use concurrent types (`ConcurrentHashMap`, `AtomicLong`, `LongAdder`) for shared counters and caches.
3. Guard compound updates with `synchronized` or a `Lock`.
