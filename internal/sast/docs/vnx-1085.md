## Overview

VNX-1085 maps to [CWE-1085: Invokable Control Element with Excessive Volume of Commented-out Code](https://cwe.mitre.org/data/definitions/1085.html). A Python function whose body holds 5 or more lines of commented-out code.

**Severity:** Low | **CWE:** [CWE-1085](https://cwe.mitre.org/data/definitions/1085.html) | **Languages:** Python

## Why This Matters

Disabled code inside a function hides what the function used to do. A commented-out permission or CSRF check reads like a decision nobody recorded, and the dead lines go stale against the live code around them.

## What Gets Flagged

One finding per function, at its `def` line:

```python
class TransferView:
    def post(self, request):                                   # FLAGGED: 5 commented-out lines
        amount = int(request.POST["amount"])
        # self.check_csrf(request)
        # self.require_role(request.user, "teller")
        # if amount > LIMIT:
        #     raise PermissionDenied()
        # audit.record(request.user, amount)
        return self.transfer(request.user, amount)
```

A comment counts as code when it reads as a statement: an assignment, a call, an import, `return`/`raise`/`del`/`assert`, or a block header ending in a colon (`if ...:`, `for ... in ...:`, `else:`, `try:`).

## What Does Not Get Flagged

- Prose comments, even ones that mention code (`# Example: price(item, 3)`, `# Note: return early if qty is zero`).
- Fewer than 5 commented-out lines in a function.
- Commented-out code at module level.
- Test files.

The threshold is this rule's choice; CWE-1085 does not fix one.

## Remediation

1. Delete the commented-out lines; version control keeps the history.
2. If the code is still needed, restore it, or put it behind a feature flag with a comment saying why it is off.
3. For a deliberate exception, add `# vulnetix-ignore: VNX-1085` on the `def` line.
