## Overview

VNX-644 maps to [CWE-644: Improper Neutralization of HTTP Headers for Scripting Syntax](https://cwe.mitre.org/data/definitions/644.html). It reports a response header whose value is copied from the request (query string, form, path parameter, body, cookie or another request header), on the same line or through a variable assigned up to 10 lines above, with no encoding in between.

**Severity:** Medium | **CWE:** [CWE-644](https://cwe.mitre.org/data/definitions/644.html) | **Languages:** node, python

## Why This Matters

Headers are read raw by browsers, proxies, caches, log viewers and plug-ins. A reflected value can carry script syntax that one of those components renders, or CR/LF characters that split the response (CWE-113) where the framework does not reject them.

## What Gets Flagged

```python
resp.headers["Content-Disposition"] = "attachment; filename=" + request.args["file"]
response["Content-Disposition"] = f'attachment; filename="{name}.csv"'   # name = request.GET.get(...)
```

```javascript
res.setHeader('Content-Disposition', 'attachment; filename=' + req.params.name);
res.set('X-Client-Tag', req.query.tag);
res.writeHead(200, { 'Content-Type': 'text/html', 'X-Name': q.name });   // q from url.parse(req.url, true)
ctx.set('X-Request-Name', ctx.query.name);
```

Not flagged: constant values, `contentDisposition(req.params.name)`, `encodeURIComponent(...)`, `parseInt(...)`, `quote(name)`, a value cleaned with `.replace(/[\r\n]/g, '')`, and writes to the request's own headers.

## Remediation

1. Validate header values against an allow-list (for example a fixed set of languages).
2. Encode what must be reflected: `content-disposition` or RFC 5987 `filename*=` encoding, `encodeURIComponent`, `urllib.parse.quote`.
3. Strip CR and LF from any value that reaches a header.
