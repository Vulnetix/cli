## Overview

VNX-325 maps to [CWE-325: Missing Cryptographic Step](https://cwe.mitre.org/data/definitions/325.html). It reports AES set up in a mode that provides confidentiality only (CBC, CTR, CFB, OFB, PCBC) when the same file never computes a MAC, an AEAD tag or a signature.

**Severity:** Medium | **CWE:** [CWE-325](https://cwe.mitre.org/data/definitions/325.html) | **Languages:** java, kotlin, node, php, python, ruby

## Why This Matters

Encryption without authentication lets an attacker flip bits in the ciphertext and have the change decrypt silently. CBC decryption without a MAC is also a padding oracle: an error that distinguishes bad padding is enough to decrypt the whole message.

## What Gets Flagged

```java
// FLAGGED: no Mac anywhere in the file
Cipher c = Cipher.getInstance("AES/CBC/PKCS5Padding");
```

```python
# FLAGGED
cipher = AES.new(key, AES.MODE_CBC, iv)
enc = Cipher(algorithms.AES(key), modes.CTR(iv)).encryptor()
```

```javascript
// FLAGGED
const cipher = crypto.createCipheriv('aes-256-cbc', key, iv);
```

```php
$ct = openssl_encrypt($plain, 'aes-256-cbc', $key, OPENSSL_RAW_DATA, $iv);   // no hash_hmac in the file
```

```ruby
cipher = OpenSSL::Cipher.new("aes-256-cbc")
```

## What Is Not Flagged

- AEAD modes: GCM, CCM, EAX, SIV, OCB, ChaCha20-Poly1305.
- A file that also computes an HMAC, CMAC, Poly1305 tag or signature (`Mac.getInstance`, `hmac.new`, `createHmac`, `Signature`).
- ECB and bare `"AES"`, which [VNX-CRYPTO-003](vnx-crypto-003) reports.
- Comments, Python string literals and test files.

A MAC computed in a different file is not seen, so check a finding against its caller.

## Remediation

1. Prefer an AEAD: AES-GCM or ChaCha20-Poly1305.
2. Otherwise encrypt-then-MAC: HMAC-SHA256 over the IV and ciphertext with a separate key, verified in constant time before decrypting.
