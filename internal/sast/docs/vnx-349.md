## Overview

VNX-349 maps to [CWE-349: Acceptance of Extraneous Untrusted Data With Trusted Data](https://cwe.mitre.org/data/definitions/349.html). It reports a trusted object merged wholesale with request data, so every extra field the client sends is accepted alongside the data the server vouched for:

- JavaScript/TypeScript: `Object.assign()`, lodash `_.merge`/`extend`/`assign`/`defaults` (also `merge` imported by name from lodash) and `{...a, ...b}` combining such an object with `req.body`/`query`/`params`/`cookies`; and `...req.body` spread into the options of `res.render()`;
- Python: `.update()`, `{**a, **b}` and `dict(a, **b)` with `request.json`/`get_json()`/`form`/`args`/`values`/`data`/`POST`/`GET`;
- Java: `putAll(request.getParameterMap())` and Jackson `readerForUpdating(x).readValue(request.getInputStream())`.

The trusted side is recognised by name: `session`, `claims`/`*Claims`, `decoded*`, `verified*`, `principal`, `current_user`, `auth_user`/`auth_context`, `req.user`/`request.user`. The request side may be inline or a variable assigned from the request in the 15 lines above.

**Severity:** Medium | **CWE:** [CWE-349](https://cwe.mitre.org/data/definitions/349.html) | **Languages:** java, node, python

## Why This Matters

Code downstream reads the merged object as if all of it were verified. A client that adds `"role": "admin"` or `"sub": "victim"` to its body overwrites, or adds to, the claims the token proved. Spread into render options, the body can set the view engine's own `layout` or `settings`, which in Express/hbs is a known local-file read.

Not reported: individually picked fields (`{ theme: req.body.theme }`), merges into a fresh object or into an object not named as trusted (mass assignment onto a model is [VNX-915](../vnx-915/)'s concern), merges of server-side data, comments and string literals. Python `session.update(request.form)` is also reported by [VNX-501](../vnx-501/).

## What Gets Flagged

```typescript
const claims: any = jwt.verify(token, key);
const ctx = { ...claims, ...req.body };
```

```python
claims = jwt.decode(token, key, algorithms=["HS256"])
claims.update(request.get_json())
```

```java
claims.putAll(request.getParameterMap());
```

## Remediation

1. Copy only the fields you expect from the request, validated, into a separate object.
2. Keep verified claims and the session read-only to request handlers; never let the request write into them wholesale.
3. Pass template engines an explicit view model, never the request body.
