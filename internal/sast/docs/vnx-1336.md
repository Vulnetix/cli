title: "VNX-1336 – Server-side template injection: template source built from request data"
description: "Reports Python and Node.js code that compiles a template whose source comes from request data (render_template_string, Jinja2 from_string/Template, Django and Mako Template, Handlebars.compile, ejs/pug render and compile, nunjucks renderString, lodash _.template), directly or through one or two assignments. Literal or file templates with request data passed as context are not reported."
---

## Overview

VNX-1336 maps to [CWE-1336: Improper Neutralization of Special Elements Used in a Template Engine](https://cwe.mitre.org/data/definitions/1336.html). When request data becomes part of the template **source**, and not just the values the template renders, an attacker can write template expressions (`{{ config }}`, `{{ ''.__class__.__mro__ }}`, `#{7*7}`) that the engine evaluates on the server.

**Severity:** Medium | **CWE:** [CWE-1336](https://cwe.mitre.org/data/definitions/1336.html) | **Languages:** node, python

## Why This Matters

Server-side template injection in Jinja2, Mako, Pug, EJS, Handlebars and lodash templates regularly escalates to remote code execution, because those engines give templates access to the host language's objects.

## What Gets Flagged

```python
name = request.args.get("name", "guest")
template = f"<h1>Hello {name}</h1>"
return render_template_string(template)              # FLAGGED

tpl = env.from_string(request.get_json()["body"])    # FLAGGED
t = Template(request.GET["q"])                       # FLAGGED (django.template)
```

```javascript
const src = req.body.template
const fn = Handlebars.compile(src)                   // FLAGGED
res.send(pug.render(`p Hello ${req.query.name}`))    // FLAGGED
res.send(nunjucks.renderString('Hello ' + req.query.name, {}))  // FLAGGED
```

## What Is Not Flagged

- A literal template with request data passed only as render context: `render_template_string("<h1>{{ name }}</h1>", name=request.args["name"])`, `ejs.render('<%= name %>', { name: req.query.name })`.
- Templates loaded from files: `render_template`, `res.render`, `env.get_template`, a template read from disk.
- Python's `string.Template`, which substitutes values and evaluates no expressions.
- Comments and docstrings.
- Templates built from stored data (a value read from the database) are not followed.

## Remediation

1. Keep template source constant or load it from files under your control.
2. Pass user input only as context variables, which the engine escapes.
3. If users must author templates, use a sandboxed engine (`jinja2.sandbox.SandboxedEnvironment`) or a logic-less format, and never expose host objects to it.
