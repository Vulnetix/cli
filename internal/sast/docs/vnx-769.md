---
title: "VNX-769 – Uncontrolled File Descriptor Consumption"
description: "Reports Python loops and comprehensions that open a new file or socket handle per element and keep it open, which exhausts the process's descriptor limit on large input."
---

## Overview

VNX-769 maps to [CWE-769: Uncontrolled File Descriptor Consumption](https://cwe.mitre.org/data/definitions/769.html) (deprecated by MITRE in favour of [CWE-774](https://cwe.mitre.org/data/definitions/774.html); the number is kept for rule identity). It reports Python code that opens one handle per element of its input and keeps it:

- a handle assigned inside a `for`/`while` body (`fh = open(p)`, `io.open`, `codecs.open`, `gzip.open`, `bz2.open`, `lzma.open`, `tarfile.open`, `os.open`, `socket.socket(...)`, `socket.create_connection(...)`) that the loop body never closes (`fh.close()`, `os.close(fd)`, `with fh`, `contextlib.closing(fh)`), returns or yields;
- handles appended to a collection in a loop (`handles.append(open(p))`) with no close in the following lines;
- a list, set or dict comprehension that opens a handle per element (`[open(p) for p in paths]`).

Not reported: `with` blocks, handles closed or yielded in the loop, handles chained straight into a read (`open(p).read()`), generator expressions, handles opened outside a loop (VNX-775 reports a missing close there), comments, string literals and test files.

**Severity:** Low | **CWE:** [CWE-769](https://cwe.mitre.org/data/definitions/769.html) | **Languages:** python

## Why This Matters

Every open handle consumes a file descriptor. When the number of iterations is controlled by input (uploaded archives, a list of hosts, a directory listing), enough elements exhaust the per-process limit and every later `open`, `accept` or `connect` fails with `EMFILE`.

## What Gets Flagged

```python
for path in paths:
    fh = open(path, encoding="utf-8")        # flagged
    records.append(json.load(fh))

files = [open(s) for s in shards]            # flagged
```

Not flagged:

```python
for path in paths:
    with open(path, encoding="utf-8") as fh:
        records.append(json.load(fh))
```

## Remediation

1. Open handles in a `with` block inside the loop so each one closes before the next opens.
2. When handles must be held together (a k-way merge), bound how many are open at once and close them through `contextlib.ExitStack`.
