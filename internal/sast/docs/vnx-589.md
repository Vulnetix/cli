## Overview

VNX-589 maps to [CWE-589: Call to Non-ubiquitous API](https://cwe.mitre.org/data/definitions/589.html). It reports calls to:

- C11 Annex K functions only Microsoft's runtime ships: `strcpy_s`, `strcat_s`, `sprintf_s`, `memcpy_s`, `fopen_s`, `gets_s`, `scanf_s` and related names.
- Microsoft-only names: `_stricmp`, `_strnicmp`, `_strdup`, `_snprintf`, `_vsnprintf`, `_itoa`, `itoa`.
- BSD extensions: `strlcpy`, `strlcat`, `arc4random*`, `strtonum`, `getprogname`.
- GNU extensions: `memrchr`, `strchrnul`, `mempcpy`, and `qsort_r`, whose argument order differs between glibc and BSD.

**Severity:** Low | **CWE:** [CWE-589](https://cwe.mitre.org/data/definitions/589.html) | **Languages:** c, cpp

## Why This Matters

Code that calls one of these builds on the author's platform and fails to compile or link elsewhere. Worse, `qsort_r` compiles on both glibc and BSD with the comparator and context arguments swapped, so it misbehaves at run time.

## What Gets Flagged

```c
errno_t e = fopen_s(&fp, path, "r");
strlcpy(buf, name, n);
qsort_r(buf, n, 1, cmp, NULL);
```

```cpp
return _stricmp(a, b) == 0 &&
```

Not flagged: a file with an `#if`/`#ifdef` on a platform or `HAVE_*` macro, or that defines `_GNU_SOURCE` or `__STDC_WANT_LIB_EXT1__`; a file whose path names a platform (`impl/apple/`, `win32_io.c`); a function the project defines, declares at file scope or `#define`s itself (a compat implementation); `my_strlcpy()`, `ops->strlcpy()`; comments and strings.

## Remediation

1. Use the portable equivalent (`snprintf`, `memcpy`, `strcasecmp`), or
2. guard the call with a feature test (`HAVE_STRLCPY`, `_WIN32`) and provide a fallback implementation.
