## Overview

VNX-335 maps to [CWE-335: Incorrect Usage of Seeds in Pseudo-Random Number Generator (PRNG)](https://cwe.mitre.org/data/definitions/335.html). It reports a generator that produces secrets and is seeded with a value an attacker can reproduce: a literal, a string's bytes, a constant, or the current time.

**Severity:** High | **CWE:** [CWE-335](https://cwe.mitre.org/data/definitions/335.html) | **Languages:** java, kotlin, python

## Why This Matters

A seeded generator replays the same sequence for the same seed. A SHA1PRNG `SecureRandom` seeded before its first use is fully deterministic, and a clock seed has only a few thousand plausible values around the time a token was issued.

## What Gets Flagged

```java
// FLAGGED: any explicit seed
SecureRandom r = new SecureRandom("fixed".getBytes());
// FLAGGED: clock seed on a SecureRandom
sr.setSeed(System.currentTimeMillis());
// FLAGGED: clock-seeded Random whose output becomes a token
private final Random random = new Random(System.currentTimeMillis());
```

```python
# FLAGGED: the file then draws a token from random
random.seed(time.time())
rng = random.Random(1337)
```

## What Is Not Flagged

- Unseeded generators, and `setSeed(generateSeed(...))`, which only adds entropy.
- Fixed seeds for simulations, shuffles and ML reproducibility (`random.seed(42)`, numpy, torch) when no secret is drawn from the generator.
- Files whose secrets come from the `secrets` module.
- Comments and test files.

## Remediation

Use `new SecureRandom()` or `SecureRandom.getInstanceStrong()` and never seed it; in Python use the `secrets` module, which cannot be seeded.
