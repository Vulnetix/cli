---
title: "VNX-168 – Improper Handling of Inconsistent Special Elements"
description: "Reports CSV parsed by splitting each line on every comma, which ignores CSV quoting so a quoted comma shifts every later column, in files that use no CSV parser."
---

## Overview

VNX-168 maps to [CWE-168: Improper Handling of Inconsistent Special Elements](https://cwe.mitre.org/data/definitions/168.html). In CSV a comma is a separator outside quotes and data inside them. Splitting on every comma treats both the same. The rule reports:

- Python, JavaScript/TypeScript and Java `.split(",")`, including the regex spellings `/,/` and `"\\s*,\\s*"`, `re.split` and a chained `.split(",")` on a continuation line
- Go `strings.Split(x, ",")` and `strings.SplitN(x, ",", n)`
- PHP `explode(",", ...)` and `preg_split('/,/', ...)`

within 25 code lines of a CSV reference (a `.csv` name, `text/csv`, a csv file/row/line/upload name, a `'csv'` upload field or a name ending in `_csv`), in a file that uses no CSV parser (Python `csv`/pandas, papaparse, csv-parse, csv-parser, fast-csv, d3-dsv, OpenCSV, Commons CSV, Jackson CSV, univocity, Go `encoding/csv`, PHP `fgetcsv`/`str_getcsv`/League\Csv).

Not reported: comma-separated values that are not CSV documents (headers, environment variables, query parameters, tag lists), a comma list read from configuration (`process.env`, `os.environ`/`getenv`, `System.getenv`, a `config.`/`settings.` object) or from a request parameter (`req.query`, `request.args`, `$_GET`, `FormValue`, `getParameter`) even beside CSV code, a split of a string literal, files that parse CSV with a library, comments, string literals and test files.

**Severity:** Low | **CWE:** [CWE-168](https://cwe.mitre.org/data/definitions/168.html) | **Languages:** python, node, java, go, php

## Why This Matters

An uploaded or exported CSV with a field like `"Smith, John"` splits into one column too many. Every later column moves: an email lands in the role column, an amount in the account column. Someone who controls one field can choose which column their next value lands in.

## What Gets Flagged

```python
# FLAGGED
with open("uploads/users.csv") as f:
    for line in f:
        name, email, role = line.strip().split(",")
```

```go
// FLAGGED
f, _ := os.Open("data/records.csv")
...
out = append(out, strings.Split(sc.Text(), ","))
```

```java
// FLAGGED
String[] cols = line.split("\\s*,\\s*");   // reading invoices.csv
```

```python
# NOT FLAGGED: a CSV parser
for name, email, role in csv.reader(f):
    ...
```

## Remediation

Parse CSV with a CSV parser: Python `csv.reader`, Go `encoding/csv`, PHP `fgetcsv`/`str_getcsv`, Java Commons CSV or OpenCSV, JavaScript papaparse or csv-parse.
