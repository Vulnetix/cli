## Overview

VNX-654 maps to [CWE-654: Reliance on a Single Factor in a Security Decision](https://cwe.mitre.org/data/definitions/654.html). It reports a condition that tests the client's network origin and a branch that grants access on that alone.

- **Origin read:** Python `request.remote_addr`, `request.access_route`, `request.client.host`, `REMOTE_ADDR`, `HTTP_X_FORWARDED_FOR`, `HTTP_X_REAL_IP`, `HTTP_REFERER`, `request.referrer` and the X-Forwarded-For/X-Real-IP/X-Client-IP/Referer headers; JavaScript `req.ip`, `req.ips`, Koa `ctx.ip`/`ctx.request.ip`, `.remoteAddress` and the same headers. It can be read directly or through a variable assigned a few lines above.
- **Comparison:** `==`, `===`, `in`, `includes`, `startswith`/`startsWith`, `indexOf`, a regex `test`.
- **Grant in the branch:** `return next()`/`next()`/`await next()`, `login()`/`login_user()`, a session admin/user/authenticated flag, `is_admin = True`, `return True`, a decorator returning the wrapped view.

Not reported: a condition that also checks the authenticated user, session, token or password, negated checks and blocklists, logging, rate limiting, region lookups, a grant behind a nested check, test files, comments and string literals.

**Severity:** Low | **CWE:** [CWE-654](https://cwe.mitre.org/data/definitions/654.html) | **Languages:** python, node

## Why This Matters

X-Forwarded-For and Referer are written by the client. A real address is shared behind NAT and proxies, and "localhost" is exactly where an SSRF request comes from. None of them proves who the caller is.

## What Gets Flagged

```python
if request.remote_addr == "127.0.0.1":          # FLAGGED
    return f(*args, **kwargs)
```

```javascript
if (OFFICE.includes(req.ip)) {                  // FLAGGED
  return next()
}
```

```python
# NOT FLAGGED: address plus an authenticated user
if request.remote_addr in ALLOWED and current_user.is_authenticated:
    return f(*args, **kwargs)
```

## Remediation

1. Authenticate the caller (session, token, mTLS) and use the network check only as an additional restriction.
2. Never trust X-Forwarded-For unless a known proxy sets it; configure the framework's trusted-proxy list instead.
