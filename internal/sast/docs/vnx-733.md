title: "VNX-733 – Compiler Optimization Removal or Modification of Security-critical Code"
description: "Reports C and C++ code the optimiser may delete: a memset/bzero of a secret buffer that nothing reads before it is freed or goes out of scope, and pointer-wraparound checks (p + n < p) on pointers, which are undefined behaviour."
---

## Overview

VNX-733 maps to [CWE-733](https://cwe.mitre.org/data/definitions/733.html). It reports two shapes:

- **Dead-store wipe.** `memset`/`bzero`/`ZeroMemory`/`RtlZeroMemory` with a zero fill, of a buffer whose name marks it as a secret: password, passphrase, secret, key, seed, pin, token, credential or plaintext, with prefixes such as `session_key` and camelCase forms such as `masterKey`. The next statement frees the buffer, or, for a local array, returns or closes the scope. Nothing reads the cleared memory afterwards, so the compiler may remove the clear.
- **Pointer-wraparound check.** `if (p + n < p)` or `p + n <= p` on a name declared as a pointer. Pointer overflow is undefined behaviour, so the compiler may fold the test to false.

**Severity:** Low | **CWE:** [CWE-733](https://cwe.mitre.org/data/definitions/733.html) | **Languages:** c, cpp

## What Gets Flagged

```c
memset(password, 0, 128);     // FLAGGED: dead store
free(password);

if (buf + off < buf)          // FLAGGED: UB, may be removed
    return -1;
```

Not reported:

- wipes the compiler must keep: `explicit_bzero`, `memset_s`, `SecureZeroMemory`, `OPENSSL_cleanse` and `sodium_memzero`
- a clear followed by a use of the buffer
- clears of struct members or pointer parameters before a return
- non-zero fills
- integer overflow checks such as `a + b < a` on `size_t`
- test code and comments

VNX-CWE1037-AUTO reports the dead-store wipe as well.

## Remediation

1. Wipe secrets with `explicit_bzero`, `memset_s`, `SecureZeroMemory` or `OPENSSL_cleanse`.
2. Write bounds checks on lengths, for example `n > (size_t)(end - p)`, and do not test pointer arithmetic for overflow.
