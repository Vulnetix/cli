title: "VNX-223 – Omission of Security-relevant Information"
description: "Detects Python code that discards the record of a security event: a failed token, signature or permission check swallowed by an except clause that only passes or by contextlib.suppress(), logging.disable(), a disabled security/audit logger, and Django's django.security loggers routed to the null handler."
---

## Overview

VNX-223 maps to [CWE-223: Omission of Security-relevant Information](https://cwe.mitre.org/data/definitions/223.html). Detection and incident response depend on the system recording security events: forged tokens, bad signatures, refused permissions, suspicious requests. CWE-223 is a property of what a system records, which no single line shows; the rule reports the concrete places where Python code throws that record away.

- An `except` clause whose whole body is `pass`, `...` or `continue`, when the exception is a security one (`InvalidTokenError`, `ExpiredSignatureError`, `DecodeError`, `BadSignature`, `SignatureExpired`, `InvalidSignature`, `PermissionDenied`, `SuspiciousOperation`, `AuthenticationFailed`, `CSRFError`, `VerifyMismatchError`, ...) or the `try` block performs a verification (`jwt.decode`, `.verify()`, `verify_*()`, `check_password`, `authenticate`, `hmac.compare_digest`, `.unsign`, `bcrypt.checkpw`, `validate_csrf`, `has_perm`, `check_permissions`). Such a handler also tends to fail open.
- `logging.disable()` with no argument or a level above `DEBUG`.
- A security, auth, audit, access or login logger set `disabled = True`, also through a variable (`audit_log = logging.getLogger("app.audit")` then `audit_log.disabled = True`).
- Django `LOGGING` sending a `django.security` logger to the `null` handler (or to no handler) with `propagate: False`.

**Severity:** Low | **CWE:** [CWE-223](https://cwe.mitre.org/data/definitions/223.html) | **Languages:** Python

## What Gets Flagged

```python
try:
    claims = jwt.decode(token, SECRET, algorithms=["HS256"])
except Exception:          # FLAGGED
    pass
```

```python
logging.disable(logging.CRITICAL)   # FLAGGED
```

```python
"django.security.DisallowedHost": {   # FLAGGED
    "handlers": ["null"],
    "propagate": False,
},
```

## What Is Not Flagged

- Handlers that log, raise or return a failure.
- A `continue` that tries the next key in a loop which raises once every key has failed (key rotation).
- Swallowed exceptions unrelated to security (`FileNotFoundError` around `os.remove`, a bare `except` around `conn.close()`).
- `logging.disable(logging.NOTSET)`, and `django.security` sent to real handlers.
- Comments and test code (including `conftest.py`).

## Remediation

```python
try:
    claims = jwt.decode(token, SECRET, algorithms=["HS256"])
except jwt.InvalidTokenError:
    security_log.warning("rejected token", extra={"ip": request.remote_addr})
    raise PermissionDenied
```
