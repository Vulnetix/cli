title: "VNX-1111 – Incomplete I/O Documentation"
description: "A Python function whose structured docstring documents some of its parameters but omits others."
---

## Overview

VNX-1111 maps to [CWE-1111: Incomplete I/O Documentation](https://cwe.mitre.org/data/definitions/1111.html). It reports a Python function whose docstring has a parameter section (Google-style `Args:`/`Parameters:` or Sphinx `:param name:`) that leaves out one or more of the function's own parameters.

**Severity:** Low | **CWE:** [CWE-1111](https://cwe.mitre.org/data/definitions/1111.html) | **Languages:** Python

## Why This Matters

A documented interface that lists some inputs reads as complete. Callers do not learn that an undocumented parameter exists or what it changes (a `mode`, a timeout, an access-control flag), and reviewers checking how input is handled miss it.

## What Gets Flagged

Reported at the `def` line, naming the missing parameters:

```python
def fetch_report(session, report_id, timeout):    # FLAGGED: 'timeout' undocumented
    """Download a report.

    Args:
        session: HTTP session to use.
        report_id: Identifier of the report.
    """
```

```python
def write_blob(path, data, mode="wb"):             # FLAGGED: 'mode' undocumented
    """Write bytes to disk.

    :param path: destination file
    :param data: bytes to write
    """
```

Multi-line signatures, methods, `async def` and defaults containing commas are handled.

## What Does Not Get Flagged

- Functions with no structured parameter section (an undocumented function is a different question).
- `self`, `cls`, `*args`, `**kwargs` and parameters whose name starts with `_`.
- NumPy-style sections with dashed underlines (not parsed).
- Test files.

## Remediation

1. Add an entry for every parameter to the docstring's parameter section.
2. If a parameter is internal, rename it with a leading underscore or make it keyword-only and document it.
