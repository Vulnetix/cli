---
title: "VNX-499 – Serializable Class Containing Sensitive Data"
description: "Detects non-transient secret fields (password, token, API key, private key, card number) in Java classes that implement Serializable and do not control their serial form."
---

## Overview

VNX-499 maps to [CWE-499: Serializable Class Containing Sensitive Data](https://cwe.mitre.org/data/definitions/499.html). Default Java serialisation writes every non-transient field into the byte stream. When the object ends up in an HTTP session store, a cache, a file or an RMI call, the secret travels with it in recoverable form.

The rule reports a field of a class that implements `Serializable` (the clause may span lines) when the field is neither `transient` nor `static` and holds a secret: a `String`, `char[]`, `byte[]` or `CharSequence` whose name says password, passphrase, pwd, pin, secret, API key, private key, an access/refresh/auth/session/bearer/id/csrf token, credential, credit card or card number, CVV or SSN, or a field of type `PrivateKey`, `SecretKey`, `SecretKeySpec`, `KeyPair`, `KeyStore` or `Key`.

**Severity:** Low | **CWE:** [CWE-499](https://cwe.mitre.org/data/definitions/499.html) | **Languages:** Java

## What Gets Flagged

```java
public class UserAccount implements Serializable {
    private String username;
    private String password;      // FLAGGED
    private char[] pin;           // FLAGGED
```

```java
public class OAuthSession extends BaseSession implements Comparable<OAuthSession>, Serializable {
    private String accessToken;   // FLAGGED
    private PrivateKey signingKey; // FLAGGED
```

## What Is Not Flagged

- `transient` and `static` fields (`private static final String PASSWORD_PARAM = "password"`).
- Names that describe a secret rather than hold it (`passwordPolicy`, `tokenEndpoint`) and non-text types (`int passwordLength`).
- Classes that control their serial form: `writeObject`, `writeReplace`, `serialPersistentFields` or `Externalizable`.
- Classes that are not `Serializable`, test code, comments and string literals.

Classes that become serialisable only through a superclass are not resolved.

## Remediation

1. Mark the field `transient` and re-obtain the secret after deserialisation.
2. Or define `writeObject`/`writeReplace` so the secret is excluded, or throw `NotSerializableException`.
