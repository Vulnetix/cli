## Overview

VNX-791 maps to [CWE-791: Incomplete Filtering of Special Elements](https://cwe.mitre.org/data/definitions/791.html). It reports hand-written sanitisers that delete a dangerous token in one pass:

- Python `str.replace(TOKEN, '')`, `re.sub(TOKEN, '', s)` and `PATTERN.sub('', s)` where `PATTERN = re.compile(TOKEN)` in the same file
- JavaScript/TypeScript `replaceAll(TOKEN, '')`, `split(TOKEN).join('')`, `replace(/TOKEN/g, '')` and `replace(PATTERN, '')` where `const PATTERN = /TOKEN/g` in the same file

where TOKEN is a `<script`/`<iframe`/`<object`/`<embed`/`<svg` tag, a generic tag pattern built from word characters (`<\w+...`, `<(?:\w+)...`, which cannot match a nested `<`), a `javascript:` or `vbscript:` scheme, an event-handler attribute (`onerror`, `on\w+`...), a `..` or `../` traversal sequence, or shell metacharacters. A character class of two or more shell metacharacters (`[;&|]`) is always reported; a single one (`;`, `&`, `|`, a backtick, `$`) only when a command (`cmd`, `exec`, `subprocess`, `child_process`, `system(`...) appears within six lines, because `'$'`, `'|'` and `'&'` are deleted from prices, table cells and slugs far more often.

A replacement repeated in a `while`/`do` loop, escaping (replacing with an entity), an ellipsis (`'...'`), `<[^>]*>` (which absorbs a nested `<`), anchored patterns (reported by VNX-796) and JavaScript first-occurrence `replace('x', ...)` (reported by VNX-792 and VNX-793) are not reported.

**Severity:** Medium | **CWE:** [CWE-791](https://cwe.mitre.org/data/definitions/791.html) | **Languages:** node, python

## Why This Matters

Deleting a token once reassembles it from nested input: `<scr<script>ipt>` becomes `<script>`, and `....//` becomes `../`. A denylist of shell characters leaves the ones it forgot (`|`, `$(...)`, a newline).

## What Gets Flagged

```python
username = username.replace("<script>", "").replace("</script>", "")   # FLAGGED
name = name.replace('../', '')                                         # FLAGGED
return cmd.replace(';', '').replace('&', '')                           # FLAGGED
```

```javascript
return input.replace(/<script>/gi, '');   // FLAGGED
const stripped = name.replaceAll('../', '');   // FLAGGED
```

## Remediation

1. Encode for the output context (template auto-escaping, `html.escape`) instead of deleting tags.
2. For paths, resolve the full path and check it stays under the base directory.
3. For commands, pass an argument list without a shell instead of filtering metacharacters.
