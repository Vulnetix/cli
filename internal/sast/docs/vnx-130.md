## Overview

VNX-130 maps to [CWE-130: Improper Handling of Length Parameter Inconsistency](https://cwe.mitre.org/data/definitions/130.html). It reports a value decoded from wire byte order (`ntohs`, `ntohl`, `be16toh`/`be32toh`/`le16toh`/`le32toh`, `get_unaligned_be16/be32/le16/le32`, OpenSSL's `n2s`/`n2l`, or bytes combined as `(p[0] << 8) | p[1]`) that is used as the length argument of `memcpy`, `memmove`, `strncpy` or `strncat`, or as the size of `read`/`recv`/`recvfrom`/`fread`, with no comparison against the destination or the received size in between. The conversion written directly in the length argument is reported too.

**Severity:** High | **CWE:** [CWE-130](https://cwe.mitre.org/data/definitions/130.html) | **Languages:** c, cpp

## What Gets Flagged

```c
uint16_t len = ntohs(h->len);
memcpy(payload, pkt + sizeof(*h), len);          // FLAGGED

n2s(p, payload);
pl = p;
memcpy(bp, pl, payload);                         // FLAGGED: Heartbleed

std::memcpy(body, frame + 4, ntohs(fh->length)); // FLAGGED
```

## What Is Not Flagged

- A length compared in an `if`/`while`/`assert` or a ternary, or clamped with `MIN()`/`min()`, before the copy.
- Constant and `sizeof` lengths, and decoded values that are never used as a copy length.
- Host-to-network conversions (`htons`, `htonl`).
- Lengths that reach the copy through another function (out of scope).

## Remediation

Before copying, check the decoded length against both the destination size and the number of bytes actually received, and discard the message if either check fails.
