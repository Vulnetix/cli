description: "Per-request or per-user data stored in a field of a Java component that one instance serves every request: a class that extends HttpServlet/GenericServlet, is annotated @WebServlet, @Controller or @RestController, or extends a Struts Action. A request handler assigns a non-final field (instance or static) from the request (getParameter, getHeader, getAttribute, getSession, getRemoteUser, getUserPrincipal, getCookies, getInputStream/getReader, getQueryString), directly or through a local variable assigned from the request a few lines above. Concurrent requests share the field, so one user's data is served to another. Not reported: locals, final fields, assignments in init() or a constructor, fields of classes that are not request singletons (including Spring beans annotated @RequestScope, @SessionScope or @Scope request/session/prototype), fields set from servlet configuration, and the pattern in comments or string literals."
---

## Overview

VNX-488 maps to [CWE-488: Exposure of Data Element to Wrong Session](https://cwe.mitre.org/data/definitions/488.html). It reports request data written into a field of a servlet or Spring controller, which one instance shares across all requests.

**Severity:** Low | **CWE:** [CWE-488](https://cwe.mitre.org/data/definitions/488.html) | **Languages:** java

## Why This Matters

The container creates one servlet instance, and Spring creates one controller instance, and every request thread runs through it at once. A field set from request A can be read while serving request B, so one user sees another user's name, account or cart.

## What Gets Flagged

```java
public class ProfileServlet extends HttpServlet {
    private String userName;

    protected void doGet(HttpServletRequest request, HttpServletResponse response) {
        userName = request.getParameter("user");     // FLAGGED
        response.getWriter().println(render(userName));
    }
}
```

```java
@RestController
public class CartController {
    private static String lastUser;

    @GetMapping("/cart")
    public Cart cart(HttpServletRequest req) {
        String user = req.getRemoteUser();
        lastUser = user;                              // FLAGGED
        ...
```

Not flagged: the same value kept in a local variable, a `final` field, or a field set in `init()` from servlet configuration.

## Remediation

1. Keep per-request data in local variables or pass it as method arguments.
2. Store per-user data in the request (`request.setAttribute`) or the session, never in a field of the servlet or controller.
3. If a component must hold per-request state, make it request-scoped (`@RequestScope`) rather than a singleton.
