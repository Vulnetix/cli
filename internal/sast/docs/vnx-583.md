---
title: "VNX-583 – finalize() method declared public"
description: "Reports Java overrides of Object.finalize() declared public and Kotlin member finalize() functions left at the default public visibility. Protected finalizers, overloads with parameters, calls and test files are not reported."
---

## Overview

VNX-583 maps to [CWE-583: finalize() Method Declared Public](https://cwe.mitre.org/data/definitions/583.html). It reports a Java `void finalize()` declaration with no parameters whose modifiers include `public`, in any order and after annotations, and a Kotlin member `fun finalize()` with no visibility modifier or with `public` (Kotlin members are public by default).

**Severity:** Medium | **CWE:** [CWE-583](https://cwe.mitre.org/data/definitions/583.html) | **Languages:** java, kotlin

## Why This Matters

`Object.finalize()` is protected. Widening it to public lets any caller run the finalizer, which typically frees native memory or closes handles, while the object is still in use. A later access then works on released resources.

## What Gets Flagged

```java
public void finalize() throws Throwable {
public synchronized void finalize() {
@Override public void finalize()
```

```kotlin
class NativeHandle(private val ptr: Long) {
    fun finalize() { Native.free(ptr) }
}
```

Not flagged: `protected void finalize()`, Kotlin `protected fun finalize()` and top-level `fun finalize()`, `public void finalize(int code)`, `public void finalizeOrder()`, calls such as `s.finalize()`, comments, strings and test files.

## Remediation

1. Declare the override `protected`, as `Object.finalize()` is.
2. Prefer `AutoCloseable` with try-with-resources, or `java.lang.ref.Cleaner`; finalization is deprecated for removal.
