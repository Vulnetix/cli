---

## Overview

VNX-760 maps to [CWE-760: Use of a One-Way Hash with a Predictable Salt](https://cwe.mitre.org/data/definitions/760.html). It reports a constant written in the salt position of `hashlib.pbkdf2_hmac`, `hashlib.scrypt`, `PBKDF2HMAC`, `new PBEKeySpec`, `pbkdf2.Key`, `scrypt.Key`, `argon2.IDKey`, `crypto.pbkdf2Sync` or `crypto.scryptSync`, a literal `$2...` salt given to bcrypt, a salt-named variable assigned a constant and then used in a hash or KDF call, and a username or email used as the PBKDF2 salt.

It does not report random salts (`os.urandom`, `secrets`, `SecureRandom`, `crypto/rand`, `randomBytes`, `gensalt()`), a stored hash passed back to `hashpw` to verify, or salt constants used for something other than password hashing (itsdangerous signing namespaces, column names, lengths). Constant IVs and nonces are VNX-CRYPTO-010.

**Severity:** High | **CWE:** [CWE-760](https://cwe.mitre.org/data/definitions/760.html) | **Languages:** go, java, node, python

## Why This Matters

A salt only helps if every password gets a different, unpredictable one. A constant salt is the same as no salt across the whole user table: one precomputed table covers every account, and identical passwords still produce identical hashes.

## What Gets Flagged

```python
SALT = b"s3cr3t-static-salt"                                            # flagged
return hashlib.pbkdf2_hmac('sha256', password.encode(), b'NaCl', 100000) # flagged
```

```java
private static final String SALT = "acme-2019";                         // flagged
PBEKeySpec spec = new PBEKeySpec(password, "salt".getBytes(), 65536, 128); // flagged
```

```go
return scrypt.Key([]byte(password), []byte("NaCl"), 32768, 8, 1, 32)    // flagged
```

## Remediation

1. Generate a fresh random salt of at least 16 bytes for every password (`os.urandom(16)`, `SecureRandom.nextBytes`, `crypto/rand.Read`, `crypto.randomBytes(16)`) and store it beside the hash.
2. Prefer bcrypt or Argon2 libraries that generate and embed the salt themselves.
