title: "VNX-698 – Execution After Redirect (EAR)"
description: "Reports a PHP header('Location: ...') or wp_redirect() not followed by exit/die/return/throw, and a Laravel, Flask, Django or Starlette redirect built as a bare statement and never returned, so the handler keeps executing after the redirect."
---

## Overview

VNX-698 maps to [CWE-698: Execution After Redirect (EAR)](https://cwe.mitre.org/data/definitions/698.html). A handler sends a redirect, usually to the login page when an access check fails, but does not stop. The code after the redirect still runs: the protected action is performed, or the protected page is rendered into the body of the redirect response, for any client that ignores the `Location` header (curl, a script, a proxy).

The rule reports:

- **PHP** `header('Location: ...')` (any case, any quotes) and WordPress `wp_redirect()`/`wp_safe_redirect()` whose next statement is ordinary code rather than `exit`, `die`, `return` or `throw`, including a redirect that closes an `if` block when code follows the block;
- **Laravel** `redirect(...)`, `redirect()->...` and `Redirect::...` called as a bare statement in a file that uses `Illuminate`: the response is built and thrown away;
- **Flask, Django, Starlette** `redirect(...)`, `HttpResponseRedirect(...)`, `HttpResponsePermanentRedirect(...)` and `RedirectResponse(...)` called as a bare statement (not returned, assigned or raised), which does nothing at all.

Not reported: a redirect followed by `exit`, `die`, `return`, `throw` or `break` (also on the same line, and with comments or further `header()`/`setcookie()` calls between), a redirect that ends a helper function (the caller decides), a redirect followed by an `else` branch or `?>`, returned or assigned redirects, bottle's `redirect()` (which raises), plain PHP files that define their own `redirect()` helper, test files, comments and string literals. Ruby on Rails `redirect_to` is not covered.

**Severity:** High | **CWE:** [CWE-698](https://cwe.mitre.org/data/definitions/698.html) | **Languages:** php, python

## What Gets Flagged

```php
if (empty($_SESSION['is_admin']))
    header("Location: /login.php");          // FLAGGED: the DELETE still runs
$db->query("DELETE FROM users WHERE id = $id");
```

```python
@app.route("/admin/purge", methods=["POST"])
def purge():
    if not session.get("is_admin"):
        redirect(url_for("login"))           # FLAGGED: not returned
    purge_all_records()
```

## What Is Not Flagged

```php
if (empty($_SESSION['user'])) {
    header("Location: /login.php");
    exit;
}
```

```python
if not session.get("is_admin"):
    return redirect(url_for("login"))
```

## Remediation

1. In PHP, call `exit;` immediately after `header('Location: ...')` or `wp_redirect()`.
2. In Laravel, Flask, Django and Starlette, `return` the redirect response.
3. Prefer framework access control (middleware, decorators, `@login_required`) to inline checks.
