## Overview

VNX-1112 maps to [CWE-1112: Incomplete Documentation of Program Execution](https://cwe.mitre.org/data/definitions/1112.html). It reports command-line options and arguments that change how a Python program runs but are missing from its `--help` output.

**Severity:** Low | **CWE:** [CWE-1112](https://cwe.mitre.org/data/definitions/1112.html) | **Languages:** Python

## Why This Matters

`--help` is the documentation operators read before running a tool. An option missing from it (a `--force`, a `--skip-verify`, a destination path) is an execution control nobody knows to review. It gets used without anyone understanding it, or left at a default nobody chose.

## What Gets Flagged

Reported at the line that opens the call, which may span several lines:

```python
parser.add_argument("--output", default="out.csv")         # FLAGGED
parser.add_argument(                                       # FLAGGED
    "--retries",
    type=int,
)
parser.add_option("-f", "--force", action="store_true")    # FLAGGED (optparse)

@click.option("--verbose", is_flag=True)                   # FLAGGED
```

Django management commands (`add_arguments`) and subparsers are covered.

## What Does Not Get Flagged

- Calls that pass `help=`, including `help=argparse.SUPPRESS` (a deliberate choice to hide an option).
- Calls that expand `**options`, since help may be inside them.
- `action="version"` and `action="help"`, for which argparse writes the help text itself.
- `add_option` calls whose first argument is not a `-` flag (a menu or config API, not optparse), and calls inside a triple-quoted usage example.
- `add_argument_group`, `add_mutually_exclusive_group` and `click.argument` (which takes no help).
- Commented-out calls and test files.

## Remediation

1. Add `help="..."` describing what the option changes and its default.
2. Hide internal options explicitly with `help=argparse.SUPPRESS` or `hidden=True` in click.
