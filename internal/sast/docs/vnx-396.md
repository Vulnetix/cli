---
title: "VNX-396 – Declaration of Catch for Generic Exception"
description: "A catch of Exception, RuntimeException or Throwable (Java) or Exception/bare catch (C#) whose body neither rethrows nor uses the caught exception, turning every failure into the same default."
---

## Overview

VNX-396 maps to [CWE-396: Declaration of Catch for Generic Exception](https://cwe.mitre.org/data/definitions/396.html). It reports Java `catch (Exception e)`, `catch (RuntimeException e)` and `catch (Throwable t)` (including `final` and `java.lang.` forms), and C# `catch (Exception)`, `catch (Exception ex)` and a bare `catch`, whose body neither rethrows nor references the caught exception: it is not logged, wrapped or recorded, and every failure, including unrelated programming errors, becomes the same `return null`, `return false` or flag.

Not reported: a generic catch that logs, wraps, records or rethrows (`throw;`, `throw e`), a catch of a specific type, a variable named `ignored`/`ignore`/`expected`/`unused`, an empty Java catch body (VNX-391 reports that), test files, comments and strings.

**Severity:** Low | **CWE:** [CWE-396](https://cwe.mitre.org/data/definitions/396.html) | **Languages:** java, csharp

## Why This Matters

A generic catch answers questions the code never asked. A lookup that fails because the database is down, because of a bug, or because the row is absent all return `null`, and the cause is lost at the one place it was known.

## What Gets Flagged

```java
} catch (Exception e) {          // FLAGGED: e is never used
    return null;
}
```

```csharp
catch (Exception)                // FLAGGED
{
    return null;
}
```

## Remediation

1. Catch the specific exceptions the call declares or is documented to throw.
2. If a broad boundary catch is needed, log the exception with its stack trace or wrap and rethrow it.
