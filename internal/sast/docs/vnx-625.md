---
title: "VNX-625 – Permissive Regular Expression"
description: "Reports host and URL allow-list regular expressions with an unescaped dot in the host name, no end anchor after the domain, or a domain-only pattern with no start anchor."
---

## Overview

VNX-625 maps to [CWE-625: Permissive Regular Expression](https://cwe.mitre.org/data/definitions/625.html). Redirect, CORS and SSRF checks often use a regular expression to allow one host. Two mistakes make such checks easy to get around: an unescaped `.` matches any character (`shop.example.com` also accepts `shopXexample.com`), and a pattern that stops at the domain also accepts `https://example.com.attacker.net`.

**Severity:** Medium | **CWE:** [CWE-625](https://cwe.mitre.org/data/definitions/625.html) | **Languages:** Python, JavaScript/TypeScript, Go, Java

## What Gets Flagged

```python
re.match(r"^https?://accounts.example.com/", url)                 # unescaped dots
re.match(r"https://([a-z0-9-]+\.)?example\.com", origin)          # no end anchor
```

```javascript
/^https:\/\/([a-z]+\.)?example\.com/.test(origin)
/^https:\/\/app\.example\.io(:\d+)?/.test(origin)                  // optional port does not anchor
/example\.com$/.test(origin)                                      // no start anchor: evilexample.com
```

```go
regexp.MustCompile(`^https://[a-z0-9-]+\.example\.com`)
```

A pattern counts as a host check when it starts with `^`, contains `://`, or is used with `re.match`. Not flagged: escaped dots with an end anchor (`$`, `\Z`, a following `/`), `re.fullmatch()` and Java's whole-string `matches()` (for the missing-anchor form), `re.sub()` and other extraction uses, patterns without a host name, test files, comments and plain string literals.

## Remediation

Escape every dot and anchor the end, or compare the parsed host exactly:

```python
re.match(r"^https://([a-z0-9-]+\.)?example\.com(:\d+)?(/|$)", origin)
urllib.parse.urlsplit(url).hostname in {"example.com", "www.example.com"}
```
