## Overview

VNX-1057 maps to [CWE-1057: Data Access Operations Outside of Expected Data Manager Component](https://cwe.mitre.org/data/definitions/1057.html). It reports raw database access in a Python request-handling module when the project has a data manager component that should own it.

- **Handler module:** named or placed as a view, route, handler, controller, endpoint, resolver or API module (`views.py`, `routes/`, `handlers.py`, `api/`), or one that declares routes (`@app.route`, `@bp.get`, `@router.post`, `@api_view`) or Django views (`def name(request, ...)`).
- **Data manager component:** another scanned file under a `models`, `repositories`, `dao`, `db`, `database`, `persistence`, `store`, `crud` or `queries` module.
- **Raw access:** a DB-API driver `connect()`, a `.cursor()` call, Django `Model.objects.raw()`, `cursor.execute/executemany/executescript`, and `execute()`, `fetch()`, `fetchrow()`, `fetchval()`, `fetch_all()` or `fetch_one()` (DB-API, asyncpg, databases) on a connection, db, session or engine handle whose argument is SQL text, `text(...)`, or a name assigned SQL text a few lines above.

**Severity:** Low | **CWE:** [CWE-1057](https://cwe.mitre.org/data/definitions/1057.html) | **Languages:** python

## Why This Matters

When handlers write their own SQL, the protections the data layer applies (parameterisation, tenant scoping, authorisation filters, auditing) are applied only where someone remembered them. Raw SQL scattered through views is also where injection bugs collect.

Not reported: ORM queries (`Model.objects.filter`, `session.query`, `select()`), calls into the data manager's functions, raw SQL inside the data manager modules, projects with no data manager component, test files, comments and SQL written in string literals that are not executed.

## What Gets Flagged

```python
def product_list(request):
    category = request.GET.get("category", "all")
    products = Product.objects.raw("SELECT * FROM shop_product WHERE category = %s", [category])
```

```python
@bp.post("/<int:post_id>/delete")
def delete(post_id):
    get_db().execute("DELETE FROM post WHERE id = ?", (post_id,))
```

Not flagged:

```python
products = Product.objects.filter(active=True).order_by("name")
```

## Remediation

1. Move the query into the repository, model manager or DAO and call that function from the handler.
2. Keep connection handling (`connect`, `cursor`) inside the data layer.
