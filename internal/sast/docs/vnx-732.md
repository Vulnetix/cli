## Overview

VNX-732 maps to [CWE-732: Incorrect Permission Assignment for Critical Resource](https://cwe.mitre.org/data/definitions/732.html). It reports three things in Python:

- `os.chmod`/`os.lchmod`/`os.fchmod` or `.chmod()` with a world-writable mode. That is an octal literal ending in 2, 3, 6 or 7, or `stat.S_IWOTH`/`stat.S_IRWXO`, given directly, as `mode=`, or through a variable assigned up to ten lines above.
- `os.umask()` with a value that leaves others-write unmasked, such as `os.umask(0)`.
- chmod of a path whose name says it holds a key or credential, to a mode that others can read.

**Severity:** High | **CWE:** [CWE-732](https://cwe.mitre.org/data/definitions/732.html) | **Languages:** python

## What Gets Flagged

```python
os.chmod(upload_dir, 0o777)                   # FLAGGED
Path("/var/lib/app/cache").chmod(0o777)       # FLAGGED
os.umask(0)                                   # FLAGGED
os.chmod(key_path, 0o644)                     # FLAGGED: key readable by everyone
```

Not reported:

- owner-only and group modes (`0o600`, `0o640`, `0o755` on ordinary files), and the sticky shared-directory mode `0o1777`
- umask values that mask others-write (`0o022`, `0o077`)
- the read-the-umask idiom `old = os.umask(0); os.umask(old)`
- modes passed to `os.open`/`os.makedirs`, which the umask filters
- test code, comments and strings

VNX-276 reports world-writable chmod across many languages.

## Remediation

1. Use `0o600` for secrets, `0o700` for private directories, and `0o644`/`0o755` for files that must be readable.
2. Never clear the umask. Keep at least `0o022`.
