---
title: "VNX-1090 – Method Containing Access of a Member Element from Another Class"
description: "Python code that reads, writes or reflects on another class's private member through its name-mangled form (obj._Owner__attr, getattr(obj, \"_Owner__attr\")), bypassing that class's own methods."
---

## Overview

VNX-1090 maps to [CWE-1090: Method Containing Access of a Member Element from Another Class](https://cwe.mitre.org/data/definitions/1090.html). It reports Python code that reaches into another class's private (double-underscore) member through the name-mangled spelling `_Owner__attr`, either as an attribute access or through `getattr`/`setattr`/`hasattr`/`delattr` with that name as a string. A subclass reaching its parent's private member is reported too.

**Severity:** Low | **CWE:** [CWE-1090](https://cwe.mitre.org/data/definitions/1090.html) | **Languages:** python

## Why This Matters

A double-underscore attribute is the owning class's private state. Code elsewhere that writes it skips whatever the class's own methods enforce (validation, locking, audit logging), and code that reads it breaks silently when the class changes its internals. This is the most explicit way Python code can access a member element of another class, so it is the one a static rule can report without guessing.

Not reported: a class using its own mangled name, single-underscore (protected) attributes, dunder names such as `__class__` and `__dict__`, the mangled name in a plain string or a comment, and test files. Access to another class's protected or public members is not judged, because without types it cannot be told apart from ordinary use.

## What Gets Flagged

```python
class Auditor:
    def reset(self, account):
        account._Account__balance = 0           # FLAGGED

def rotate(vault, new_key):
    setattr(vault, "_Vault__master_key", new_key)   # FLAGGED

class AdminSession(BaseSession):
    def elevate(self):
        return self._BaseSession__token          # FLAGGED
```

## Remediation

1. Add a method to the owning class that performs the operation and keeps its invariants, and call it instead.
2. If the value really is part of the public contract, expose it as a property.
3. For a confirmed intentional access, add a `# vulnetix-ignore: VNX-1090` comment on the line.
