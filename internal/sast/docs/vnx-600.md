---
title: "VNX-600 – Servlet parses request input with no handler for the exception"
description: "Reports servlet handlers and JSP scriptlets that convert a request parameter or header into a number, decimal, UUID or date outside any try block, so a malformed value throws out of the servlet."
---

## Overview

VNX-600 maps to [CWE-600: Uncaught Exception in Servlet](https://cwe.mitre.org/data/definitions/600.html). The rule looks inside servlet handlers (`doGet`, `doPost`, `doPut`, `doDelete`, `doHead`, `doOptions`, `doTrace` or `service` taking an `HttpServletRequest`) and JSP scriptlets for a conversion of request input: `Integer`/`Long`/`Short`/`Double`/`Float` `parse*` or `valueOf`, `new BigDecimal`, `new BigInteger`, `UUID.fromString`, or `LocalDate`/`LocalDateTime`/`Instant.parse`. The argument must be a request read (`getParameter`, `getHeader`, `getQueryString`, `getPathInfo`...) or a variable assigned from one within the 15 lines above, and the conversion must sit outside any `try` block.

It does not report conversions inside a `try`, in a helper method that handles the exception itself, of constants or of non-request data (properties, `argv`), code outside servlet handlers, or comments and string literals. Exceptions thrown by deeper calls are not traced.

**Severity:** Medium | **CWE:** [CWE-600](https://cwe.mitre.org/data/definitions/600.html) | **Languages:** java

## Why This Matters

A `NumberFormatException` or `IllegalArgumentException` that escapes the servlet becomes a 500 response. Depending on the container's error page configuration it carries a stack trace with class names, library versions and file paths, and the attacker can trigger it at will by sending `?id=x`.

## What Gets Flagged

```java
protected void doGet(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException {
    int id = Integer.parseInt(request.getParameter("id"));   // FLAGGED
}

String ref = req.getHeader("X-Order-Ref");
UUID orderId = UUID.fromString(ref);                          // FLAGGED

// NOT FLAGGED
try {
    int id = Integer.parseInt(request.getParameter("id"));
} catch (NumberFormatException e) {
    response.sendError(HttpServletResponse.SC_BAD_REQUEST, "bad id");
}
```

## Remediation

1. Catch the conversion exception and answer 400 Bad Request.
2. Validate the input format before converting it.
3. Configure a generic error page (`<error-page>` in `web.xml`) so no unhandled exception shows a stack trace.
