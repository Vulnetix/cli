---
title: "VNX-117 – Improper Output Neutralization for Logs"
description: "Decoded HTTP request data written into a Java, Python or Node log message without CR/LF neutralisation, inline or through a variable assigned from the request."
---

## Overview

VNX-117 maps to [CWE-117: Improper Output Neutralization for Logs](https://cwe.mitre.org/data/definitions/117.html). It reports a logger call whose arguments carry a decoded request value: Java `request.getParameter()`/`getHeader()` or a `String` handler parameter bound with `@RequestParam`, `@PathVariable`, `@RequestHeader` or `@CookieValue`; Python `request.args`/`form`/`json`/`headers`/`GET`/`POST`/`META`; Node `req.query`/`body`/`params`/`headers`/`cookies`. The value can be used inline, interpolated, or through a variable assigned from it (or from such a variable) in the 25 lines above.

Not reported: values passed through a CR/LF `replace`/`replaceAll`, an escaping or encoding call, `JSON.stringify`, `repr`/`%r`, or a numeric conversion; structured log calls whose first argument is an object literal; still-URL-encoded values such as `getRequestURI()`, `req.originalUrl` and `request.path`.

**Severity:** High | **CWE:** [CWE-117](https://cwe.mitre.org/data/definitions/117.html) | **Languages:** java, node, python

## Why This Matters

A request value containing `\r\n` starts a new line in a plain-text log. An attacker can forge entries ("login succeeded for admin"), hide their own activity among fake lines, or inject content that log viewers and SIEM parsers interpret as markup or fields.

## What Gets Flagged

```java
// FLAGGED
String user = request.getParameter("user");
log.warn("Failed login for user " + user);
log.info("User-Agent: {}", request.getHeader("User-Agent"));
```

```python
# FLAGGED
username = request.form.get("username")
logger.warning("failed login for %s", username)
app.logger.info(f"login attempt from {request.headers.get('X-Forwarded-For')}")
```

```javascript
// FLAGGED
console.log('login attempt for ' + req.body.username);
logger.warn(`bad password for ${req.body.username}`);
```

Not flagged: `log.info("User " + user.replace('\n', '_').replace('\r', '_'))`, `logger.info("query %r", request.args.get("q"))`, `console.log('search for ' + JSON.stringify(req.query.q))`, `pino.info({ query: req.query.q }, 'search')`.

## Remediation

1. Strip or replace `\r` and `\n` (and other control characters) from request values before logging them.
2. Prefer a structured (JSON) log encoder, which escapes newlines inside field values, and pass request data as fields rather than inside the message text.
3. In Python, `%r` or `repr()` renders control characters escaped.
