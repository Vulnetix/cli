---
title: "VNX-460 – Improper Cleanup on Thrown Exception"
description: "Reports Java code that releases a lock (unlock()) or closes a file, socket or JDBC resource (close()) only on the normal path, with no finally between acquisition and release, so an exception in between leaves it held or open."
---

## Overview

VNX-460 maps to [CWE-460: Improper Cleanup on Thrown Exception](https://cwe.mitre.org/data/definitions/460.html). It reports a `x.lock()` (including `readLock()`/`writeLock()`) followed later in the same block by `x.unlock()` with no `finally` in between, and a closeable resource (FileInputStream, FileWriter, Buffered*, RandomAccessFile, Socket, ZipFile, Object*Stream, Scanner, `getConnection()`, `prepareStatement()`, `Files.newInputStream()`...) assigned to a variable and later closed with `v.close()` in the same block with no `finally` in between. The lock/try/finally idiom, try-with-resources, release inside a finally block, tryLock branches, a lock released in another method and streams over in-memory buffers are not reported.

**Severity:** Medium | **CWE:** [CWE-460](https://cwe.mitre.org/data/definitions/460.html) | **Languages:** java

## Why This Matters

If anything between acquisition and release throws, the release never runs. A lock stays held and every later caller blocks; file descriptors and database connections leak until the pool or process runs out, which is a reliable denial of service.

## What Gets Flagged

```java
// FLAGGED: unlock() is skipped if validate() throws
lock.lock();
validate(delta);
value += delta;
lock.unlock();

// FLAGGED: the stream leaks if load() throws
FileInputStream in = new FileInputStream(file);
props.load(in);
in.close();

// NOT FLAGGED
lock.lock();
try {
    value += delta;
} finally {
    lock.unlock();
}
```

## Remediation

1. Call `unlock()` in a `finally` block that immediately follows `lock()`.
2. Open closeable resources in try-with-resources (`try (var in = new FileInputStream(f)) { ... }`).
3. For confirmed false positives, add a `// vulnetix-ignore: VNX-460` comment on the line.
