title: "VNX-345 – Insufficient Verification of Data Authenticity"
description: "Python code loads request, socket or downloaded bytes with marshal, executes code fetched over the network, or runs a downloaded file, with no signature or digest check in between."
---

## Overview

VNX-345 maps to [CWE-345: Insufficient Verification of Data Authenticity](https://cwe.mitre.org/data/definitions/345.html). It reports Python code that acts on data from an untrusted channel as though it were authentic:

1. `marshal.load()`/`loads()` (also through an `import marshal as m` alias or `from marshal import loads`) applied to request data (body, form, args, cookies, files, headers), bytes read from a socket, or a body downloaded with requests, httpx or `urlopen()`, inline or through a variable assigned from it (one further assignment, such as a base64 decode, is followed) within 12 lines;
2. `exec()`/`eval()` of content fetched with requests, httpx or `urlopen()`;
3. a file downloaded with `urlretrieve()` and then run with `subprocess`, `os.system` or `os.exec*`.

**Severity:** Medium | **CWE:** [CWE-345](https://cwe.mitre.org/data/definitions/345.html) | **Languages:** python

## Why This Matters

Bytes from a cookie, a form or a socket are written by whoever sent them. `marshal` builds code objects from them; executing downloaded code hands the process to whoever controls the server or the connection. Without an HMAC, a signature or a pinned digest, nothing establishes that the data came from where the code assumes.

Not reported: when the 15 lines above verify an HMAC or signature (`hmac.compare_digest`, `hmac.new`, itsdangerous signers, `.verify()`) or a downloaded file's hash; `json.loads` and `ast.literal_eval`; marshal of local files or of the program's own `dumps()`; comments and string literals.

Unpickling untrusted bytes is the same weakness, so it is reported once, by the rule that owns the call: `pickle`, `cPickle`, `_pickle`, `dill`, `cloudpickle` and `jsonpickle` are reported by [VNX-PY-003](../vnx-py-003/), and the loaders that unpickle under the hood (`torch.load`, `joblib.load`, `pandas.read_pickle`, `numpy.load(..., allow_pickle=True)`) by [VNX-PY-013](../vnx-py-013/), wherever the bytes come from.

## What Gets Flagged

```python
raw = base64.b64decode(request.form["code"])
code = marshal.loads(raw)

exec(requests.get(f"https://plugins.example.com/{name}.py").text)

path, _ = urllib.request.urlretrieve("https://downloads.example.com/agent.sh", "/tmp/agent.sh")
subprocess.run(["sh", path], check=True)
```

## Remediation

1. Exchange data in a format that cannot carry code (JSON) and validate it.
2. When a serialised object must round-trip through a client, sign it (itsdangerous, `hmac.new` over the bytes) and verify with `hmac.compare_digest` before loading.
3. Pin downloaded code by SHA-256 or verify its signature before executing it.
