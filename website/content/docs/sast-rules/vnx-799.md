## Overview

VNX-799 maps to [CWE-799: Improper Control of Interaction Frequency](https://cwe.mitre.org/data/definitions/799.html). It reports login, token, one-time-code and password-reset routes that accept credentials while nothing in the project caps how often they can be tried.

**Severity:** Medium | **CWE:** [CWE-799](https://cwe.mitre.org/data/definitions/799.html) | **Languages:** node, python

## Why This Matters

An endpoint that checks a password or a six-digit code answers as fast as the server can run. Without a limiter or an account lockout, credential stuffing, password spraying and OTP brute force cost the attacker nothing but requests.

The rule judges the project, not the line: a global `app.use(limiter)`, a NestJS `ThrottlerGuard`, flask-limiter `default_limits`, django-axes or lockout bookkeeping anywhere in the project silences it.

## What Gets Flagged

```javascript
// FLAGGED: login accepts POST, no limiter on the route or the app
app.post('/login', async (req, res) => { /* ... */ });

// FLAGGED: the limiter covers only the reset path
app.use('/rest/user/reset-password', rateLimit({ windowMs: 300000, max: 100 }));
app.post('/rest/user/login', login());
```

```python
# FLAGGED: Flask login accepting POST
@app.route("/login", methods=["GET", "POST"])
def login(): ...

# FLAGGED: Django urls.py with no axes / ratelimit
path("accounts/login/", views.login_view, name="login"),
```

Not flagged: `router.post('/login', loginLimiter, ctrl.login)`, `@limiter.limit("5 per minute")` under the route, a GET-only `@app.route("/login")`, `axios.post('/login')` client code.

```javascript
// FLAGGED: chained route and hapi route object
router.route('/login').post(async (req, res) => { /* ... */ });
server.route({ method: 'POST', path: '/auth/login', handler });
```

Also not flagged: a Django `path("login/", views.login_view)` whose view carries `@ratelimit(key="ip", rate="5/m")`, and a Koa app with `app.use(ratelimit({...}))`.

## Remediation

1. Put a limiter on every credential-checking route (express-rate-limit, @nestjs/throttler, flask-limiter, slowapi, django-ratelimit), keyed by account as well as IP.
2. Add progressive delay or temporary lockout after repeated failures (django-axes, a failed-attempts counter).
3. If a gateway enforces the limit, record that with a `vulnetix-ignore: VNX-799` comment on the route.
