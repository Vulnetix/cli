## Overview

VNX-277 maps to [CWE-277: Insecure Inherited Permissions](https://cwe.mitre.org/data/definitions/277.html). Some permission settings are not applied to one object but inherited by every object created after them. If that inherited set is too broad, every file, directory, pipe or registry key the program creates is too broad as well, including those created by libraries and child processes that never asked for it.

Reported:

- **A umask that leaves others-write open.** `umask(0)`, `umask(0000)`, `umask(020)` in C and C++, `os.umask(0)` in Python, `syscall.Umask(0)`/`unix.Umask(0)` in Go, `umask(0)` in PHP, `File.umask(0)` in Ruby, `process.umask(0)`/`process.umask("0000")` in Node.js, `umask 000`/`umask 0`/`umask a=rwx` in shell scripts and Dockerfile `RUN` lines, and `UMask=0000` in a systemd unit. Libraries create files with mode `0666` and directories with `0777` and rely on the umask to remove group and other write; with a zero umask they become world-writable.
- **A Windows NULL DACL.** `SetSecurityDescriptorDacl(&sd, TRUE, NULL, FALSE)` grants everyone full access to whatever is created with that descriptor.
- **An inheritable SDDL ACE for a broad group.** An allow ACE with `OI`/`CI` that gives Everyone (`WD`), Anonymous (`AN`), Authenticated Users (`AU`) or Users (`BU`) generic all or write rights, such as `D:(A;OICI;GA;;;WD)`.
- **A .NET access rule inherited by children.** `new FileSystemAccessRule(...)` or `new RegistryAccessRule(...)` that allows Everyone, Users, Authenticated Users or the World SID `FullControl`, `Modify` or write rights with `ContainerInherit`/`ObjectInherit`.

**Severity:** Low | **CWE:** [CWE-277](https://cwe.mitre.org/data/definitions/277.html) | **Languages:** C, C++, Python, Go, PHP, Ruby, JavaScript/TypeScript, shell, Dockerfile, systemd units, C#

## What Gets Flagged

```c
setsid();
umask(0);            // FLAGGED: everything the daemon creates later inherits it
chdir("/");
```

```c
SetSecurityDescriptorDacl(&sd, TRUE, NULL, FALSE);   // FLAGGED: NULL DACL
```

```csharp
// FLAGGED: Everyone gets FullControl on the directory and everything below it
security.AddAccessRule(new FileSystemAccessRule("Everyone", FileSystemRights.FullControl,
    InheritanceFlags.ContainerInherit | InheritanceFlags.ObjectInherit,
    PropagationFlags.None, AccessControlType.Allow));
```

```sh
umask 000            # FLAGGED
```

```ini
[Service]
UMask=0000           # FLAGGED: every file the service creates is world-writable
```

## What Is Not Flagged

- A umask that masks others-write: `022`, `027`, `077`, `002`.
- Reading the umask (`old = os.umask(0); os.umask(old)`, `$mask = umask();`), and a zero umask restored within a few statements, such as around an `os.open(path, flags, 0o600)` in a `try`/`finally`: that sets one exact mode on purpose and leaves nothing behind.
- A umask taken from a variable, a real DACL (`SetSecurityDescriptorDacl(&sd, TRUE, acl, FALSE)`), ACEs for SYSTEM or Administrators, read-only or non-inheritable rules, and deny rules.
- Test code and the calls in comments or strings.

## Remediation

```c
umask(027);   /* or 077 for private data */
```

```csharp
var rule = new FileSystemAccessRule(serviceAccountSid, FileSystemRights.Modify,
    InheritanceFlags.ContainerInherit | InheritanceFlags.ObjectInherit,
    PropagationFlags.None, AccessControlType.Allow);
```

Build a security descriptor that names the principals that need access instead of passing a NULL DACL.
