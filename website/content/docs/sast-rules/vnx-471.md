## Overview

VNX-471 maps to [CWE-471: Modification of Assumed-Immutable Data (MAID)](https://cwe.mitre.org/data/definitions/471.html). Reports Java public static final fields that hold a mutable value (a non-empty array, a new ArrayList/HashMap/HashSet/Date/StringBuilder and similar, or Arrays.asList), where final freezes only the reference. Immutable collections, empty arrays, non-public fields, test sources and comments are not reported.

**Severity:** Medium | **CWE:** [CWE-471](https://cwe.mitre.org/data/definitions/471.html) | **Languages:** java

## Why This Matters

This weakness class (Modification of Assumed-Immutable Data) creates a concrete exploit surface: the rule searches for the concrete source-level patterns most commonly associated with CWE-471 and surfaces them for review. Each finding should be evaluated in context — the rule catches the pattern, not the context.

## What Gets Flagged

```java
// FLAGGED: any caller can overwrite TRUSTED_HOSTS[0]
public static final String[] TRUSTED_HOSTS = {"api.acme.example", "auth.acme.example"};

// FLAGGED: a "constant" list anyone can add to
public static final List<String> ADMINS = new ArrayList<>();

// NOT FLAGGED: immutable
public static final List<String> SCOPES = List.of("read", "write");
```

## Remediation

1. Review each flagged line and determine whether the pattern represents a real instance of CWE-471 or a false positive.
2. Replace the flagged construct with a documented safe alternative appropriate to your language and framework.
3. For confirmed false positives, add a `# vulnetix-ignore: VNX-471` comment on the line.
4. Ensure equivalent test coverage exists to prevent regression.
