## Overview

VNX-690 maps to [CWE-690: Unchecked Return Value to NULL Pointer Dereference](https://cwe.mitre.org/data/definitions/690.html). Allocation functions, `fopen` and `getenv` report failure by returning `NULL`. When the caller dereferences the result without testing it, the failure becomes a crash (and, on some platforms, a write to a low address).

The rule reports, in C and C++ files:

- the result of `malloc`, `calloc`, `realloc`, `strdup`, `strndup`, `fopen` or `getenv` assigned to a variable that, within the next six code lines and with no NULL test in between, is dereferenced (`p->f`, `p[i]`, `*p`) or passed to a libc function that dereferences it (`strcpy`, `memcpy`, `memset`, `strlen`, `strcmp`, `sprintf`, `fprintf`, `fgets`, `fread`, `atoi` and similar);
- `getenv(...)` passed straight to such a function or indexed: `strcpy(buf, getenv("HOME"))`, `strlen(getenv("X"))`, `getenv("LANG")[0]`.

Not reported: an allocation inside an `if`/`while` condition or checked on the same line, a test of the variable (`== NULL`, `!= NULL`, `!p`, `if (p)`, `p &&`, a ternary, `assert`) before the use, wrapper allocators that abort on failure (`xmalloc`, `zmalloc`), a `getenv` result guarded by a ternary, string literals and comments. The value is not followed across functions. The two-line form overlaps VNX-476.

**Severity:** Low | **CWE:** [CWE-690](https://cwe.mitre.org/data/definitions/690.html) | **Languages:** c, cpp

## What Gets Flagged

```c
char *buf = malloc(n);
strcpy(buf, name);            // FLAGGED: buf may be NULL

FILE *fp = fopen(path, "a");
fprintf(fp, "started\n");     // FLAGGED: fp may be NULL

strcpy(home, getenv("HOME")); // FLAGGED: HOME may be unset
```

## What Is Not Flagged

```c
char *buf = malloc(n);
if (buf == NULL)
    return NULL;
strcpy(buf, name);

strcpy(dst, getenv("HOME") ? getenv("HOME") : "/");
```

## Remediation

1. Test every pointer returned by an allocator, `fopen` or `getenv` before using it, and handle the failure (return an error, fall back to a default).
2. Where the project has an aborting allocator (`xmalloc`), use it consistently.
