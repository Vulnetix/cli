## Overview

VNX-643 maps to [CWE-643: Improper Neutralization of Data within XPath Expressions ('XPath Injection')](https://cwe.mitre.org/data/definitions/643.html). It reports an XPath expression that splices a variable into the query text, either inline in the call or in a variable assigned up to 20 lines above, when that expression reaches an XPath compile or evaluate call.

**Severity:** High | **CWE:** [CWE-643](https://cwe.mitre.org/data/definitions/643.html) | **Languages:** java, python

## Why This Matters

XPath has no prepared statements by default. A value such as `' or '1'='1` closes the quoted literal and turns a lookup for one user into a match on every node, which is how XML-backed logins and directories are bypassed and dumped.

## What Gets Flagged

```java
xpath.evaluate("//stock[@supplier='" + supplier.getCode() + "']", doc, XPathConstants.NODESET);

String path = "//bin[@label='" + bin + "']";
XPathExpression expr = xpath.compile(path);

doc.selectSingleNode(String.format("//product[sku='%s']", sku));
```

A Java expression traced to request data (`request.getParameter`, a header or cookie, a `@RequestParam` or other annotated handler parameter, or a `String` method parameter spliced into a quoted value as in `"//user[@name='" + name + "']"`) is reported by [VNX-JAVA-013](../vnx-java-013/), the Java taint rule for the same injection, so the line appears once. This rule keeps the Java expressions built from any other non-constant value, and every Python one.

```python
tree.xpath(f"//user[@name='{user}' and @password='{pw}']")

query = f"/Employees/Employee[@emplid='{param}']"
run_query = lxml.etree.XPath(query)

root.findall(".//book[@author='" + author + "']")
```

Not flagged: `xpath.evaluate("//user[name/text()=$user]", doc)` with an `XPathVariableResolver`, `tree.xpath("//user[@name=$name]", name=user)`, constant expressions such as `ROOT + "/server/host"`, and other `evaluate()` calls (ScriptEngine, browser `document.evaluate`).

## Reading The Method First

Before reporting, the rule reads the enclosing Java method or Python function (at most 120 lines up) the way a reviewer would, and does not report an operand that provably holds a constant where the query is built:

- a literal it was last assigned on every path that reaches the query;
- the branch an `if`/`else` (Python `if`/`elif`/`else`) or a conditional expression actually takes, when the condition folds to a constant: integer literals and integer locals assigned once (`if (4 * 10) + n > 30` with `n = 5`), or in Python a literal tested with `in` / `not in` against a string local;
- the case a `switch` (Java) or `match` (Python) on a constant selects;
- the element a list index, or a map, dict or `ConfigParser` key, actually holds after the adds, removes, puts and pops above it, when that element is a literal;
- the result of a method or function in the same file (a nested class included) whose every return is constant.

```python
sku = request.args.get("sku", "")
batch = 8
if batch * 5 - 10 > 20:      # always true
    pick = "SKU-100"
else:
    pick = sku               # never runs
tree.xpath(f"//item[@sku='{pick}']")   # not flagged
```

In Python, a value placed inside an apostrophe-quoted XPath literal is also not reported when its apostrophes are replaced (`{name.replace("'", "&apos;")}`) or when an early return has proven it has none (`if "'" in name: return ...` above the query, in a block that encloses it). A value between double quotes is still reported, because the apostrophe check does not protect that delimiter.

Anything the analysis cannot resolve stays reported: a condition on run-time data, a helper in another file, a collection that is passed to a call or aliased, a value assigned inside `try`, a loop, or rebound by a tuple, `for`, `with` or walrus target.

## Remediation

1. Bind values as XPath variables: `XPath.setXPathVariableResolver` in Java, keyword arguments with `$name` in lxml.
2. If a variable cannot be bound, validate the value against a strict allow-list (for example digits only for an id).
3. Never build the expression text from request data.
