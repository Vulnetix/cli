title: "VNX-204 – Observable Response Discrepancy"
description: "Reports login code that answers an unknown user or email (\"User not found\", \"no such user\", \"Invalid username\") with a different message from a wrong password, which lets an attacker enumerate accounts."
---

## Overview

VNX-204 maps to [CWE-204: Observable Response Discrepancy](https://cwe.mitre.org/data/definitions/204.html). When a login form says "User not found" for one input and "Wrong password" for another, it tells an attacker which usernames or email addresses have accounts. That list is the starting point for credential stuffing, password spraying and targeted phishing.

**Severity:** Low | **CWE:** [CWE-204](https://cwe.mitre.org/data/definitions/204.html) | **Languages:** Python, JavaScript/TypeScript, Go, Java, PHP, Ruby, C#

## What Gets Flagged

A string literal saying the user, username, account, email or login does not exist, is not found, unknown, invalid or not registered, within 20 lines of and in the same function as a distinct message saying the password is wrong. The user-not-found line is reported.

```python
if user is None:
    return jsonify(error="User not found"), 401        # flagged
if not user.check_password(request.form["password"]):
    return jsonify(error="Incorrect password"), 401
```

```ruby
raise AuthError, "#{email} doesn't exist" unless user  # flagged
raise AuthError, "Incorrect Password!" unless user.authenticate(password)
```

Not flagged: one combined message ("Invalid username or password"), a not-found message with no password message beside it (an admin lookup returning 404), log statements, test code, messages in comments, and messages in different functions. Timing differences between the two branches are covered by [VNX-205](../vnx-205/).

## Remediation

Return the same message, status code and response shape for both cases:

```python
if user is None or not user.check_password(request.form["password"]):
    return jsonify(error="Invalid username or password"), 401
```
