## Overview

VNX-444 maps to [CWE-444: Inconsistent Interpretation of HTTP Requests ('HTTP Request/Response Smuggling')](https://cwe.mitre.org/data/definitions/444.html). When a front-end proxy and a back-end server disagree about where one request ends, an attacker can hide a second request inside the first and have it processed with someone else's connection.

The rule reports two code shapes that create that disagreement:

1. **Lenient parsing.** `insecureHTTPParser: true` in `http`/`https` server or request options, or `--insecure-http-parser` in a script or `NODE_OPTIONS`.
2. **Two framing headers.** `Transfer-Encoding` and `Content-Length` both set (setHeader/putheader/header calls, header-object keys, index assignments) within five lines of each other in the same branch, or a raw HTTP string carrying both. The finding is on the `Transfer-Encoding` line.

Not reported: `insecureHTTPParser: false`, `Transfer-Encoding` set after removing `Content-Length`, the two headers set in alternative branches (`if length: ... else: chunked`, or a branch that returns before the other header is set), code that reads or compares the headers, comments and prose strings.

**Severity:** Medium | **CWE:** [CWE-444](https://cwe.mitre.org/data/definitions/444.html) | **Languages:** Node.js, Python

## What Gets Flagged

```javascript
// FLAGGED: lenient parser
const server = http.createServer({ insecureHTTPParser: true }, app);

// FLAGGED: both framing headers on one response
res.setHeader('Content-Length', body.length);
res.setHeader('Transfer-Encoding', 'chunked');
```

```python
# NOT FLAGGED: alternatives, never both
if length:
    headers["Content-Length"] = str(length)
else:
    headers["Transfer-Encoding"] = "chunked"
```

## Remediation

1. Remove `insecureHTTPParser` and `--insecure-http-parser`; fix the client that needed them.
2. Send exactly one framing header: `Content-Length` when the size is known, chunked otherwise.
3. Reject inbound requests that carry both headers.
