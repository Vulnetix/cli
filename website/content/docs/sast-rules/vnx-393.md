---
title: "VNX-393 – Return of Wrong Status Code"
description: "A Java catch block reports success for an operation that failed: an HTTP 200 response (ResponseEntity.ok, HttpStatus.OK, Response.ok, setStatus(200)) or return true from a verify/validate/authorize-style method."
---

## Overview

VNX-393 maps to [CWE-393: Return of Wrong Status Code](https://cwe.mitre.org/data/definitions/393.html). It reports, inside the body of a Java catch block, an HTTP success answer (`return ResponseEntity.ok(...)`, `ResponseEntity.status(HttpStatus.OK)`, `new ResponseEntity<>(..., HttpStatus.OK)`, JAX-RS `Response.ok(...)`, or `setStatus(200)`/`setStatus(SC_OK)`), and `return true;` in a boolean method whose name makes a security or validity decision (`verify*`, `validate*`, `authenticate*`, `authorize*`, `checkPermission*`/`checkAccess*`/`checkSignature*`/`checkToken*`/`checkPassword*`, `hasPermission*`, `hasAccess*`, `canAccess*`, `isValid*`, `isAuthorized*`, `isAuthenticated*`, `isAllowed*`, `isPermitted*`, `isTrusted*`, `isVerified*`, `isSecure*`, `isSafe*`, and names such as `isTokenValid` or `isUserAllowed`), which fails open. A return broken after `ResponseEntity`/`Response` (`return ResponseEntity` then `.ok()`) is read as one statement.

Not reported: a catch that returns an error status or `false`, `return true` from a method whose name is not such a decision (`isRetryable`, `deleteQuietly`) or is negated (`isNotAllowed`, which fails closed), success statuses outside a catch, test files and comments.

**Severity:** Low | **CWE:** [CWE-393](https://cwe.mitre.org/data/definitions/393.html) | **Languages:** java

## Why This Matters

The caller acts on the status. A transfer that failed but answered 200 is shown to the user as done; a signature check whose crypto threw and returned `true` accepts any forged token.

## What Gets Flagged

```java
} catch (InsufficientFundsException e) {
    return ResponseEntity.ok("transfer failed: " + e.getMessage());   // FLAGGED
}

public boolean verifySignature(byte[] payload, byte[] sig) {
    try {
        return s.verify(sig);
    } catch (GeneralSecurityException e) {
        return true;                                                  // FLAGGED: fails open
    }
}
```

## Remediation

1. Return the error status that describes the failure (`ResponseEntity.badRequest()`, `status(HttpStatus.INTERNAL_SERVER_ERROR)`, `sendError`).
2. A security decision must fail closed: return `false` or rethrow.
