## Overview

VNX-756 maps to [CWE-756: Missing Custom Error Page](https://cwe.mitre.org/data/definitions/756.html). It reports configuration that sends the framework's debug error page (stack trace, source lines, local variables) to the client in place of a custom error page:

- FastAPI and Starlette: `FastAPI(debug=True)`, `Starlette(debug=True)`
- Tornado: `debug=True` or `serve_traceback=True`, as an `Application` keyword or a settings entry
- Bottle: `bottle.debug(True)`, `debug(True)` and `run(..., debug=True)`
- CherryPy: `'request.show_tracebacks': True`
- Sanic and Quart: `app.run(..., debug=True)`
- web.py: `web.config.debug = True` and `app.internalerror = web.debugerror`

For every framework except FastAPI and Starlette, the file must import that framework.

**Severity:** Low | **CWE:** [CWE-756](https://cwe.mitre.org/data/definitions/756.html) | **Languages:** python

## What Gets Flagged

```python
app = FastAPI(
    title="Orders",
    debug=True,          # reported on the FastAPI( line
)
cherrypy.config.update({"request.show_tracebacks": True})   # FLAGGED
```

Not reported: debug read from an environment variable, a setting or a flag, `debug=False`, `run(debug=True)` on other objects, test code and comments. VNX-PY-008 covers the Flask debugger and VNX-PY-006 covers Django `DEBUG = True`.

## Remediation

1. Turn debug off in deployed configuration, and read it from the environment with `False` as the default.
2. Register a generic error handler that logs the exception on the server and returns a plain error page.
