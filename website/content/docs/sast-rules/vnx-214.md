## Overview

VNX-214 maps to [CWE-214: Invocation of Process Using Visible Sensitive Information](https://cwe.mitre.org/data/definitions/214.html). A process's arguments are public on the host: any local user can read them with `ps` or from `/proc/<pid>/cmdline`, and they are recorded by process accounting, audit logs, CI logs and crash reports. A password passed as an argument is therefore disclosed to everyone on the machine for as long as the process runs.

The rule reports a credential argument whose value is dynamic (a variable, concatenation, interpolation or format verb):

- a credential flag: `--password`, `--passwd`, `--pass`, `--secret`, `--token`, `--api-key`, `--client-secret`, `--access-token`, `--auth-token` (also prefixed, such as `--db-password`), attached (`--password=` + x), interpolated (`f"--token={t}"`, `` `--api-key=${k}` ``, `{1}`, `%s`) or as the next element of an argument list (`["--token", tok]`);
- `mysql`/`mysqldump`/`mysqladmin`/`mariadb` `-p<value>` built from a variable;
- `sshpass -p <variable>`, `redis-cli -a <variable>`, `openssl ... -passout pass:<value>`, npm `:_authToken=<value>`;
- a URL argument with the password in it: `f"--dbname=postgresql://{user}:{password}@{host}/{db}"`.

In code the line that builds the argument is reported, wherever it is executed later; an argument list passed to `subprocess`, `child_process`, `exec.Command`, `ProcessBuilder`/`Runtime.exec`, PHP `exec`/`system`/`proc_open`/Symfony `Process`, or C# `Process.Start`/`ProcessStartInfo` is reported at the call. In shell scripts, Makefiles and Dockerfiles the same flags with a `$` value are reported, plus `docker login -p "$X"`, `curl -u "user:$X"`, `openssl -pass pass:"$X"`, `redis-cli -a "$X"` and clients given a URL such as `pg_dump "postgresql://app:${DB_PASSWORD}@db/app"` or `git clone "https://x-access-token:$TOKEN@github.com/..."`.

**Severity:** Medium | **CWE:** [CWE-214](https://cwe.mitre.org/data/definitions/214.html) | **Languages:** Python, JavaScript/TypeScript, Go, Java, PHP, C#, shell, Dockerfile

## What Gets Flagged

```python
subprocess.run(["mysqldump", "-u", user, f"-p{password}", db], check=True)   # FLAGGED
```

```go
return exec.Command("mysqldump", "-u", user, "-p"+password, db).Run()   // FLAGGED
```

```javascript
spawn('sshpass', ['-p', password, 'ssh', host]);   // FLAGGED
```

```sh
mysqldump -u "$DB_USER" -p"$DB_PASSWORD" shop > /backups/shop.sql          # FLAGGED
docker login -u "$REGISTRY_USER" -p "$REGISTRY_TOKEN" registry.example.com  # FLAGGED
openssl pkcs12 -export -in cert.pem -out bundle.p12 -passout pass:"$P12_PASSWORD"   # FLAGGED
```

## What Is Not Flagged

- A connection URL built for a library driver (`create_engine(f"postgresql://{u}:{p}@h/db")`) rather than a command.
- Credentials passed through the environment (`MYSQL_PWD`, `PGPASSWORD`, `env=`, `openssl -pass env:VAR`), stdin (`--password-stdin`, `input=`) or a file (`--password-file`, `--defaults-extra-file`, `sshpass -f`/`-e`).
- A bare `-p` that prompts, and `-p` meaning port or parents (`docker run -p`, `ssh -p`, `mkdir -p`).
- CLI option definitions (`add_argument("--password", ...)`, `@click.option("--api-key", ...)`).
- Literal credentials in shell scripts (VNX-BASH-005 reports those), comments and test code.

## Remediation

```python
subprocess.run(["mysqldump", "-u", user, db], env={**os.environ, "MYSQL_PWD": password}, check=True)
```

```sh
printf '%s' "$REGISTRY_TOKEN" | docker login -u "$REGISTRY_USER" --password-stdin registry.example.com
```
