title: "VNX-476 – NULL Pointer Dereference"
description: "Detects a value that can be NULL being dereferenced before it is checked: an unchecked malloc/calloc/realloc/strdup/fopen/getenv result in C and C++, and an unchecked request parameter, header, environment variable, system property or listFiles() result in Java."
---

## Overview

VNX-476 maps to [CWE-476: NULL Pointer Dereference](https://cwe.mitre.org/data/definitions/476.html). Some calls return NULL as their normal way of saying "no": an allocation that failed, a file that could not be opened, an environment variable or request parameter that was not sent. Dereferencing that result crashes the process, and on some platforms turns into memory corruption. The rule reports:

1. **C/C++:** the result of `malloc`, `calloc`, `realloc`, `strdup`, `strndup`, `fopen` or `getenv` assigned to a variable and, within the next six code lines with no NULL test in between, dereferenced (`p->f`, `p[i]`, `*p`) or passed to a libc function that dereferences it (`memcpy`, `memset`, `strcpy`, `strlen`, `strcmp`, `sprintf`, `fgets`, `fprintf`, `fread`, `fclose`, `atoi` and similar).
2. **Java:** `request.getParameter(...)`, `request.getHeader(...)`, `System.getenv(...)` or one-argument `System.getProperty(...)` dereferenced by a chained call, or assigned to a variable whose method is called within six code lines without a null check, and a for-each over `File.listFiles()`.

Not reported: an allocation made inside an `if`/`while` condition, a variable tested before use (`== NULL`, `!p`, `p &&`, `assert`, `serverAssert`, a ternary, `Objects.requireNonNull`, `Assert.notNull`, `StringUtils.isEmpty`), wrapper allocators such as `xmalloc`/`zmalloc` that never return NULL, a constant-first comparison (`"x".equals(v)`), `getProperty` with a default, the system properties the JVM always defines (`os.name`, `user.home`, `user.dir`, `java.*`, the separators), and comments. NULL returned by the project's own functions, fields and cross-function flows are not followed.

**Severity:** Medium | **CWE:** [CWE-476](https://cwe.mitre.org/data/definitions/476.html) | **Languages:** C, C++, Java

## What Gets Flagged

```c
// FLAGGED: malloc may return NULL
char *out = (char *) malloc(len + 1);
memcpy(out, msg, len);

// FLAGGED: HOME may be unset
const char *home = getenv("HOME");
strcpy(dst, home);
```

```java
// FLAGGED: null when the parameter is absent
String q = request.getParameter("q").trim();

String auth = req.getHeader("Authorization");
if (auth.startsWith(scheme)) { ... }
```

## What Is Not Flagged

```c
char *p = malloc(len + 1);
if (p == NULL)
    return NULL;
memcpy(p, name, len);
```

```java
String name = request.getParameter("name");
if (name == null) return "anonymous";
return name.trim();
```

## Remediation

1. Check every allocation, `fopen` and `getenv` result before using it, and handle the failure (return an error, use a default).
2. In Java, test request values and environment variables for null, use `Optional.ofNullable`, or call `getProperty(key, default)`.
3. Put the constant first in comparisons (`"debug".equals(mode)`) so a null value compares false instead of throwing.
