## Overview

CWE-928 is the OWASP Top Ten 2013 view; this rule reports its most concrete Java/Kotlin manifestation, a broken or obsolete symmetric cipher (A6 Sensitive Data Exposure): Cipher, SecretKeyFactory or KeyGenerator .getInstance with DES, DESede/TripleDES/3DES, RC4/ARCFOUR, RC2 or Blowfish (any mode and padding), the same algorithm passed through a String constant assigned in the same file, new SecretKeySpec(key, "DES"/"RC4"/...), and new DESKeySpec/DESedeKeySpec. Not reported: AES, ChaCha20 and RSA transformations, algorithm names in comments, log messages or other string literals not passed to a crypto API, and identifiers that only start with DES (DESCRIPTOR, DESIGN). A constant defined in another file is not followed.

**Severity:** Medium | **CWE:** [CWE-928: Weaknesses in OWASP Top Ten (2013)](https://cwe.mitre.org/data/definitions/928.html) | **Languages:** Java, Kotlin

## Why This Matters

DES has a 56-bit key that can be brute-forced, 3DES and Blowfish have 64-bit blocks open to Sweet32 collision attacks, and RC4 and RC2 are broken. Data encrypted with them should be treated as recoverable.

## What Gets Flagged

```
Cipher c = Cipher.getInstance("DES/CBC/PKCS5Padding");
Cipher rc4 = Cipher.getInstance( "RC4" );
SecretKeySpec spec = new SecretKeySpec(raw, "RC4");

private static final String TRANSFORMATION = "DESede/ECB/PKCS5Padding";
return Cipher.getInstance(TRANSFORMATION);
```

## What Is Not Flagged

```
Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
Cipher x = Cipher.getInstance("ChaCha20-Poly1305");
log.info("DES is not supported");
```

## Remediation

1. Use AES-GCM (`AES/GCM/NoPadding`) with a 128- or 256-bit key and a unique 12-byte IV per message, or ChaCha20-Poly1305.
2. Re-encrypt stored data that was protected with a broken cipher.
3. For a confirmed false positive, add a `vulnetix-ignore: VNX-928` comment on the line.
