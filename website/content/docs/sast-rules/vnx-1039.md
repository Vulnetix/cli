title: "VNX-1039 – reCAPTCHA v3 verdict accepted without checking the score"
description: "Reports Python and JavaScript/TypeScript handlers in reCAPTCHA v3 projects that accept the siteverify response on success alone, and score checks against 0, so the bot detector never rejects a bot."
---

## Overview

VNX-1039 maps to [CWE-1039: Automated Recognition Mechanism with Inadequate Detection or Handling of Adversarial Input Perturbations](https://cwe.mitre.org/data/definitions/1039.html). reCAPTCHA v3 is an automated recognition mechanism: `siteverify` answers `success: true` for every well-formed token, bots included, and the bot/human judgement is only in the `score` (0.0 to 1.0). The rule reports:

- in a project that uses reCAPTCHA v3 (`grecaptcha.execute(...)`, `api.js?render=<site key>`, react-google-recaptcha-v3, a `RECAPTCHA_V3` name), a file that handles the siteverify response and reads `success` but never mentions the score;
- a score compared against 0 (`score > 0`, `score >= 0.0`), which accepts every request.

Not reported: reCAPTCHA v2, hCaptcha and Turnstile projects (no score; `success` is the verdict), handlers that read the score, comments and test files. CWE-1039 in general (machine-learning classifiers that adversarial input can fool) has no static signature; this rule covers the concrete case of a bot-detection score being ignored.

**Severity:** Medium | **CWE:** [CWE-1039](https://cwe.mitre.org/data/definitions/1039.html) | **Languages:** Python, JavaScript/TypeScript

## Why This Matters

A v3 integration that checks only `success` blocks nothing: an automated client that obtains any token passes, so sign-up, login and contact forms are open to credential stuffing and spam while the team believes they are protected.

## What Gets Flagged

```python
result = r.json()
if not result["success"]:
    abort(403)
```

```javascript
const { success } = await resp.json();
```

```python
return data.get("success") and data.get("score", 0) >= 0.0
```

## Remediation

1. Reject requests whose `score` is below a threshold suited to the action (Google suggests starting at 0.5).
2. Check that `action` matches the action the page executed, and that `hostname` is yours.
