title: "VNX-597 – String compared with == or != instead of equals()/strcmp()"
description: "Reports Java comparisons of a String with a string literal or with another String variable by == or !=, and C comparisons of a char pointer with a string literal, which compare references or addresses rather than content."
---

## Overview

VNX-597 maps to [CWE-597: Use of Wrong Operator in String Comparison](https://cwe.mitre.org/data/definitions/597.html). In Java, `==` on two Strings compares references, so the result depends on whether both happen to be the same interned object. In C, comparing a `char *` with a string literal compares addresses.

The rule reports:

- in Java, any expression compared with a string literal by `==` or `!=` (`role == "admin"`, `request.getParameter("a") == "x"`, also with the literal on the next line);
- in Java, a comparison of two variables both declared `String` within the 60 lines above;
- in `.c` files, an expression compared with a string literal.

It does not report `equals`, `equalsIgnoreCase`, `Objects.equals` or `strcmp`, comparisons with `null`, char literals (`c == 'a'`), C++ files (where `std::string` overloads `==`), Kotlin (where `==` is `equals`), or operators inside comments and string literals. Boxed numbers and other objects compared by reference are [VNX-595](../vnx-595/).

**Severity:** Medium | **CWE:** [CWE-597](https://cwe.mitre.org/data/definitions/597.html) | **Languages:** java, c

## Why This Matters

A string read from a request, a file or a database is never the interned literal, so a check like `if (role == "admin")` is always false for real input and true only in a unit test that passes the literal. The reverse, `if (token != expected)`, rejects or accepts depending on how the two values were built. Either way a security decision no longer depends on the value.

## What Gets Flagged

```java
if (role == "admin") { }                              // FLAGGED
if (request.getParameter("action") == "delete") { }   // FLAGGED
return presented == expectedToken;                    // FLAGGED (both String)
```

```c
if (input == "letmein") { }                           /* FLAGGED */
```

```java
// NOT FLAGGED
if ("admin".equals(role) || Objects.equals(role, "root")) { }
if (role == null || c == 'a') { }
```

## Remediation

1. Java: use `"literal".equals(value)` (null-safe) or `Objects.equals(a, b)`; for secrets compare with `MessageDigest.isEqual` on the bytes.
2. C: use `strcmp`/`strncmp`, or a constant-time comparison for secrets.
