## Overview

VNX-482 maps to [CWE-482: Comparing instead of Assigning](https://cwe.mitre.org/data/definitions/482.html). `session.isAdmin === false;` was meant to revoke a privilege and does nothing; `cart.total == 0` in a Python test was meant to be an `assert` and checks nothing. The rule reports a line that is only `lvalue == expression` (or `===` in JavaScript/TypeScript) used as a statement, and `for (i == 0; ...)`.

Not reported: comparisons that are part of a larger statement (`assert`, `return`, `if`, an assignment, a call argument, a ternary, `a == b && f()`), continuation lines of a multi-line expression (the previous line ends with an operator, a comma or an open bracket, or the next line continues it), Python docstrings, a comparison directly under `with pytest.raises(...)` or `self.assertRaises(...)` (evaluated on purpose to prove `__eq__` raises), comparisons inside strings and comments, and Java and C#, where a statement that only compares does not compile.

**Severity:** Medium | **CWE:** [CWE-482](https://cwe.mitre.org/data/definitions/482.html) | **Languages:** C, C++, JavaScript, TypeScript, Python

## What Gets Flagged

```c
s->authenticated == 0;           /* FLAGGED: meant = */
for (i == 0; i < n; i++)         /* FLAGGED */
```

```javascript
session.isAdmin === false;       // FLAGGED
```

```python
def test_clear():
    cart.clear()
    cart.total == 0              # FLAGGED: missing assert
```

## What Is Not Flagged

```python
assert cart.total == 0
ok = a == b
```

## Remediation

1. Use `=` when an assignment was meant.
2. In tests, write `assert` (or the framework's assertion) in front of the comparison.
3. Enable the compiler or linter warning for unused expression results (`-Wunused-value`, ESLint `no-unused-expressions`, Ruff/Pylint `B015`/`W0104`).
