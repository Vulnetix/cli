## Overview

VNX-1322 maps to [CWE-1322: Use of Blocking Code in Single-threaded, Non-blocking Context](https://cwe.mitre.org/data/definitions/1322.html). A Node.js server runs every request on one thread. A synchronous file, process, key-derivation or compression call inside a request handler stops that thread until it returns, so every other client waits.

**Severity:** Medium | **CWE:** [CWE-1322](https://cwe.mitre.org/data/definitions/1322.html) | **Languages:** node

## Why This Matters

A single slow disk read or child process inside a handler turns into server-wide latency, and an attacker who can trigger the call repeatedly (a large file, an expensive `pbkdf2Sync`) can deny service to everyone with a handful of requests.

## What Gets Flagged

The rule looks for a sync API inside a function whose parameters are `(req, res)`, `(request, reply)`, `(request, response)`, `(request, h)` or a Koa `ctx`, including `http.createServer` callbacks and TypeScript-typed parameters.

```javascript
router.get('/docs/:name', (req, res) => {
  const body = fs.readFileSync(file, 'utf8')            // FLAGGED
  res.send(body)
})

this.handleLogin = function(req, res, next) {
  var key = crypto.pbkdf2Sync(req.body.password, salt, 210000, 64, "sha512")  // FLAGGED
}

convert.post('/convert', async (req: Request, res: Response) => {
  const out = execSync(`soffice --convert-to pdf ${input}`)  // FLAGGED
})
```

## What Is Not Flagged

- Sync calls at module level or in a helper outside any handler (loading certificates or config at startup, warming a cache).
- `fs.promises.*`, callback-style `fs.readFile`, `execFile` with a callback.
- Build scripts and CLIs, test files, comments and string literals.
- A sync call reached from a handler through a helper function defined elsewhere is not followed.

## Remediation

1. Use the asynchronous form: `await fs.promises.readFile(...)`, `execFile(..., cb)` or `util.promisify(exec)`, `crypto.pbkdf2(..., cb)`, `zlib.gzip(..., cb)`, `bcrypt.compare(...)`.
2. Move unavoidable synchronous work to startup, or to a worker thread.
