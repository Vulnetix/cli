---
title: "VNX-360 – Android receiver for a system broadcast trusts the intent without checking its action"
description: "Reports BroadcastReceiver.onReceive methods (Java, Kotlin) that act on a system broadcast such as BOOT_COMPLETED or SMS_RECEIVED without checking intent.getAction(), where the receiver is reachable by other apps."
---

## Overview

VNX-360 maps to [CWE-360: Trust of System Event Data](https://cwe.mitre.org/data/definitions/360.html). Only the system can broadcast `BOOT_COMPLETED`, `SMS_RECEIVED` or `POWER_CONNECTED`, but any installed app can deliver an intent straight to an exported receiver by naming its component. A receiver that acts without checking the intent's action therefore treats a forged "system event", and its extras, as genuine.

The rule reports, in Java and Kotlin, an `onReceive(Context, Intent)` method whose body (up to 40 lines) never reads the intent's action (`getAction()`, `intent.action`, `intent?.action`), when the receiver is:

- registered in the same file with an `IntentFilter(...)` / `addAction(...)` naming a system action (`Intent.ACTION_*`, `"android.intent.action.*"`, `"android.provider.Telephony.*"`, `Telephony.Sms.Intents.*`, `*_ACTION` constants), or
- declared in an `AndroidManifest.xml` `<receiver>` whose intent filter names an `android.*` system action and which is neither `android:exported="false"` nor protected by `android:permission`.

Not reported: receivers that check the action, receivers for the app's own custom actions only (VNX-ANDROID-003 judges exported components), receivers registered with `RECEIVER_NOT_EXPORTED`, non-exported or permission-protected manifest receivers, and test files.

**Severity:** Low | **CWE:** [CWE-360](https://cwe.mitre.org/data/definitions/360.html) | **Languages:** android, java, kotlin

## What Gets Flagged

```xml
<receiver android:name=".sync.BootReceiver" android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.BOOT_COMPLETED" />
    </intent-filter>
</receiver>
```

```java
// FLAGGED: any app can send this receiver an explicit intent with any extras
public void onReceive(Context context, Intent intent) {
    String account = intent.getStringExtra("account");
    SyncService.wipeAndResync(context, account);
}
```

```java
// NOT FLAGGED
public void onReceive(Context context, Intent intent) {
    if (!Intent.ACTION_BOOT_COMPLETED.equals(intent.getAction())) {
        return;
    }
    SyncService.schedule(context);
}
```

## Remediation

1. Check `intent.getAction()` against the expected system action before doing anything.
2. Do not trust extras on a system-event intent; system broadcasts such as `BOOT_COMPLETED` carry none.
3. Register dynamic receivers with `RECEIVER_NOT_EXPORTED`, and protect SMS receivers with `android:permission="android.permission.BROADCAST_SMS"`.
