## Overview

VNX-1188 maps to [CWE-1188: Initialization of a Resource with an Insecure Default](https://cwe.mitre.org/data/definitions/1188.html). Reports a security setting that is initialised to its insecure value whenever nobody configures it. Python: a top-level DEBUG = True in a settings module that is not a development/local/test settings file, and an environment or config read (os.environ.get, os.getenv, os.environ.setdefault, decouple config(), django-environ env()/env.bool()) whose fallback value turns on a debug/insecure switch (DEBUG as the last word of the name, DEBUG_MODE, ALLOW_INSECURE, SKIP_TLS_VERIFY, DISABLE_AUTH, DISABLE_CSRF, NO_AUTH, CORS_ALLOW_ALL ...) or turns off a protection (VERIFY_SSL, TLS_VERIFY, CHECK_CERT, REQUIRE_AUTH, AUTH_ENABLED, CSRF_ENABLED, SECURE_COOKIES, SESSION_COOKIE_SECURE, SECURE_SSL_REDIRECT, HTTPS_ONLY, COOKIE_SECURE, REJECT_UNAUTHORIZED ...). Pydantic BaseSettings: a bool field declared directly in a class deriving from BaseSettings whose default is the insecure value (debug: bool = True, verify_ssl: bool = False). JavaScript/TypeScript: process.env.NAME || value or ?? value with the same insecure fallback, a destructuring default from process.env (const { DEBUG = 'true' } = process.env), process.env.INSECURE_SWITCH !== 'false' (on unless disabled) and process.env.PROTECTION === 'true' (off unless enabled). Not reported: a secure fallback (DEBUG defaulting to False, VERIFY_SSL defaulting to True), a read with no fallback, non-boolean settings, names that configure a debug tool rather than a debug mode (DEBUG_COLORS, DEBUG_PORT), a read quoted inside a string literal, a BaseSettings subclass of a project base class (the base is not followed), DEBUG = True in dev/local/test settings files or indented inside a class or docstring, comments, strings and test files. Overlaps VNX-PY-006 for Django DEBUG.

**Severity:** Medium | **CWE:** [CWE-1188](https://cwe.mitre.org/data/definitions/1188.html) | **Languages:** node, python

This weakness class (Initialization of a Resource with an Insecure Default) creates a concrete exploit surface: the rule searches for the concrete source-level patterns most commonly associated with CWE-1188 and surfaces them for review. Each finding should be evaluated in context — the rule catches the pattern, not the context.

## What Gets Flagged

```python
DEBUG = True                                         # FLAGGED (settings.py)
WEB_DEBUG = os.environ.get("WEB_DEBUG", True)        # FLAGGED
VERIFY_SSL = os.getenv("VERIFY_SSL", "false") == "true"  # FLAGGED
DEBUG = os.getenv("DEBUG", "False") == "True"        # not flagged

// JavaScript
skipVerify: process.env.SKIP_TLS_VERIFY !== 'false',  // FLAGGED
secureCookies: process.env.SECURE_COOKIES === 'true',  // FLAGGED
```
