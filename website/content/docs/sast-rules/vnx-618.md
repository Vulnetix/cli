## Overview

VNX-618 maps to [CWE-618: Exposed Unsafe ActiveX Method](https://cwe.mitre.org/data/definitions/618.html). A control that tells the browser it is safe for scripting makes every one of its methods callable by any web page. The rule reports the places where that claim is made, and the pages that load a control whose methods run commands or touch the file system.

**Severity:** Low | **CWE:** [CWE-618](https://cwe.mitre.org/data/definitions/618.html) | **Languages:** C, C++, HTML, JavaScript

## What Gets Flagged

```cpp
public IObjectSafetyImpl<CLauncher, INTERFACESAFE_FOR_UNTRUSTED_CALLER | INTERFACESAFE_FOR_UNTRUSTED_DATA>,
*pdwEnabledOptions = INTERFACESAFE_FOR_UNTRUSTED_CALLER | INTERFACESAFE_FOR_UNTRUSTED_DATA;
IMPLEMENTED_CATEGORY(CATID_SafeForScripting)
```

```
'Implemented Categories'
{
    {7DD95801-9882-11CF-9FA9-00AA006C42C4}
}
```

```javascript
var sh = new ActiveXObject("WScript.Shell");
```

```html
<object id="shell" classid="clsid:72C24DD5-D70A-438B-8A42-98424B88AFB8"></object>
```

Not flagged: the flag and GUID definitions themselves (`#define`, `DEFINE_GUID`, `extern` declarations), a mask test in `SetInterfaceSafetyOptions`, ActiveX objects with no command or file capability (`Msxml2.XMLHTTP`, `Microsoft.XMLDOM`), media `<object>` embeds, comments and string literals.

## Remediation

1. Do not mark a control safe for scripting unless every exposed method is safe with hostile arguments.
2. Restrict the control to approved sites (SiteLock) and remove methods that run commands or read and write files.
3. Replace page dependencies on `WScript.Shell`, `Shell.Application`, `Scripting.FileSystemObject` or `ADODB.Stream` with server-side code.
