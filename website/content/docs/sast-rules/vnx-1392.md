title: "VNX-1392 – Use of Default Credentials"
description: "Reports a default account (admin, root, sa, guest, postgres, elastic, tomcat, pi, ...) configured with a default, guessable or empty password: in a URL or DSN, a connection string, as adjacent call arguments, or as neighbouring user and password keys in code and configuration."
---

## Overview

VNX-1392 maps to [CWE-1392: Use of Default Credentials](https://cwe.mitre.org/data/definitions/1392.html). A default account with its default password (`admin/admin`, `root/root`, `guest/guest`, `postgres/postgres`, `elastic/changeme`, `sa` or `root` with no password) is the first pair credential-stuffing tools try. The rule reports the pair when the account is one of `admin`, `administrator`, `root`, `sa`, `guest`, `postgres`, `elastic`, `tomcat`, `pi`, `oracle`, `system`, `mysql`, and the password equals the account name, is a vendor default, is a wordlist-weak value, or is empty for `root`/`sa`.

**Severity:** Low | **CWE:** [CWE-1392](https://cwe.mitre.org/data/definitions/1392.html) | **Languages:** Python, JavaScript/TypeScript, Go, Java, PHP, Ruby, C#, Dockerfile, plus YAML, .env, .properties and XML config

## What Gets Flagged

```python
DATABASE_URL = "postgres://postgres:postgres@db:5432/app"
requests.get(url, auth=HTTPBasicAuth("admin", "admin"))
mysql.connector.connect(host="db", user="root", password="")
```

```php
$conn = mysqli_connect("localhost", "root", "root", "shop");
```

```yaml
RABBITMQ_DEFAULT_USER: guest
RABBITMQ_DEFAULT_PASS: guest
- MYSQL_ROOT_PASSWORD=root
```

```xml
<user name="admin" password="admin" />
```

```go
sql.Open("mysql", "root:root@tcp(mysql:3306)/inventory")
```

```csharp
const string Conn = "Server=sql01;Database=Shop;User Id=sa;Password=sa;";
```

Not flagged: a non-default account (`app`, `ops`) even with a default password, a strong password, environment or secret references, comparisons, text inside a longer string or a comment, test code and config templates. A default password on its own is VNX-1393; a weak one is VNX-1391.

## Remediation

1. Disable or rename the built-in account, or create a dedicated least-privilege account for the application.
2. Generate a unique password per deployment and inject it from a secrets manager.
3. Never leave `root` or `sa` with an empty password, even in development images that might be published.
