---
title: "VNX-755 – Interrupt or JVM error caught and swallowed"
description: "Reports Java catch blocks that drop an InterruptedException without restoring the interrupt, rethrowing or leaving the work, and catch blocks that handle a JVM Error (OutOfMemoryError, StackOverflowError, ...) without rethrowing or ending the process."
---

## Overview

VNX-755 maps to [CWE-755: Improper Handling of Exceptional Conditions](https://cwe.mitre.org/data/definitions/755.html). It reports two handlers that absorb conditions they should not:

- **`catch (InterruptedException e)`**, alone or in a multi-catch, when the body does none of these: call `Thread.currentThread().interrupt()`, `throw`, `return`, `break`. The thread loses the request to stop, so shutdown, timeouts and executor cancellation no longer work. A handler that is the last statement of a `run()`, `call()` or lambda body is not reported, because the thread ends right after it.
- **`catch` of a JVM `Error`**: `Error`, `VirtualMachineError`, `OutOfMemoryError`, `StackOverflowError`, `InternalError`, `ThreadDeath` or `LinkageError`, when the body does not rethrow.

**Severity:** Low | **CWE:** [CWE-755](https://cwe.mitre.org/data/definitions/755.html) | **Languages:** java

## What Gets Flagged

```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {   // FLAGGED: interrupt lost
    // keep polling
}

} catch (OutOfMemoryError oom) {     // FLAGGED: execution continues
    return new byte[0];
}
```

Not reported: handlers that restore the interrupt, rethrow, wrap, return or break. Also not reported: `catch (Throwable)` and `catch (Exception)`, which VNX-396 and VNX-391 cover, test code and comments.

## Remediation

1. In an `InterruptedException` handler, call `Thread.currentThread().interrupt()` or rethrow.
2. Let JVM errors propagate, or rethrow them once cleanup is done.
