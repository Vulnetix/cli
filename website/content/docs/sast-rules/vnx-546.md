## Overview

VNX-546 maps to [CWE-546: Suspicious Comment](https://cwe.mitre.org/data/definitions/546.html). A marker comment that says the code beside it is insecure is a record of a known, unfixed weakness. The rule reports a comment that starts with `TODO`, `FIXME`, `HACK`, `XXX` or `BUG` (also `TODO(name):` and `@todo`) and whose text names a security concern: authentication, authorization, permissions, privileges, passwords, credentials, secrets, CSRF, XSS, injection, sanitising, escaping, validation, encryption, plain text, SSL/TLS, certificates, overflow, unsafe, insecure, vulnerable, hard-coded values, rate limiting, access control or traversal. Whole-line, block-comment continuation and trailing comments are read.

**Severity:** Low | **CWE:** [CWE-546](https://cwe.mitre.org/data/definitions/546.html) | **Languages:** Python, JavaScript/TypeScript, Java, Go, C, C++

## What Gets Flagged

```go
// FIXME: escape the name before it goes into the HTML
return fmt.Sprintf("<h1>%s</h1>", name)
```

```c
strcpy(dst, src); // FIXME: possible buffer overflow, src is unchecked
```

## What Is Not Flagged

- Ordinary TODOs (refactoring, performance, naming) and security prose without a marker.
- Markers inside string literals and URLs, identifiers containing the word (`TODO_AUTH`, `todoSecurity`) and `XXXXXX` placeholders.
- Test files.
- In Go, Java, JavaScript/TypeScript and Python, a marker that admits a missing, disabled or broken control (`// FIXME: no authorization check here`, `// HACK: skip TLS verification`, `// TODO: verify the webhook signature`, `// XXX insecure`) is reported by VNX-635, so the same comment is not reported twice.

## Remediation

Fix the weakness the comment describes. If it cannot be fixed now, track it in the issue tracker with an owner and a date rather than leaving the admission in the source.
