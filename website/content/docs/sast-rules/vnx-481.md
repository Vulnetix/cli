---
title: "VNX-481 – Assigning instead of Comparing"
description: "Detects an if or while condition that is a bare assignment, if (x = y), in C, C++ and Java, where a comparison (==) was meant. The deliberate double-parenthesis form is not reported."
---

## Overview

VNX-481 maps to [CWE-481: Assigning instead of Comparing](https://cwe.mitre.org/data/definitions/481.html). `if (uid = 0)` overwrites `uid` and tests the assigned value, so the branch is never taken and the variable now holds the wrong value; `if (isAdmin = true)` makes every user an admin. The rule reports an `if` or `while` whose condition starts with `lvalue = expression` (including `*p = ...`, `s->field = ...`, `a[i] = ...`).

Not reported: the conventional deliberate form with an extra pair of parentheses (`if ((p = next()))`, `while ((c = getc(f)) != EOF)`), comparisons (`==`, `<=`, `>=`, `!=`), the comma operator (`while (p = q, q = next(q), p)`), the C++17 init-statement (`if (err = f(); err != 0)`), assignments in `for` headers and ordinary statements, and conditions in strings and comments.

**Severity:** Medium | **CWE:** [CWE-481](https://cwe.mitre.org/data/definitions/481.html) | **Languages:** C, C++, Java

## What Gets Flagged

```c
if (uid = 0) {               /* FLAGGED */
while (n->state = 1) {       /* FLAGGED */
```

```java
if (isAdmin = true) {        // FLAGGED
```

## What Is Not Flagged

```c
while ((c = getc(in)) != EOF)
if ((p = malloc(16)))
if (a == b)
```

## Remediation

1. Use `==` for comparison.
2. When the assignment is intended, move it to its own statement or wrap it in a second pair of parentheses and compare explicitly: `if ((p = next()) != NULL)`.
3. Compile C/C++ with `-Wparentheses` (part of `-Wall`).
