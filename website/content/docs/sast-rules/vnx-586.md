## Overview

VNX-586 maps to [CWE-586: Explicit Call to Finalize()](https://cwe.mitre.org/data/definitions/586.html). It reports `x.finalize()`, `this.finalize()`, `getX().finalize()`, a `.finalize()` that continues a call chain on the next line, and a bare `finalize();` statement.

**Severity:** Low | **CWE:** [CWE-586](https://cwe.mitre.org/data/definitions/586.html) | **Languages:** java

## Why This Matters

The garbage collector runs a finalizer once, when the object is unreachable. Calling it directly runs the cleanup while the object is still referenced, so later use works on released resources, and the collector may run it a second time.

## What Gets Flagged

```java
resource.finalize();
this.finalize();
r.finalize ( );
```

Not flagged: `super.finalize()` inside an overriding `finalize()`, the `protected void finalize()` declaration, `builder.finalize(ctx)`, `builder.finalizeBuild()`, `System.runFinalization()`, comments, strings and test files.

## Remediation

1. Give the class an explicit `close()` method (implement `AutoCloseable`) and call that instead.
2. Use try-with-resources or `java.lang.ref.Cleaner` for native resources.
