## Overview

VNX-1204 maps to [CWE-1204: Generation of Weak Initialization Vector (IV)](https://cwe.mitre.org/data/definitions/1204.html). Reports Java code that builds a cipher IV or nonce (IvParameterSpec, GCMParameterSpec, ChaCha20ParameterSpec) from bytes that are not freshly random: a zero-filled new byte[N] passed straight to the spec; a byte[] allocated with new byte[N] and handed to the spec within the next 40 lines without anything filling it (no nextBytes, read, readFully, ByteBuffer.get, System.arraycopy, element assignment or other call that takes the array); a byte[] initialised from a literal ({...}, new byte[]{...}, "...".getBytes()) that the file uses as an IV; a string literal's bytes passed to the spec; and an IV filled by java.util.Random or ThreadLocalRandom.nextBytes. A zero, constant or predictable IV repeats across messages, which leaks plaintext equality under CBC and breaks confidentiality and authentication under CTR and GCM. Not reported: IVs filled by SecureRandom, IVs read from the message being decrypted, cipher.getIV(), byte arrays never used as an IV, strings and comments. Overlaps VNX-JAVA-020 (static IV), VNX-329 (predictable IV) and VNX-CRYPTO-010 (hard-coded IV).

**Severity:** Medium | **CWE:** [CWE-1204](https://cwe.mitre.org/data/definitions/1204.html) | **Languages:** java

## What Gets Flagged

```java
c.init(Cipher.ENCRYPT_MODE, key, new IvParameterSpec(new byte[16]));  // FLAGGED

byte[] iv = new byte[16];                    // FLAGGED: never filled
cipher.init(Cipher.ENCRYPT_MODE, k, new IvParameterSpec(iv));

private static final byte[] IV_BYTES = { 0x00, 0x01, /* ... */ };  // FLAGGED

rnd.nextBytes(iv);                           // FLAGGED when rnd is java.util.Random

new SecureRandom().nextBytes(iv);            // not flagged
```
