## Overview

VNX-1341 maps to [CWE-1341: Multiple Releases of Same Resource or Handle](https://cwe.mitre.org/data/definitions/1341.html). Releasing the same memory, file, descriptor or library handle twice corrupts allocator state (double free), or closes a descriptor number that another thread has since reused.

**Severity:** Medium | **CWE:** [CWE-1341](https://cwe.mitre.org/data/definitions/1341.html) | **Languages:** c, cpp

## Why This Matters

A double free is a classic memory-corruption primitive: an attacker who controls the allocations between the two frees can often turn it into arbitrary write and code execution. A double `close()` can close an unrelated file or socket opened in between.

## What Gets Flagged

```c
if (fread(buf, 1, 4096, f) == 0) {
    free(buf);                 // FLAGGED: then goto out, which frees buf again
    goto out;
}
...
out:
    free(buf);
```

```c
if (expired) {
    free(s->token);
}
free(s->token);                // FLAGGED: second release when expired
```

```cpp
delete entry_;
...
delete entry_;                 // FLAGGED
```

Release functions covered: `free`, `fclose`, `close`, `closedir`, `pclose`, `closesocket`, `CloseHandle`, `kfree`, `vfree`, `g_free`, `munmap`, `delete`/`delete[]`, and library releasers named `*_free`, `*_destroy`, `*_close`, `*_cleanup` (`EVP_CIPHER_CTX_free`, `sqlite3_close`, `curl_easy_cleanup`).

## What Is Not Flagged

- A release followed by `x = NULL`, `fd = -1` or a new assignment (on the same line or after), or `&x` passed to another function.
- Releases in exclusive branches (`if`/`else`, `switch` cases, `#if`/`#else`).
- An early release whose block returns, breaks or jumps to a label that does not release it again.
- Loops releasing a different element each pass, releases in different functions, reference-count drops (`*_unref`, `*_release`) and comments.
- Paths through other functions and aliases (`q = p; free(p); free(q);`) are not followed.

## Remediation

1. Release each resource in exactly one place, typically the cleanup label.
2. Set pointers to `NULL` and descriptors to `-1` immediately after releasing them, and guard the cleanup with `if (p)` / `if (fd != -1)`.
