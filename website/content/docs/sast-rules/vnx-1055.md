## Overview

VNX-1055 maps to [CWE-1055: Multiple Inheritance from Concrete Classes](https://cwe.mitre.org/data/definitions/1055.html). It reports a Python class whose bases include two or more concrete classes defined in the same file. A base is concrete when its body defines a method or assigns an attribute and it is not abstract. The class header may span several lines.

A base counts as abstract, and is ignored, when its name ends in `Mixin`, `Base`, `ABC`, `Interface` or `Protocol` (or starts with `Abstract`), it derives from `ABC`, `ABCMeta`, `Protocol` or a mixin, or its body uses `@abstractmethod` or raises `NotImplementedError`.

**Severity:** Low | **CWE:** [CWE-1055](https://cwe.mitre.org/data/definitions/1055.html) | **Languages:** python

## Why This Matters

When two concrete bases both carry state and behaviour, the method resolution order decides whose `__init__`, attributes and overrides win. A reordering of the base list, or a new method in either base, silently changes the subclass, and security-relevant behaviour such as validation or authorisation can be skipped.

Not reported: one concrete base combined with mixins or ABCs, bases imported from other modules (the rule cannot see whether they are concrete), empty marker classes such as exception tag hierarchies (`class ConnectTimeout(ConnectionFailed, TimedOut)` whose bases only `pass`), `Generic[...]` and `metaclass=` arguments, test files and comments.

## What Gets Flagged

```python
class FileStore:
    def __init__(self, path):
        self.path = path

class SqlStore:
    def __init__(self, dsn):
        self.conn = sqlite3.connect(dsn)

class HybridStore(FileStore, SqlStore):
    ...
```

Not flagged:

```python
class ReportView(BaseView, JsonMixin, Renderer):
    ...
```

## Remediation

1. Prefer composition: hold an instance of the second class instead of inheriting from it.
2. Keep one concrete base and turn the others into stateless mixins or abstract interfaces.
