---
title: "VNX-754 – Class resource used without checking for null"
description: "Reports Java getResourceAsStream()/getResource() results, which are null when the resource is missing, that are dereferenced or handed to a consumer such as Properties.load() before any null check."
---

## Overview

VNX-754 maps to [CWE-754: Improper Check for Unusual or Exceptional Conditions](https://cwe.mitre.org/data/definitions/754.html). When a resource is missing, `getResourceAsStream()` on a Class, ClassLoader or ServletContext returns `null` instead of throwing. `Class`/`ClassLoader.getResource()` does the same. The rule reports the result when it is:

- dereferenced in the same expression
- passed straight to a consumer that dereferences it: `Properties.load`, `new InputStreamReader(...)`, `IOUtils.toString`, `FileCopyUtils.copyToByteArray`, a parser, and so on. The consumer can also open on the line above.
- assigned to a variable that the next 15 lines use before any null check

**Severity:** Low | **CWE:** [CWE-754](https://cwe.mitre.org/data/definitions/754.html) | **Languages:** java

## What Gets Flagged

```java
return Banner.class.getResourceAsStream("/banner.txt").readAllBytes();   // FLAGGED
props.load(Settings.class.getClassLoader().getResourceAsStream("app.properties")); // FLAGGED
InputStream in = Keystore.class.getResourceAsStream("/server.p12");      // FLAGGED
ks.load(in, pass);
```

Not reported:

- results checked with `== null`, `!= null`, `Objects.requireNonNull`, `Optional.ofNullable` or `checkNotNull` before use
- Spring `ResourceLoader.getResource()`, which never returns null
- test code and comments

## Remediation

Check the result before using it, and fail with a message that names the missing resource:

```java
InputStream in = Objects.requireNonNull(
    getClass().getResourceAsStream("/app.properties"), "app.properties missing from classpath");
```
