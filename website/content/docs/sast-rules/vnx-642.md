title: "VNX-642 – Authorization state kept in a client-controlled cookie"
description: "Reports a plain (unsigned) cookie whose name is a privilege flag or role, such as isAdmin, role or access_level, being set or read back in JavaScript/TypeScript, Python, Java or Kotlin. Signed cookies and server-side sessions are not reported."
---

## Overview

VNX-642 maps to [CWE-642: External Control of Critical State Data](https://cwe.mitre.org/data/definitions/642.html). It reports a cookie whose whole name is an authorization flag or role (`admin`, `isAdmin`, `is_admin`, `role`, `user_role`, `permissions`, `access_level`, `isLoggedIn` and similar) when the cookie is set or read without a signature.

**Severity:** Medium | **CWE:** [CWE-642](https://cwe.mitre.org/data/definitions/642.html) | **Languages:** java, node, python

## Why This Matters

A plain cookie is client state. Anyone can open the browser's developer tools and change `isAdmin=0` to `isAdmin=1`. If the server reads that value back to decide what the user may do, the user decides their own privilege.

## What Gets Flagged

```javascript
res.cookie('role', user.role, { httpOnly: true });      // set, unsigned
const { isAdmin } = req.cookies;                        // read back
```

```python
resp.set_cookie("is_admin", "1" if user.admin else "0")
admin_flag = request.COOKIES.get('admin')
```

```java
Cookie roleCookie = new Cookie("role", acct.getRole());
if (c.getName().equals("isAdmin") && "true".equals(c.getValue())) {
public ResponseEntity<String> reports(@CookieValue("role") String role) {
```

A read that is itself the decision, compared or tested on its line (`if (req.cookies.isAdmin === 'true')`, `if request.COOKIES.get('admin') == "1":`) or assigned to a variable that a condition uses within 15 lines, is reported by [VNX-784](../vnx-784/) (a security decision on a cookie), so VNX-642 does not report that line again. Writes, and reads that decide nothing on the spot, stay with VNX-642.

Not flagged: `res.cookie(..., { signed: true })`, `req.signedCookies`, Django `set_signed_cookie`/`get_signed_cookie`, Flask `session[...]`, and cookies with other names (`session`, `auth_token`, `theme`, `admin_theme`).

## Remediation

1. Keep roles and privilege flags in the server-side session, keyed by an opaque session id.
2. If the value must travel in a cookie, sign it (`cookie-parser` with a secret and `signed: true`, Django `set_signed_cookie`) and still re-check it against the user record.
3. Never authorise from a value the client can write.
