title: "VNX-268 – Privilege Chaining"
description: "The program runs sudo, doas or pkexec with a command line that includes a runtime value, chaining whatever controls that value to the root rights of the program's account."
---

## Overview

VNX-268 maps to [CWE-268: Privilege Chaining](https://cwe.mitre.org/data/definitions/268.html). An application account that may run commands through `sudo`, `doas` or `pkexec` holds two privileges: its own, and a route to root. This rule reports code that joins them with a value decided at run time, so whoever influences that value also chooses what root runs.

**Severity:** Low | **CWE:** [CWE-268](https://cwe.mitre.org/data/definitions/268.html) | **Languages:** c, cpp, python

## Why This Matters

A sudoers entry such as `app ALL=(root) NOPASSWD: /usr/bin/systemctl restart *` looks narrow. Combined with code that fills in the service name from a request, a job parameter or a file, it becomes "run this root command with an argument I pick", and an argument can be an option (`--now`, `-o`), a path or a second command. Each privilege is reasonable alone; chained, they hand out root.

## What Gets Flagged

```python
subprocess.run(["sudo", "systemctl", "restart", service], check=True)
os.system(f"sudo rm -rf {path}")
subprocess.call("sudo chown " + user + " " + path, shell=True)

cmd = f"sudo useradd -m {name}"
subprocess.run(cmd, shell=True, check=True)
```

```c
snprintf(cmd, sizeof(cmd), "sudo /usr/sbin/useradd -m %s", name);
return system(cmd);

execlp("sudo", "sudo", "-n", script.c_str(), (char *)NULL);
execvp("pkexec", argv);
```

Not flagged: a fully constant privileged command (`sudo systemctl reload nginx`, `sudo -n true`), a value checked against an allow-list just above the call (`if service not in ALLOWED_SERVICES: raise`), commands that do not use sudo, doas or pkexec, `sudo` in messages and help strings, and calls in comments. Whether the sudoers or polkit rule itself is too broad lives outside the code and is not judged.

## Remediation

1. Run a fixed privileged command, and choose any variable part from an allow-list in code (`if service not in {"nginx", "cron"}: raise`).
2. Pass arguments as a list, never through a shell, and end options with `--` so a value cannot become a flag.
3. Better, move the privileged action into a dedicated helper or service with a narrow, validated interface, and drop the application's sudo rights.
