title: "VNX-772 – Missing Release of Resource after Effective Lifetime"
description: "Reports Java methods that acquire a socket, file stream, JDBC connection or Files stream into a local variable outside try-with-resources and never close, return or hand it off, and file streams created inline for a consumer that does not close them."
---

## Overview

VNX-772 maps to [CWE-772: Missing Release of Resource after Effective Lifetime](https://cwe.mitre.org/data/definitions/772.html). It reports a Java method that acquires an operating-system resource into a local variable and never releases it:

- `Socket`, `DatagramSocket`, `ServerSocket`, `FileInputStream`, `FileOutputStream`, `FileReader`, `FileWriter`, `RandomAccessFile`, `ZipFile`, `JarFile`;
- a reader, writer, `Scanner` or object stream constructed directly around a new file stream;
- a JDBC `Connection` from `DriverManager` or a `DataSource`;
- a stream from `Files.lines`, `list`, `walk`, `find`, `newInputStream`, `newOutputStream`, `newBufferedReader`, `newBufferedWriter`.

It is reported when the declaration is not in a try-with-resources header and the rest of the method has no `close()` of the variable, no close helper call with it, no `return` of it, no assignment of it elsewhere and no hand-off as a call argument. A file stream created inline and passed straight to a consumer that does not close it (`props.load(new FileInputStream(p))`, `new Scanner(new File(p)).next()`) is reported too.

Not reported: try-with-resources (single- or multi-line headers), close in `finally`, resources returned to the caller, stored in a field or handed to another object, a `ServerSocket` serving an `accept()` loop, in-memory streams (`ByteArrayInputStream`, `StringReader`, `Scanner(System.in)`), comments, string literals and test sources.

**Severity:** Low | **CWE:** [CWE-772](https://cwe.mitre.org/data/definitions/772.html) | **Languages:** java

## Why This Matters

A leaked descriptor or connection stays open until the garbage collector finalises it, if it ever does. Under load the process runs out of file descriptors or the pool runs out of connections, and every later request fails.

## What Gets Flagged

```java
Socket socket = new Socket(host, port);                 // flagged
BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()));
return in.readLine();

props.load(new FileInputStream(path));                  // flagged
```

Not flagged:

```java
try (FileInputStream in = new FileInputStream(path)) {
    return in.readAllBytes();
}
```

## Remediation

Declare the resource in a try-with-resources header. Where ownership leaves the method, return it or hand it to the object that will close it.
