title: "VNX-1004 – Sensitive cookie set without the HttpOnly flag"
description: "Reports session, authentication and identity cookies set without HttpOnly in Go, Node.js, PHP, Python and Java, and framework settings that turn the session cookie's HttpOnly flag off."
---

## Overview

VNX-1004 maps to [CWE-1004: Sensitive Cookie Without 'HttpOnly' Flag](https://cwe.mitre.org/data/definitions/1004.html). It reports a cookie whose name says it carries a session, authentication or identity value (`session`, `sid`, `auth`, `token`, `jwt`, `access`/`refresh`, `remember`, `login`, `userid`, `admin`, `role`, ...; a constant naming the cookie is resolved within the file) when it is set without HttpOnly:

- **Go:** `http.Cookie{...}` literals without `HttpOnly: true` (and no later `.HttpOnly = true`); `HttpOnly: false` in a session store's `Options`.
- **Node.js:** Express `res.cookie(...)` and Fastify `reply.setCookie(...)` without `httpOnly: true`; `httpOnly: false` in session or cookie options; a session token written to `document.cookie`.
- **PHP:** `setcookie()`/`setrawcookie()` without the httponly argument or with it false; `ini_set('session.cookie_httponly', 0)`; `session_set_cookie_params` with httponly false.
- **Python:** `set_cookie(...)` (Flask, Django, Starlette) without `httponly=True`; `SESSION_COOKIE_HTTPONLY = False`.
- **Java:** `new Cookie(...)` with no `setHttpOnly(true)` on it in the following lines; `ResponseCookie.from(...)` builders without `.httpOnly(true)`; `server.servlet.session.cookie.http-only=false`.

Not reported: cookies with other names (preferences and lookalikes such as `author_view` or `accessibility_mode`, CSRF/XSRF tokens, which double-submit schemes must let scripts read), cookies being deleted, wrappers that take HttpOnly as a parameter, Koa `ctx.cookies.set` (HttpOnly by default), test files and comments.

**Severity:** Medium | **CWE:** [CWE-1004](https://cwe.mitre.org/data/definitions/1004.html) | **Languages:** Go, Node.js, PHP, Python, Java

## Why This Matters

A cookie without HttpOnly is readable through `document.cookie`, so a single cross-site scripting flaw anywhere on the origin hands the attacker the victim's session. Express, Flask, Django, Starlette and PHP's `setcookie` all default to readable cookies.

## What Gets Flagged

```javascript
res.cookie('token', token);
```

```python
resp.set_cookie("session_id", token)
SESSION_COOKIE_HTTPONLY = False
```

```php
setcookie('session_token', $token);
ini_set('session.cookie_httponly', 0);
```

```go
http.SetCookie(w, &http.Cookie{Name: "auth_token", Value: token, Path: "/"})
```

```java
Cookie cookie = new Cookie("access_token", token);
response.addCookie(cookie);
```

## Remediation

1. Set HttpOnly on every cookie that carries a session or credential: `{ httpOnly: true }`, `httponly=True`, `HttpOnly: true`, `cookie.setHttpOnly(true)`, or the seventh `setcookie` argument / `'httponly' => true`.
2. Remove overrides that turn the framework session cookie's HttpOnly off.
3. Set Secure and SameSite on the same cookies.
