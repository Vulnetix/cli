## Overview

VNX-646 maps to [CWE-646: Reliance on File Name or Extension of Externally-Supplied File](https://cwe.mitre.org/data/definitions/646.html). It reports a condition, return or membership test that looks at the extension of an uploaded file's client-supplied name (`originalname`, `originalFilename`, `req.files.x.name`, `.filename`), directly or through a variable derived from it, when nothing in the same file checks the file's content.

**Severity:** Medium | **CWE:** [CWE-646](https://cwe.mitre.org/data/definitions/646.html) | **Languages:** node, python

## Why This Matters

The client picks the file name. `shell.php.jpg`, an executable renamed to `invoice.pdf` or an HTML page called `avatar.png` passes an extension check. If the server then stores, serves or parses the file according to that name, the attacker chooses how it is treated.

## What Gets Flagged

```javascript
if (!/\.(jpe?g|png|gif)$/i.test(file.originalname)) { return cb(new Error('images only')); }

const ext = path.extname(req.file.originalname).toLowerCase();
if (!['.png', '.jpg'].includes(ext)) { ... }
```

```python
return "." in filename and filename.rsplit(".", 1)[1].lower() in ALLOWED_EXTENSIONS

validators=[FileExtensionValidator(allowed_extensions=["pdf", "docx"])]
```

Not flagged: the same checks in a file that also sniffs the content (`fileTypeFromBuffer`, `magic.from_buffer`, `Image.open(...).verify()`), building a storage name such as `Date.now() + path.extname(file.originalname)`, and extension checks on paths that are not uploads.

## Remediation

1. Determine the type from the content: magic bytes (`file-type`, `python-magic`) or a decoder that rejects anything else (Pillow `verify()`).
2. Store uploads under a server-generated name and serve them with a server-chosen `Content-Type` and `Content-Disposition: attachment`.
3. Keep extension allow-lists as a usability check, never as the security check.
