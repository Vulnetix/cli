---
title: "VNX-682 – Incorrect Calculation"
description: "Detects calculations that are wrong for every input: integer division or remainder by a literal zero in C, C++ and Java, and Java Math.abs() of a hash or unbounded random value, which can stay negative."
---

## Overview

VNX-682 maps to [CWE-682: Incorrect Calculation](https://cwe.mitre.org/data/definitions/682.html). Most incorrect calculations depend on intent, which a line-oriented rule cannot know. This rule reports the two shapes that are wrong whatever the input.

**Severity:** Low | **CWE:** [CWE-682](https://cwe.mitre.org/data/definitions/682.html) | **Languages:** C, C++, Java

## What Gets Flagged

```c
return hits / 0;        // FLAGGED: undefined behaviour in C
int rem = hits % 0;     // FLAGGED
x /= 0;                 // FLAGGED
```

```java
long bucket = sum % 0L;                              // FLAGGED: ArithmeticException
return Math.abs(key.hashCode()) % shards;            // FLAGGED: negative for Integer.MIN_VALUE
int idx = Math.abs(random.nextInt()) % items.length; // FLAGGED
```

## What Is Not Flagged

- Floating-point division by `0.0`, hexadecimal or non-zero divisors, and division by a variable (VNX-369 reports unchecked external divisors).
- `Math.floorMod(h, n)`, a masked hash (`h & 0x7fffffff`) and `Math.abs(r.nextInt(n))`.
- Test code, where dividing by zero is how an exception is provoked.
- Comments and string literals.

## Remediation

Fix the divisor, and compute a bucket with `Math.floorMod(key.hashCode(), n)` or `(key.hashCode() & 0x7fffffff) % n`.
