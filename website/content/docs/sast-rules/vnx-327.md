description: "Detects calls that compute MD5 or SHA-1 digests in Java, Node.js, PHP, Python and Ruby. Matches the API call, not the word: a field named SHA1, a JSON tag or an algorithm-name list is not a use."
---

## Overview

VNX-327 maps to [CWE-327: Use of a Broken or Risky Cryptographic Algorithm](https://cwe.mitre.org/data/definitions/327.html). It reports a call into the MD5 or SHA-1 digest, because both are broken for collision resistance and must not protect integrity, authenticity or passwords.

**Severity:** High | **CWE:** [CWE-327](https://cwe.mitre.org/data/definitions/327.html) | **Languages:** java, node, php, python, ruby

## What Gets Flagged

```python
# FLAGGED: hashlib.md5 / hashlib.sha1
digest = hashlib.md5(data).hexdigest()
```

```javascript
// FLAGGED: createHash('md5' | 'sha1')
const h = crypto.createHash('sha1').update(x).digest('hex');
```

```java
// FLAGGED: MessageDigest.getInstance("MD5" | "SHA-1")
MessageDigest md = MessageDigest.getInstance("MD5");
```

```php
// FLAGGED: md5() / sha1() / md5_file() / sha1_file()
$h = md5($password);
```

```ruby
# FLAGGED: Digest::MD5 / Digest::SHA1
Digest::MD5.hexdigest(data)
```

## What Is Not Flagged

The rule matches the call, so these are not reported:

- A struct field, constant, JSON tag or class called `MD5`, `SHA1` or `SHA1Hasher`, and lists of algorithm names.
- HMAC over SHA-1 (`hmac.new(key, msg, hashlib.sha1)`), which does not depend on collision resistance.
- Comments, and test files.

Go is covered by the dedicated [VNX-CRYPTO-001](vnx-crypto-001) and [VNX-CRYPTO-002](vnx-crypto-002) rules, which recognise `md5.New`/`md5.Sum` and `sha1.New`/`sha1.Sum`.

## Remediation

1. Use SHA-256 or stronger for integrity and fingerprints.
2. Use a password hash (argon2id, bcrypt, scrypt) for credentials, never a plain digest.
3. If the digest is a non-security identifier (a cache key, a content address that is verified another way), suppress that line with `# vulnetix-ignore: VNX-327` and say why.
