## Overview

VNX-763 maps to [CWE-763: Release of Invalid Pointer or Reference](https://cwe.mitre.org/data/definitions/763.html). It reports `free(&x)` for a plain variable, `free(arr)` and `delete[] arr` where `arr` is declared as an array in the same function or at file scope, `free("literal")`, and C++ `delete &x`.

It does not report pointers from an allocator, `&p[0]`, array parameters (which are pointers), struct members, wrapper functions such as `sdsfree`, or an array of the same name in another function. Offset pointers are VNX-761, mismatched allocators VNX-762 and double frees VNX-415.

**Severity:** Low | **CWE:** [CWE-763](https://cwe.mitre.org/data/definitions/763.html) | **Languages:** c, cpp

## Why This Matters

The allocator trusts that whatever it is given has a chunk header it wrote. A stack or static address has none, so the release corrupts the allocator's free lists, which is a classic route to code execution.

## What Gets Flagged

```c
struct config cfg;
free(&cfg);          // flagged

char path[4096];
free(path);          // flagged

free("default");     // flagged
```

## Remediation

1. Release only memory obtained from the matching allocator.
2. Let stack and static objects go out of scope; do not free them.
