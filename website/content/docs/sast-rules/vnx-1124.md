## Overview

VNX-1124 maps to [CWE-1124: Excessively Deep Nesting](https://cwe.mitre.org/data/definitions/1124.html). It reports a Python control-flow statement (`if`, `elif`, `else`, `for`, `while`, `try`, `except`, `finally`, `with`, `match`, `case`) nested inside **five or more** enclosing control blocks of the same function.

Depth is measured by indentation from the enclosing `def`, using that function's own indent step (4 spaces, 2 spaces or a tab), so it is the same whether the function is top level or a method. Each function is reported once, on the first statement that reaches the depth.

Not reported: nesting of four blocks or fewer; depth that comes from a nested `def` (the inner function is measured from its own `def`); continuation lines inside brackets (comprehension `if` clauses, wrapped arguments); comments, docstrings and test files.

**Severity:** Low | **CWE:** [CWE-1124](https://cwe.mitre.org/data/definitions/1124.html) | **Languages:** python

## Why This Matters

At six levels a reader can no longer see which conditions guard a statement. An authorisation check, an error branch or an `else` placed one level off is easy to misread, and the mistake survives review because nobody can hold the whole condition stack in mind.

## What Gets Flagged

```python
def sync(accounts, ledger):
    for acct in accounts:
        if acct.active:
            for entry in ledger.entries(acct):
                if entry.pending:
                    with ledger.lock(entry):
                        if entry.amount > acct.limit:   # FLAGGED: inside 5 blocks
                            entry.reject()
```

## Remediation

1. Return or `continue` early on guard conditions (`if not acct.active: continue`) instead of nesting the rest of the body.
2. Extract the inner loop body into a named function.
3. Replace nested lookups with a precomputed index or a generator that yields the filtered items.
