## Overview

VNX-1265 maps to [CWE-1265: Unintended Reentrant Invocation of Non-reentrant Code Via Nested Calls](https://cwe.mitre.org/data/definitions/1265.html).

**Severity:** Medium | **CWE:** [CWE-1265](https://cwe.mitre.org/data/definitions/1265.html) | **Languages:** c

## Why This Matters

`strtok()` stores its position in hidden static state. When a loop that is tokenizing one string calls `strtok()` on another string, directly or through a helper, the inner call replaces that state. The outer loop's next `strtok(NULL, ...)` then continues through the wrong buffer or stops early, so input is skipped or misparsed.

## What Gets Flagged

```c
char *item = strtok(line, ";");
while (item != NULL) {
    parse_pair(item, &key, &value);   /* parse_pair() calls strtok(pair, "=") */
    item = strtok(NULL, ";");
}

for (row = strtok(text, "\n"); row; row = strtok(NULL, "\n")) {
    cell = strtok(row, ",");          /* nested tokenization */
}
```

Not flagged: `strtok_r()`, a second tokenization that starts after the first loop has ended, helpers that do not call `strtok()`.

## Remediation

1. Use `strtok_r()` (POSIX) or `strtok_s()` with a separate save pointer for each tokenization.
2. Signal handlers that call non-reentrant functions are reported separately by VNX-479 and VNX-828.
