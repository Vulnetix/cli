## Overview

VNX-554 maps to [CWE-554: ASP.NET Misconfiguration: Not Using Input Validation Framework](https://cwe.mitre.org/data/definitions/554.html). It reports the settings that turn off ASP.NET request validation, the framework's built-in rejection of markup and script in request input.

**Severity:** Medium | **CWE:** [CWE-554](https://cwe.mitre.org/data/definitions/554.html) | **Languages:** csharp (.aspx, .master, .config, .cs, .vb)

## Why This Matters

Request validation is a coarse filter, but it stops the plain `<script>` payloads that reach pages which forget to encode their output. Turning it off for a page, a controller or the whole site removes that net everywhere it applied, usually to let one rich-text field through.

## What Gets Flagged

```aspx
<%@ Page Language="C#" ValidateRequest="false" CodeBehind="Comment.aspx.cs" Inherits="Site.Comment" %>
```

```xml
<httpRuntime targetFramework="4.8" requestValidationMode="2.0" />
<pages validateRequest="false" />
```

```csharp
[HttpPost]
[ValidateInput(false)]
public ActionResult Create(string title, string body) { ... }
```

Not flagged: validation left on or set to `true`, `requestValidationMode` 4.0 or 4.5, the field-level opt-outs `[AllowHtml]` and `Request.Unvalidated`, ASP.NET Core (it has no request validation), XML and `<%-- --%>` comments, C# comments and string literals.

## Remediation

1. Remove `ValidateRequest="false"`, `validateRequest="false"`, `requestValidationMode="2.0"` and `[ValidateInput(false)]`.
2. Where one field must accept markup, allow it on that field only with `[AllowHtml]` and sanitise it with an HTML sanitiser.
3. Encode all output (`<%: %>`, `@` in Razor, `HttpUtility.HtmlEncode`); request validation does not replace it.
