title: "VNX-651 – Exposure of WSDL File Containing Sensitive Information"
description: "Reports a WSDL or XSD that publishes a credential value, a credentialed endpoint address or a debug/internal operation, and JAX-WS, spyne and WCF service methods with such names that end up in the generated WSDL."
---

## Overview

VNX-651 maps to [CWE-651: Exposure of WSDL File Containing Sensitive Information](https://cwe.mitre.org/data/definitions/651.html). A WSDL is handed to every client that asks for `?wsdl`. The rule reports what it should not contain:

- In `.wsdl` and `.xsd` files: an element or attribute whose name ends in a credential word (`adminPassword`, `client_secret`, `apiKey`, `token`, `privateKey`) with a non-empty `default=` or `fixed=` value that is not a number, a boolean or `Bearer`, and a `soap:address`/`soap12:address`/`http:address` `location` with `user:password@` in it.
- An operation named like a back door: `debug*`, `internal*`, `dump*`, `backdoor*`, `hidden*`, `exec`/`execute`/`run` + `Command`/`Shell`/`Sql`/`Script`/`Query`, and `get*Password`/`Secret`/`PrivateKey`/`Credentials`.
- The same names on code that generates the WSDL: a Java `@WebMethod`, a Python spyne `@rpc`/`@srpc`, a C# WCF `[OperationContract]`.

Not reported: ordinary operations (`changePassword`, `getPasswordPolicy`, `testConnection`, `executeOrder`), credential elements without a value, settings that only describe a credential (`tokenType`, `passwordMinLength`), https or credential-free addresses, `@WebMethod(exclude = true)`, methods without the service annotation, comments and string literals.

**Severity:** Medium | **CWE:** [CWE-651](https://cwe.mitre.org/data/definitions/651.html) | **Languages:** java, python, csharp (and the `.wsdl`/`.xsd` files beside them)

## Why This Matters

A WSDL is a map of the service. An operation left in it for debugging tells an attacker exactly which call dumps sessions or runs SQL, and a default password in the schema is a password published to anyone.

## What Gets Flagged

```xml
<!-- FLAGGED -->
<xs:element name="adminPassword" type="xs:string" default="Winter2024!"/>
<soap:address location="http://svc_admin:S3cretPass@10.0.4.12:8080/account"/>
<operation name="debugDumpSessions">
```

```java
@WebMethod
public String internalResetCache(String region) {   // FLAGGED
```

```python
@rpc(_returns=Unicode)
def dump_all_tokens(ctx):                            # FLAGGED
```

## Remediation

1. Remove debug and internal operations from the published contract (`@WebMethod(exclude = true)`, a separate internal endpoint) or protect them with authentication.
2. Never put credential values in a schema `default`/`fixed` or an endpoint address.
3. Restrict who can fetch the WSDL in production when the service is not public.
