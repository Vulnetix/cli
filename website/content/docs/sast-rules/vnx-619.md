---
title: "VNX-619 – Dangling Database Cursor ('Cursor Injection')"
description: "Reports a Python DB-API cursor opened in a function and never closed, used as a context manager, returned, or released with its connection."
---

## Overview

VNX-619 maps to [CWE-619: Dangling Database Cursor ('Cursor Injection')](https://cwe.mitre.org/data/definitions/619.html). A cursor left open keeps its result set and server-side resources (a named PostgreSQL cursor, a MySQL unbuffered result) until garbage collection, and a pooled connection goes to the next request with it still attached.

**Severity:** Low | **CWE:** [CWE-619](https://cwe.mitre.org/data/definitions/619.html) | **Languages:** Python

## What Gets Flagged

```python
def find_user(db_path, user_id):
    conn = sqlite3.connect(db_path)
    cur = conn.cursor()          # flagged: never closed
    cur.execute("SELECT name FROM users WHERE id = ?", (user_id,))
    return cur.fetchone()

def report(request):
    cursor = connection.cursor() # flagged (Django)
    cursor.execute("SELECT id FROM shop_order")
    return JsonResponse({"rows": cursor.fetchall()})
```

Not flagged: `with conn.cursor() as cur:`, `with closing(cur):`, `cur.close()` later in the function or in a `finally` block, a closed connection, a cursor returned or yielded to the caller, a cursor stored on `self`, module-level scripts, comments and string literals.

## Remediation

Open cursors in a `with` block, or close them in `finally`:

```python
with conn.cursor() as cur:
    cur.execute("SELECT name FROM users WHERE id = %s", (user_id,))
    return cur.fetchone()
```
