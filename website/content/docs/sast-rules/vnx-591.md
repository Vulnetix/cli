---
title: "VNX-591 – Password read into a char[] copied into an immutable String"
description: "Reports Java code that copies a password returned as char[] (Console.readPassword, JPasswordField/PasswordCallback/KeyStore.PasswordProtection getPassword) into an immutable String, or reads JPasswordField.getText(), so the secret can no longer be wiped from memory."
---

## Overview

VNX-591 maps to [CWE-591: Sensitive Data Storage in Improperly Locked Memory](https://cwe.mitre.org/data/definitions/591.html). Java cannot lock memory against paging or core and heap dumps. The one control the platform offers for a password is to keep it in a `char[]` and overwrite the array once it has been used. The JDK's password APIs return `char[]` for exactly this reason.

The rule reports the line that throws that control away: `new String(...)`, `String.valueOf(...)` or `String.copyValueOf(...)` applied to `Console.readPassword()`, to `getPassword()` of `JPasswordField`, `PasswordCallback` or `KeyStore.PasswordProtection`, or to a `char[]` variable assigned from one of those within the 15 lines above. It also reports the deprecated `JPasswordField.getText()`, which returns a `String`.

It does not report a `char[]` that is used and wiped without becoming a String, a `getPassword()` of an application class that already returns a String, `new String` over other byte or char arrays, or comments and string literals. Native memory locking (`mlock`, `VirtualLock`) in C/C++ is not analysed.

**Severity:** Low | **CWE:** [CWE-591](https://cwe.mitre.org/data/definitions/591.html) | **Languages:** java

## Why This Matters

A `String` is immutable and is collected whenever the garbage collector chooses. Until then the password sits in the heap, where it can be paged to swap, written into a heap dump or crash dump, or read by anything that can inspect the process. A `char[]` can be cleared the moment authentication finishes.

## What Gets Flagged

```java
// FLAGGED: the password becomes an immutable String
String password = new String(console.readPassword("Password: "));

char[] secret = console.readPassword("Keystore password: ");
String asText = new String(secret);          // FLAGGED

String typed = new String(passwordField.getPassword());  // FLAGGED
String pin = pinField.getText();             // FLAGGED: JPasswordField.getText()

// NOT FLAGGED: the char[] is used and wiped
char[] pw = console.readPassword("Password: ");
try {
    verify(pw);
} finally {
    Arrays.fill(pw, '\0');
}
```

## Remediation

1. Keep the password in the `char[]` the API returned and pass that array to the code that needs it (`PBEKeySpec`, `KeyStore.load`, `KeyManagerFactory.init` all take `char[]`).
2. Overwrite the array with `Arrays.fill(pw, '\0')` in a `finally` block once it has been used.
3. Replace `JPasswordField.getText()` with `getPassword()`.
