---
title: "VNX-309 – Use of Password System for Primary Authentication"
description: "Login decided by comparing a submitted password directly with a stored or configured one (==, ===, !=, .equals()) instead of verifying a slow salted hash."
---

## Overview

VNX-309 maps to [CWE-309: Use of Password System for Primary Authentication](https://cwe.mitre.org/data/definitions/309.html). Whether a deployment adds a second factor elsewhere is not visible in code, so the rule reports the concrete code-level form a line-oriented check can see: authentication decided by an equality test whose two operands both name a password, in Python, JavaScript/TypeScript, Java or PHP. Examples are `user.password == request.form["password"]`, `password === user.password`, `user.getPassword().equals(password)`, `Objects.equals(password, account.getPassword())` and `$row['password'] == $_POST['password']`. Such code keeps the password in a recoverable form, makes it the sole secret, and compares it in non-constant time.

Not reported: password-hash verification (`check_password_hash`, `bcrypt.compare`, `passwordEncoder.matches`, `password_verify`), operands that hash or measure the password (`hash()`, `md5`, `digest`, `length`), confirmation checks (`password == confirm_password`, `password1 != password2`, new versus current password, matching password), comparisons with null, empty strings or other literals, enum and format comparisons, test files and comments.

**Severity:** Medium | **CWE:** [CWE-309](https://cwe.mitre.org/data/definitions/309.html) | **Languages:** java, node, php, python

## Why This Matters

A plain comparison means the password is stored in cleartext (or reversibly), so a database leak hands over every credential directly, and those credentials are often reused on other sites. With nothing but the password protecting the account, guessing or phishing it is enough.

## What Gets Flagged

```python
# FLAGGED
if u and u.password == request.form["password"]:
    session["uid"] = u.id
```

```javascript
// FLAGGED
if (!user || user.password !== req.body.password) { return res.status(401).end(); }
```

```java
// FLAGGED
if (account != null && account.getPassword().equals(password)) { return true; }
```

Not flagged: `check_password_hash(user.password_hash, form["password"])`, `await bcrypt.compare(password, user.passwordHash)`, `data.get("password1") != data.get("password2")`, `password === ''`.

## Remediation

1. Store passwords with a slow, salted hash (Argon2id, bcrypt, scrypt) and verify with the library's constant-time check.
2. Add a second factor (TOTP, WebAuthn) for login, or move to passwordless authentication.
