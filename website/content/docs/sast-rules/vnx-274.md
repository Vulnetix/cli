## Overview

VNX-274 maps to [CWE-274: Improper Handling of Insufficient Privileges](https://cwe.mitre.org/data/definitions/274.html). When the process lacks the privilege to change identity or enter a jail, the call fails. Detecting the failure is not enough: if the failure branch only prints a warning and falls through, the program carries on as root, or outside the jail, exactly as if the check were missing. VNX-273 covers the call that is not checked at all; this rule covers the check that does not stop.

Reported:

- C and C++: an `if` on the failure of `setuid`, `setgid`, `seteuid`, `setegid`, `setreuid`, `setregid`, `setresuid`, `setresgid`, `setgroups`, `initgroups` or `chroot` (`!= 0`, `< 0`, `== -1`, or the bare call), directly or through a result variable assigned just above, and on the failure of `ImpersonateNamedPipeClient`, `ImpersonateLoggedOnUser`, `ImpersonateSelf`, `ImpersonateAnonymousToken` or `SetThreadToken`, whose branch has no `return`, `exit`, `abort`, `goto`, `err()`/`errx()`, glibc `error()` with a nonzero status, `break`, `continue` or `fatal()`/`die()`-style call.
- Python: `os.setuid`, `os.setgid`, `os.seteuid`, `os.setegid`, `os.setreuid`, `os.setresuid`, `os.setresgid`, `os.setgroups`, `os.initgroups` or `os.chroot` in a `try` whose `except OSError`/`PermissionError`/`Exception`/bare `except` neither raises, returns nor exits, or inside `contextlib.suppress(OSError)`.
- Go: `if err != nil` after `syscall`/`unix` `Setuid`, `Setgid`, `Setresuid`, `Setgroups`, `Chroot` and similar, whose body neither returns, panics, calls `os.Exit` nor `log.Fatal`.
- PHP: an `if` on the failure of `posix_setuid`, `posix_setgid`, `posix_seteuid`, `posix_setegid` or `posix_initgroups` (`!posix_setuid(...)`, `=== false`) whose body neither throws, returns, exits nor dies.

**Severity:** Low | **CWE:** [CWE-274](https://cwe.mitre.org/data/definitions/274.html) | **Languages:** C, C++, Python, Go, PHP

## What Gets Flagged

```c
// FLAGGED: the failure is printed, then serve_clients() runs as root
if (setuid(pw->pw_uid) != 0) {
    perror("setuid");
}
serve_clients();
```

```python
# FLAGGED: a failed drop is swallowed
try:
    os.setuid(uid)
except PermissionError as exc:
    logger.warning("could not drop to uid %s: %s", uid, exc)
serve()
```

```go
// FLAGGED
if err := syscall.Setuid(uid); err != nil {
    log.Printf("setuid: %v", err)
}
serve()
```

```php
// FLAGGED: the worker keeps running as root
if (!posix_setgid($gid) || !posix_initgroups($user, $gid) || !posix_setuid($uid)) {
    $this->log("Warning: change gid or uid failed.");
}
```

## What Is Not Flagged

- A failure branch that stops: `return -1`, `exit(1)`, `err(1, "setgid")`, `error(EXIT_FAILURE, errno, ...)`, `abort()`, `goto fail`, `raise`, `sys.exit(...)`, `return False`, `log.Fatalf(...)`, `panic(err)`, `throw new RuntimeException(...)`, `die(...)`.
- A check on success (`if (setuid(uid) == 0) { run_unprivileged(); }`).
- An unchecked call, which is VNX-273, and a raise back to root (`if (seteuid(0) != 0) perror(...)`): failing to gain root leaves the program less privileged.
- An `except` for an unrelated exception (`except KeyError:`).

## Remediation

Treat a failed privilege change as fatal:

```c
if (setuid(pw->pw_uid) != 0) {
    perror("setuid");
    exit(EXIT_FAILURE);
}
```

```python
try:
    os.setuid(uid)
except OSError:
    log.exception("cannot drop privileges")
    raise
```
