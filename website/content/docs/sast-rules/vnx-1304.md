---
title: "VNX-1304 – Security state restored from unprotected saved state"
description: "Detects Android Java/Kotlin code that restores a security decision (logged in, admin, role, PIN verified, unlocked, premium) from plain SharedPreferences or a saved-instance Bundle instead of re-establishing it. The software analogue of CWE-1304."
---

## Overview

VNX-1304 maps to [CWE-1304: Improperly Preserved Integrity of Hardware Configuration State During a Power Save/Restore Operation](https://cwe.mitre.org/data/definitions/1304.html). CWE-1304 is a hardware weakness: configuration saved before a low-power state is restored afterwards without an integrity check. Hardware save/restore is not visible in application source, so the rule reports the nearest software analogue: a security decision saved across a process stop and restored as trusted.

Reported: `getBoolean`, `getString` or `getInt` whose key names a security decision (logged in, authenticated, admin, role, PIN or biometric verified, unlocked, premium or licensed, access level), as a literal or as a constant of the same file, called on

- plain `SharedPreferences` (a variable typed `SharedPreferences` or assigned from `getSharedPreferences`/`getDefaultSharedPreferences`, or a call chained onto one), which a rooted device or a backup restore can edit; or
- a saved-instance `Bundle` (`savedInstanceState`, a variable typed `Bundle`), restored after process death, which skips re-authentication.

Not reported: `EncryptedSharedPreferences`, keys that are not security decisions (theme, language, scroll position), the same getters on JSON objects or Intents, test code and comments.

**Severity:** Medium | **CWE:** [CWE-1304](https://cwe.mitre.org/data/definitions/1304.html) | **Languages:** Java, Kotlin

## What Gets Flagged

```java
SharedPreferences prefs = getSharedPreferences("bank", MODE_PRIVATE);
boolean loggedIn = prefs.getBoolean("isLoggedIn", false);   // FLAGGED
```

```java
@Override
protected void onRestoreInstanceState(Bundle savedInstanceState) {
    pinVerified = savedInstanceState.getBoolean("pin_verified");   // FLAGGED
}
```

## What Is Not Flagged

```java
boolean dark = prefs.getBoolean("dark_mode", false);
boolean authenticated = response.getBoolean("authenticated");   // a JSON response
```

## Remediation

1. Re-establish authentication and authorisation after a restart: ask the user again or confirm with the server.
2. Keep any persisted security state in `EncryptedSharedPreferences` or the Android Keystore, and treat it as a hint, not a decision.
3. Do not restore a "PIN verified" or "unlocked" flag from `savedInstanceState`.
