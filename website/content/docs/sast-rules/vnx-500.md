---
title: "VNX-500 – Public Static Field Not Marked Final"
description: "Detects public static fields that are not final (Java) or not readonly/const (C#), which any code in the process can reassign."
---

## Overview

VNX-500 maps to [CWE-500: Public Static Field Not Marked Final](https://cwe.mitre.org/data/definitions/500.html). A `public static` field is global state. Without `final` (Java) or `readonly`/`const` (C#), any class, plugin or deserialised object in the process can replace it, so a configuration flag, a singleton, a trusted-host list or a connection string other code depends on can change underneath it.

The rule reports the declaration, in any modifier order (`static public`, `public volatile static`), with or without an annotation or initialiser.

**Severity:** Low | **CWE:** [CWE-500](https://cwe.mitre.org/data/definitions/500.html) | **Languages:** Java, C#

## What Gets Flagged

```java
public static String adminEmail = "ops@example.com";   // FLAGGED
static public boolean debug = false;                    // FLAGGED
public static String[] trustedHosts = {"a.example.com"}; // FLAGGED
```

```csharp
public static string ConnectionString = "Server=db;Database=app"; // FLAGGED
```

## What Is Not Flagged

- `public static final` (Java) and `public static readonly` / `public const` (C#) fields.
- Non-public statics, methods, nested classes and generic methods.
- C# properties (`{ get; set; }`), expression-bodied members (`=> "x"`) and events.
- Fields of a Java interface, which are implicitly `final`.
- Test code, comments and string literals.

A `final` field that refers to a mutable object (an array or a collection) can still be changed in place; that is a separate weakness (CWE-582).

## Remediation

1. Declare the field `final` (`readonly` in C#).
2. If it must change, make it private and expose controlled accessors.
