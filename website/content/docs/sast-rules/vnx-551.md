title: "VNX-551 – Incorrect Behavior Order: Authorization Before Parsing and Canonicalization"
description: "An access decision is taken on a request-supplied path or resource name that is only decoded, parsed or canonicalised afterwards, so the check judges a different string from the one the code uses."
---

## Overview

VNX-551 maps to [CWE-551: Incorrect Behavior Order: Authorization Before Parsing and Canonicalization](https://cwe.mitre.org/data/definitions/551.html). It reports an authorisation check on a value taken from the request when that same value is decoded, parsed or canonicalised in the lines after the check.

**Severity:** Low | **CWE:** [CWE-551](https://cwe.mitre.org/data/definitions/551.html) | **Languages:** java, node, python

## Why This Matters

A check on the raw text is not a check on what the code goes on to use. `/%61dmin`, `/a/../admin` and `/admin;x` fail a `startsWith("/admin")` test, then decode or normalise to `/admin`, and the protected resource is served. A file name that contains `..` gets past a permission check written against the literal name, then `normpath` or `getCanonicalPath` turns it into a different file.

## What Gets Flagged

The rule reports the check when:

- the value is assigned from the request (servlet `getRequestURI`/`getPathInfo`/`getParameter`/`getHeader`, Django/Flask `request.path`/`args`/`GET`, Express `req.url`/`originalUrl`/`params`/`query`) in the 20 lines above;
- the check compares it with a `'/...'` literal (`startsWith`, `equals`, `includes`, `==`, `===`) in a condition, or passes it to an authorisation call (`authorize`, `checkPermission`, `hasPermission`, `canAccess`, `isAllowed`...);
- one of the next 15 lines decodes or canonicalises that same variable (`URLDecoder.decode`, `decodeURIComponent`, `unquote`, `normpath`, `realpath`, `getCanonicalPath`, `Paths.get(...).normalize()`, `path.normalize`, `urlparse`, `new URL`).

```java
String uri = request.getRequestURI();
if (uri.startsWith("/admin") && !isAdmin(request)) {   // FLAGGED
    response.sendError(HttpServletResponse.SC_FORBIDDEN);
    return;
}
String resource = URLDecoder.decode(uri, StandardCharsets.UTF_8);
```

```python
name = request.args.get("name", "")
if not has_permission(current_user(), name):            # FLAGGED
    abort(403)
target = os.path.normpath(os.path.join(ROOT, name))
```

Not flagged: a value decoded or canonicalised before it is checked, a check on one variable followed by decoding another, values that do not come from the request, comments and string literals. Related rules: VNX-179 (checks for `..` or `<` before decoding), VNX-289 (guards on the raw request path) and VNX-41 (directory-containment checks on non-canonical paths).

## Remediation

1. Decode, parse and canonicalise the value first: `URLDecoder.decode` then `Paths.get(...).normalize()`, `unquote` then `os.path.realpath`, `decodeURIComponent` then `path.posix.normalize`.
2. Authorise the canonical form, and use exactly that form afterwards.
3. Prefer framework path matching (`getServletPath()`, Spring Security matchers) over hand-written prefix checks on `getRequestURI()`.
