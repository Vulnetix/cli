## Overview

VNX-1284 maps to [CWE-1284: Improper Validation of Specified Quantity in Input](https://cwe.mitre.org/data/definitions/1284.html).

**Severity:** Medium | **CWE:** [CWE-1284](https://cwe.mitre.org/data/definitions/1284.html) | **Languages:** node, python

## Why This Matters

A quantity or amount taken from the request and used as is lets the client choose a negative or huge value. A negative transfer moves money the wrong way, a negative cart quantity gives a refund, and a huge one overflows a total or exhausts stock.

## What Gets Flagged

```python
product.stock += int(request.form["quantity"])

qty = int(request.POST.get("quantity", 1))
total = product.price * qty
```

```javascript
const { productId, quantity } = req.body;
await CartItem.create({ productId, quantity });

const { points } = req.body;
await Member.updateOne({ _id: id }, { $inc: { points: -points } });
```

Not flagged: a value compared (`if amount <= 0 or amount > src.balance: abort(400)`) or clamped (`max(1, ...)`) before use, a file that validates with a schema (`Joi.number().positive()`, pydantic `conint(gt=0)`), a value that is only displayed.

A client amount credited to a balance or booked as an order total (`dst.balance += int(request.form["amount"])`, `account.balance -= amount`, `{ $inc: { balance: -amount } }` in a wallet or payment handler) is reported by [VNX-840](../vnx-840/) (Client-Controlled Monetary Value), not here as well: the negative or oversized amount is how that one defect is exploited, so it is one finding. Quantities, units, credits, points and stock, and money values VNX-840 does not take, stay here.

## Remediation

1. Reject quantities below the minimum (usually 1) and above a business maximum before using them.
2. Validate request bodies with a schema that states the range.
