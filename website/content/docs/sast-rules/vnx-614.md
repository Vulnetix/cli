## Overview

VNX-614 maps to [CWE-614: Sensitive Cookie in HTTPS Session Without 'Secure' Attribute](https://cwe.mitre.org/data/definitions/614.html).

- **Python:** `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE` or `REMEMBER_COOKIE_SECURE` set to `False` (assignment, `app.config[...]`, `config.update(...)`); `set_cookie(..., secure=False)`; `set_cookie()` of a session, token, JWT, auth, remember-me, login, user-id or CSRF cookie with no `secure=` argument.
- **JavaScript/TypeScript:** `secure: false` in cookie or session options; `res.cookie()`/`ctx.cookies.set()` of such a cookie with no options or an options literal without `secure`; `document.cookie = "token=..."` without `; Secure`.

Not reported: a cookie being cleared (empty or null value, `max_age=0`, `setMaxAge(0)`), `secure` taken from a variable or the environment, options passed as a variable or spread, non-sensitive cookies (theme, language) and flag values (`1`, `true`), Flask's default-config dict, development settings files (`settings/local.py`, `dev.py`), `secure: false` away from any cookie (SMTP clients), and tests. VNX-SEC-013 also reports secure/httponly switched off explicitly.

**Severity:** High | **CWE:** [CWE-614](https://cwe.mitre.org/data/definitions/614.html) | **Languages:** node, python

## Why This Matters

A cookie without `Secure` is also sent over plain HTTP, for example on the first `http://` request before a redirect. Anyone on the network path can then read the session or token and take over the account.

## What Gets Flagged

```python
SESSION_COOKIE_SECURE = False
response.set_cookie("auth_token", token, httponly=True)
```

```javascript
res.cookie('token', token)
app.use(session({ cookie: { httpOnly: true, secure: false } }))
document.cookie = "access_token=" + token + "; path=/";
```

```java
Cookie session = new Cookie("JSESSIONID", id);          // no setSecure(true) follows
ResponseCookie.from("AUTH_TOKEN", jwt).httpOnly(true).build();
```

```properties
server.servlet.session.cookie.secure=false
```

## Remediation

1. Set `SESSION_COOKIE_SECURE = True` / `CSRF_COOKIE_SECURE = True` in production settings.
2. Pass `secure=True` (Python) or `secure: true` (Express, Koa) for every session and authentication cookie, and serve the site only over HTTPS with HSTS.
3. For a confirmed false positive, add a `# vulnetix-ignore: VNX-614` comment on the line.
