## Overview

A password written into a configuration file is committed with it, copied into every image and backup, and readable by anyone who can read the file. This maps to [CWE-260: Password in Configuration File](https://cwe.mitre.org/data/definitions/260.html).

This rule reads the configuration shapes that the generic hard-coded password rule, VNX-SEC-014, does not: that rule already covers YAML, `.properties`, `.ini`, `.conf`, `.env`, JSON keys and `password="..."` attributes.

**Severity:** High | **CWE:** [CWE-260](https://cwe.mitre.org/data/definitions/260.html) | **Languages:** configuration files

## What Gets Flagged

- An XML element whose name ends in password/passwd with a literal body: `<password>`, `<smtpPassword>`, `<jdbc.password>`.
- An XML `<property>`, `<prop>`, `<entry>`, `<param>`, `<parameter>`, `<add>`, `<setting>` or `<context-param>` whose name or key ends in password/passwd/pwd, with a literal value attribute or body.
- An XML attribute named for the password: Tomcat `<Resource ... password="...">`, `<user username="..." password="...">` in tomcat-users.xml, Spring Security or ASP.NET forms credentials (a `{noop}` value is plaintext), a Connector `keystorePass="..."`.
- The `Password=`/`Pwd=` key of a `connectionString` attribute in Web.config or App.config.
- PHP `define('DB_PASSWORD', '...')` (also `_PASS`, `_PWD`) anywhere, and `$config[...]['password'] = '...'` in PHP files whose path names a config, settings, database or local file.
- Credential dotfiles: `.netrc` password entries, `.pgpass` lines, `.pypirc` `password =`, `.npmrc` `_password=`/`_auth=`.

```xml
<server>
  <id>internal-repo</id>
  <password>D3ploy-Repo-2024</password>        <!-- flagged -->
</server>
<property name="password" value="Spr1ng-DS-pass"/>   <!-- flagged -->
<add key="SmtpPassword" value="Sm7p!Relay" />        <!-- flagged -->
<user username="deployer" password="Depl0yMgr!" roles="manager-script"/>   <!-- flagged -->
<add name="Main" connectionString="Server=sql01;User Id=app;Password=W3bC0nf!g;" />  <!-- flagged -->
```

```php
define( 'DB_PASSWORD', 'Wp-Pr0d-Pass' );          // flagged
```

Not flagged: placeholders and references (`${...}`, `#{...}`, `{{...}}`, `@token@`, `<...>`, `****`), encrypted values (Maven `{...}`, Jasypt `ENC(...)`, Spring `{cipher}`), empty values, labels, names that only contain the word (`passwordEncoder`, `password_hint`, `PASSWORD_MIN_LENGTH`), XML comments, config templates (`.example`, `.sample`, `.template`, `.dist`) and test resources. A registry-scoped `.npmrc` line (`//host/:_password=`) begins with `//` and is dropped by the engine's comment scope, so only the unscoped form is reported.

## Remediation

```xml
<property name="password" value="${DB_PASSWORD}"/>
```

```php
define( 'DB_PASSWORD', getenv('DB_PASSWORD') );
```

Inject passwords from the environment or a secret manager at deploy time, encrypt Maven server passwords with `mvn --encrypt-password`, and rotate any password that has been committed.
