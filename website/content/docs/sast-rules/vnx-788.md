## Overview

VNX-788 maps to [CWE-788: Access of Memory Location After End of Buffer](https://cwe.mitre.org/data/definitions/788.html). It reports C and C++ accesses one element past the end of an array declared in the same file:

- `X[sizeof(X)]` or `X[sizeof X]`
- `X[N]` where the nearest declaration of `X` is `T X[N]` (N a number or a constant)
- a `for` loop bounded by `i <= N` or `i <= sizeof(X)` that indexes `X[i]` in its body
- `n = read(fd, X, sizeof X)` (also `recv`, `pread`, `fread(X, 1, ...)`) followed by `X[n] = ...`, where a full read leaves no room for the terminator

Arrays declared elsewhere, struct members, pointer buffers, `&X[N]` (a valid one-past-the-end pointer) and bounds computed at run time are not reported.

**Severity:** High | **CWE:** [CWE-788](https://cwe.mitre.org/data/definitions/788.html) | **Languages:** c, cpp

## Why This Matters

Valid indexes run from 0 to size - 1. Writing at index `size` corrupts whatever follows the array (another variable, a saved frame pointer, heap metadata), and reading it leaks adjacent memory.

## What Gets Flagged

```c
char name[32];
name[sizeof(name)] = '\0';              // FLAGGED

int vals[N];
for (i = 0; i <= N; i++)                // FLAGGED: runs to vals[N]
    total += vals[i];

ssize_t got = read(fd, req, sizeof(req));
req[got] = '\0';                        // FLAGGED: got can equal sizeof(req)
```

## Remediation

1. Terminate at `sizeof(buf) - 1` and read at most `sizeof(buf) - 1` bytes.
2. Bound loops with `i < N`.
