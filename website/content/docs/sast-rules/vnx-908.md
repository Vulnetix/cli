title: "VNX-908 – Use of Uninitialized Resource"
description: "A C or C++ local scalar, pointer or struct is read before it is assigned (or assigned only under an if with no else), or a stack char array or malloc/new[] buffer is used as a string before anything writes it."
---

## Overview

VNX-908 maps to [CWE-908: Use of Uninitialized Resource](https://cwe.mitre.org/data/definitions/908.html). It reports three shapes in C and C++ function bodies:

1. **Read before assignment.** A local scalar, pointer or C struct declared without an initializer (`int total;`, `const char *name;`, `struct node *n;`, and each name in `int rc, n;` or `char *a, *b;`; one finding per declaration line) whose first use within 30 lines reads it: `total += v[i]`, `n->value = v`, `printf("%s", name)`.
2. **Assigned on one path only.** Such a local assigned only inside an `if` with no `else` (or on a single-line `if`) and then read at the declaration's own level.
3. **String operations on an unwritten buffer.** A stack `char` array without an initializer, or memory from `malloc`/`realloc`/`new char[]`, whose first use after any NULL check reads it as a string: `strcat`/`strncat` into it, `strlen`, `strcmp`, `puts`, `printf` `%s`, or copying from it.

Not reported: a first use that assigns the variable (including `for (i = 0, j = 0; ...)`, `(ch = getchar())`, chained `a = b = v` and `ip = strchr(s, c); if (!ip) ...` on one line), a statement-level ALL-CAPS macro call between the declaration and the read, takes its address (`&x` out-parameters, `stat(path, &st)`), reads into it with `>>`, uses it only in `sizeof`, or passes it to a C++ function (which may take it by reference) or a macro (ALL-CAPS, or defined with `#define` in the project); branches with `else`/`default`/`switch`, early returns or gotos between the assignment and the read; `calloc`, `= {0}`, `memset`, `snprintf`, `fgets` or `strcpy` into a buffer; statics, globals and struct/class fields; comments and strings. Flow through loops, other functions and pointers is not followed.

**Severity:** Low | **CWE:** [CWE-908](https://cwe.mitre.org/data/definitions/908.html) | **Languages:** c, cpp

## Why This Matters

An uninitialized local holds whatever the stack or a register last held. Reading it gives undefined behaviour: a wrong sum, a pointer write to an arbitrary address, or a `strcat` that walks past the buffer looking for a terminator that was never written. Stale stack contents can also leak earlier data (keys, pointers that defeat ASLR) into output.

## What Gets Flagged

```c
int sum(const int *v, int len)
{
    int total;
    for (int i = 0; i < len; i++)
        total += v[i];                       // FLAGGED
}

int open_log(const char *path)
{
    int fd;
    if (path != NULL) {
        fd = open(path, O_WRONLY | O_APPEND);
    }
    return fd;                               // FLAGGED
}

char *out = malloc(strlen(a) + strlen(b) + 1);
if (out == NULL)
    return NULL;
strcat(out, a);                              // FLAGGED
```

Not flagged: `if (stat(p, &st) == 0) return st.st_size;`, `int r; if (a > b) { r = a; } else { r = b; } return r;`, `char buf[64]; snprintf(buf, sizeof buf, ...)`, `char *q = calloc(1, 64); strcat(q, who);`.

## Remediation

1. Initialize locals at their declaration (`int total = 0;`, `char *name = NULL;`, `struct stat st = {0};`).
2. Assign a value on every path, including the `else` you did not write.
3. Terminate a fresh buffer before string operations (`buf[0] = '\0'`), or allocate it with `calloc`.
4. Compile with `-Wall -Wuninitialized -Wmaybe-uninitialized` and run tests under MemorySanitizer or Valgrind.
