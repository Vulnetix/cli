title: "VNX-193 – Off-by-one Error"
description: "Reports C/C++ sizes and indices one off for the terminator or last element: malloc(strlen(s)) then strcpy, buf[sizeof(buf)] or name[N] writes, for loops to i <= N over arr[N], strncat bounded by sizeof(dst), and strncpy bounded by strlen(src)."
---

## Overview

VNX-193 maps to [CWE-193: Off-by-one Error](https://cwe.mitre.org/data/definitions/193.html). C strings need one byte more than their length for the terminating NUL, and an array of N elements ends at index N - 1. Getting either wrong by one writes a byte past the buffer, which is enough to corrupt a neighbouring variable, a heap header or a saved frame pointer.

**Severity:** Medium | **CWE:** [CWE-193](https://cwe.mitre.org/data/definitions/193.html) | **Languages:** C, C++

## What Gets Flagged

```c
char *out = malloc(strlen(name));      /* flagged: no room for '\0' */
strcpy(out, name);

char tmp[64];
tmp[sizeof(tmp)] = '\0';               /* flagged: one past the end */

static int slots[SLOTS];
for (i = 0; i <= SLOTS; i++)           /* flagged */
	slots[i] = 0;

strncat(path, user, sizeof(path));     /* flagged */
strncpy(buf_, text, strlen(text));     /* flagged: never terminated */
```

Not flagged: `strlen(s) + 1` allocations, `sizeof(x) - 1` bounds and indices, `strncat(d, s, sizeof(d) - strlen(d) - 1)`, a `malloc(strlen(s))` used for a length-prefixed copy with `memcpy` and no terminator, loops over arrays declared with a larger bound, strings and comments.

## Remediation

```c
char *out = malloc(strlen(name) + 1);
tmp[sizeof(tmp) - 1] = '\0';
for (i = 0; i < SLOTS; i++)
	slots[i] = 0;
strncat(path, user, sizeof(path) - strlen(path) - 1);
```
