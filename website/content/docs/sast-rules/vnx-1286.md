## Overview

VNX-1286 maps to [CWE-1286: Improper Validation of Syntactic Correctness of Input](https://cwe.mitre.org/data/definitions/1286.html). A parser rejects malformed input by raising (Python, `JSON.parse`) or by returning `NaN` (`parseInt`, `Number`). When a request value goes straight into one with nothing handling the rejection, a malformed value fails the request with an unhandled exception (often a 500 with a stack trace) or flows on as `NaN`.

Reported:

- **Python**: `int()`, `float()`, `Decimal()`, `json.loads()`, `uuid.UUID()`, `datetime`/`date` `fromisoformat()` and `strptime()`, `ipaddress.ip_address()`/`ip_network()` applied to Flask/Django/DRF request data (`request.args`, `form`, `values`, `GET`, `POST`, `data`, `body`, `json`, `cookies`, `headers`, `query_params`, `META`), directly or through a variable assigned from it in the 10 lines above, outside a `try` block and without an `isdigit()`/regex check first.
- **JavaScript/TypeScript**: `JSON.parse()` of request data (`req.body`/`query`/`params`/`cookies`/`headers`, `ctx.query`, `ctx.request.body`, Lambda `event.body`) outside a `try` block; `parseInt()`, `parseFloat()` or `Number()` of request data with no NaN check (`isNaN`, `Number.isNaN`, `Number.isFinite`, `|| default`, a falsy test) on the line or in the 6 lines after.

Not reported:

- **A numeric conversion VNX-229 reports.** `int()`/`float()` of Flask/Django request data outside `try`, and `parseInt()`/`parseFloat()`/`Number()` of `req.query`/`req.body` with no NaN handling, are reported by [VNX-229](../vnx-229/), the rule written for that conversion, so the same unhandled conversion is one finding, not two. The conversions VNX-229 does not read stay here: `req.params`, `ctx` and Lambda `event` sources, `request.META` and `request.body`, and a conversion VNX-229 treats as handled but this rule does not.
- Framework-typed access such as `request.args.get("n", type=int)`, constants, environment variables, file contents, comments and string literals.

**Severity:** Low | **CWE:** [CWE-1286](https://cwe.mitre.org/data/definitions/1286.html) | **Languages:** Python, JavaScript, TypeScript

## What Gets Flagged

```python
@app.route("/import", methods=["POST"])
def import_rows():
    rows = json.loads(request.data)   # FLAGGED: malformed JSON raises
    size = int(request.META["CONTENT_LENGTH"])   # FLAGGED: not a source VNX-229 reads
```

```javascript
router.get('/items/:id', (req, res) => {
  const id = JSON.parse(req.params.id);   // FLAGGED: outside try
  const n = parseInt(req.params.n, 10);   // FLAGGED: NaN never checked
});
```

## What Is Not Flagged

```python
try:
    page = int(request.args.get("page", "1"))
except ValueError:
    abort(400)
size = request.args.get("size", 20, type=int)
```

```javascript
const page = parseInt(req.query.page, 10);
if (Number.isNaN(page) || page < 1) return res.status(400).end();
```

```python
amount = int(request.form["amount"])   # reported by VNX-229, not repeated here
```

## Remediation

1. Parse request values inside `try`/`except` (`try`/`catch`) and answer 400 on failure.
2. Check numeric conversions for `NaN` before use, or supply a default.
3. Prefer a schema validator (pydantic, marshmallow, zod, Joi) or framework-typed accessors.
