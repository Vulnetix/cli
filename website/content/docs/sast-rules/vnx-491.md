## Overview

VNX-491 maps to [CWE-491: Public cloneable() Method Without Final ('Object Hijack')](https://cwe.mitre.org/data/definitions/491.html). It reports an overridable public `clone()` that copies with `super.clone()` in a class that is not final.

**Severity:** Medium | **CWE:** [CWE-491](https://cwe.mitre.org/data/definitions/491.html) | **Languages:** java

## Why This Matters

`super.clone()` produces an object without running any constructor, so constructor validation never happens for the copy. When the method and the class are both open to extension, a subclass can override `clone()` to return an object in a state the original class would never allow, or one that shares its mutable internals.

## What Gets Flagged

```java
public class Account implements Cloneable {
    @Override
    public Object clone() throws CloneNotSupportedException {   // FLAGGED
        return super.clone();
    }
}
```

Not flagged: `public final Object clone()`, a `clone()` in a `final class`, and a `clone()` that returns `new Point(x, y)`.

## Remediation

1. Declare `clone()` `final`, or make the class `final`.
2. Prefer a copy constructor or static factory (`Account.copyOf(a)`), which runs the constructor's checks.
3. If the class must not be cloned, declare `public final Object clone() throws CloneNotSupportedException { throw new CloneNotSupportedException(); }`.
