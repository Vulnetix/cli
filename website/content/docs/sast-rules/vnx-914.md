---
title: "VNX-914 – Improper Control of Dynamically-Identified Variables"
description: "Reports Python setattr() whose attribute name comes from HTTP request data, so the client chooses which attribute it overwrites."
---

## Overview

`setattr(obj, name, value)` where the attribute name is Flask, Django or DRF request data, inline, through a variable assigned from it in the 15 lines above, or as the key of a `for` loop over a request mapping or its `.items()`/`.keys()`. The client picks the attribute: `is_admin`, `password_hash`, or a method it replaces.

**Severity:** Medium | **CWE:** [CWE-914](https://cwe.mitre.org/data/definitions/914.html) | **Languages:** python

## Why This Matters

Any attribute of the object becomes writable from the request, including ones the form never showed, so a profile update can grant privileges or replace a bound method.

## What Gets Flagged

```python
setattr(user, request.form["field"], request.form["value"])

for key, value in request.get_json().items():
    setattr(user, key, value)
```

Not flagged: a constant attribute name, a loop over a constant tuple, serializer `validated_data` or form `cleaned_data`, a loop that checks the key against an allow-list before the `setattr`, comments and strings. VNX-PY-016 and VNX-627 cover related shapes.

## Remediation

Iterate an explicit allow-list of editable fields and read each from the request, or use a serializer or form that declares the fields.
