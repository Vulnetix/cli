---
title: "VNX-1007 – Mixed-script homoglyph in source code"
description: "Reports words in Python, JavaScript/TypeScript and Java source that mix Latin letters with Cyrillic or Greek lookalikes, the shape used to spoof usernames, domains and identifiers."
---

## Overview

VNX-1007 maps to [CWE-1007: Insufficient Visual Distinction of Homoglyphs Presented to User](https://cwe.mitre.org/data/definitions/1007.html). It reports a word that mixes ASCII Latin letters with a Cyrillic or Greek letter that renders like a Latin one (Cyrillic `а е о р с у х і ј ѕ` and capitals `А В Е К М Н О Р С Т Х`, Greek `Α Β Ε Ζ Η Ι Κ Μ Ν Ο Ρ Τ Υ Χ ο ν ρ α`), written directly or as a `\uXXXX` escape beside a Latin letter.

Not reported: text written wholly in Cyrillic or Greek, Greek letters used as symbols (`Δ`, `μ`, `Ω`, `π`), comments, and test files, which legitimately hold homoglyph samples. The rule reads source text only; it does not judge whether a user interface renders IDN domains or usernames distinguishably.

**Severity:** Low | **CWE:** [CWE-1007](https://cwe.mitre.org/data/definitions/1007.html) | **Languages:** Python, JavaScript/TypeScript, Java

## Why This Matters

A mixed-script word looks like the ordinary one to a reviewer but compares unequal to it. `"аdmin"` with a Cyrillic `а` slips past a check against `"admin"`, `pаypal.com` looks like the real domain, and an identifier spelled that way can shadow the real one without anyone noticing in review.

## What Gets Flagged

```python
BACKDOOR_USER = "аdmin"   # first letter is Cyrillic U+0430
```

```javascript
const redirectHost = 'pаypal.com';
```

```java
private static final String SUPERUSER = "аdmin";
```

## Remediation

1. Spell names, hosts and identifiers in one script.
2. Where user-chosen names or domains are compared or displayed, normalise them (NFKC, IDNA/punycode) and reject or flag mixed-script input, for example with a Unicode confusables check (UTS #39).
