## Overview

VNX-412 maps to [CWE-412: Unrestricted Externally Accessible Lock](https://cwe.mitre.org/data/definitions/412.html). The rule reports Java locks that code outside the class can acquire and hold, blocking the class indefinitely.

**Severity:** Medium | **CWE:** [CWE-412](https://cwe.mitre.org/data/definitions/412.html) | **Languages:** java

## Why This Matters

String literals are interned and `Boolean.TRUE` or small boxed integers are shared JVM-wide, so any library that happens to synchronize on the same value contends with this class. A public lock field or getter lets any caller take the lock and never release it.

## What Gets Flagged

```java
synchronized ("refresh") { ... }                          // FLAGGED: interned literal
synchronized (user.intern()) { ... }                      // FLAGGED
synchronized (CACHE_LOCK) { ... }                         // FLAGGED when CACHE_LOCK = "token-cache"
public final Object lock = new Object();                  // FLAGGED when the class synchronizes on it
public static final ReentrantLock WRITE_LOCK = new ReentrantLock();  // FLAGGED
public ReadWriteLock getLock() { return rw; }             // FLAGGED
```

Not flagged: `synchronized (this)`, synchronized methods and `synchronized (Foo.class)` (an ordinary idiom), private or package-private lock fields, public fields that are never used as a lock, test files, comments and strings.

## Remediation

1. Lock on a `private final Object lock = new Object();` owned by the class.
2. Do not return lock objects from public methods; expose operations instead.
3. For confirmed false positives, add a `// vulnetix-ignore: VNX-412` comment on the line.
