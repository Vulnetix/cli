## Overview

VNX-1122 maps to [CWE-1122: Excessive Halstead Complexity](https://cwe.mitre.org/data/definitions/1122.html). Halstead's measures grow with the number of operators and operands a reader has to hold at once. This rule measures the most concentrated form of that: a single physical Python line whose expression contains **16 or more operators**:

- arithmetic `+ - * / // % ** @`;
- bitwise `& | ^ ~ << >>`;
- comparison `== != < > <= >=`;
- boolean `and`, `or`, `not`.

String literals and trailing comments are removed before counting. Not reported: `def` signatures and decorators (`*args`, `**kwargs`, `->`), whole-line comments, test files, and expressions already broken over several lines (each physical line is measured on its own). It is a line-level proxy, not a full per-function Halstead volume.

**Severity:** Low | **CWE:** [CWE-1122](https://cwe.mitre.org/data/definitions/1122.html) | **Languages:** python

## Why This Matters

A dense expression is where operator-precedence mistakes, off-by-one bounds and wrong bit masks hide, and when the expression is a permission or validation check, the mistake is a security bug that reviewers read past.

## What Gets Flagged

```python
# FLAGGED: 19 operators in one permission check
return (mode & 0o400 and uid == owner) or (mode & 0o040 and gid == group and not uid == 0) or (mode & 0o004 and ~mode & 0o002 == 0 and mode >> 9 | 1 != 0)
```

```python
# NOT FLAGGED: the same computation through named intermediate values
subtotal = base * qty
taxes = subtotal * tax / 100
total = subtotal + taxes - discount + fee
```

## Remediation

1. Split the expression into named intermediate values that each say what they compute.
2. Move compound permission or validation conditions into small predicate functions with descriptive names.
3. Add parentheses wherever precedence between `and`/`or` or between bitwise and comparison operators matters.
