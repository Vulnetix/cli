description: "Reports memory released by a routine that does not match its allocator: new[] with free or delete, new with free or delete[], malloc memory with delete, alloca memory with free, and unique_ptr<T> owning new T[n], in C and C++."

## Overview

VNX-762 maps to [CWE-762: Mismatched Memory Management Routines](https://cwe.mitre.org/data/definitions/762.html). For a local pointer whose most recent assignment in the same function is the allocation, it reports `new T[n]` released with `free()` or scalar `delete`, `new T` released with `free()` or `delete[]`, `malloc`/`calloc`/`realloc`/`strdup` memory released with `delete` or `delete[]`, and `alloca` memory passed to `free()`. It also reports `std::unique_ptr<T>` or `std::shared_ptr<T>` constructed from `new T[n]`.

It does not report matching pairs, a pointer reassigned from another allocator before the release, releases in another function, placement new, `unique_ptr<T[]>`, or identifiers that only contain the word `new`.

**Severity:** Low | **CWE:** [CWE-762](https://cwe.mitre.org/data/definitions/762.html) | **Languages:** c, cpp

## Why This Matters

Each allocator keeps its own bookkeeping. Releasing through the wrong one is undefined behaviour: destructors are skipped, the array length cookie of `new[]` is misread, and the heap can be corrupted.

## What Gets Flagged

```cpp
unsigned char *pixels = new unsigned char[n];
free(pixels);                                  // flagged

char *dst = (char *)malloc(len);
delete[] dst;                                  // flagged

std::unique_ptr<char> buf(new char[n]);        // flagged
```

## Remediation

1. Pair `new`/`delete`, `new[]`/`delete[]` and `malloc`/`free`; never free `alloca` memory.
2. Prefer `std::vector`, `std::string` or `std::unique_ptr<T[]>` so the release is chosen for you.
