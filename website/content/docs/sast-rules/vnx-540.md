## Overview

VNX-540 maps to [CWE-540: Inclusion of Sensitive Information in Source Code](https://cwe.mitre.org/data/definitions/540.html). A public source map turns a minified bundle back into the original source, with its comments, internal API routes, feature flags and any value an author left in it. This rule reports build configurations that publish one for production:

- webpack `devtool` set to a source-map variant that embeds or links the source (`'source-map'`, `'inline-source-map'`, `'eval-source-map'`, `'cheap-module-source-map'`...) in a config whose `mode` is `'production'` or whose file name says prod;
- `devtool: isProduction ? 'source-map' : ...` where the production branch publishes maps;
- Vue CLI `productionSourceMap: true`;
- Vite `build.sourcemap: true` or `'inline'`;
- Next.js `productionBrowserSourceMaps: true`;
- an `angular.json` `production` configuration with `"sourceMap": true`;
- `GENERATE_SOURCEMAP=true` in `.env.production`.

**Severity:** Medium | **CWE:** [CWE-540](https://cwe.mitre.org/data/definitions/540.html) | **Languages:** JavaScript/TypeScript build configuration

## What Gets Flagged

```javascript
// webpack.prod.js - FLAGGED
module.exports = merge(common, {
  mode: 'production',
  devtool: 'source-map',
});
```

```javascript
// vue.config.js - FLAGGED
module.exports = { productionSourceMap: true };
```

## What Is Not Flagged

- `hidden-source-map` and `nosources-source-map` (no link in the bundle, or no source in the map), and `devtool: false`.
- Development configs, Vite `sourcemap: 'hidden'`, CSS dev source maps and values computed at run time.
- Comments and string literals.

Secrets written directly into source code are reported by the secrets rules, not here.

## Remediation

Turn public source maps off for production builds. If you need them for error reporting, generate hidden maps (`devtool: 'hidden-source-map'`, `sourcemap: 'hidden'`) and upload them privately to the error tracker instead of deploying them.
