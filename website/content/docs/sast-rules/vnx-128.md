## Overview

VNX-128 maps to [CWE-128: Wrap-around Error](https://cwe.mitre.org/data/definitions/128.html). It reports an allocation whose size is a multiplication involving a count read from outside the program, with no overflow check:

- `malloc`/`xmalloc`/`alloca(n * size)`, `realloc(p, n * size)` and `new T[a * b]`;
- where `n` is the result of `atoi`/`atol`/`strtol`/`strtoul` (and the `ll` variants), `ntohl`/`ntohs`/`be*toh`/`le*toh` or `getenv`, or a variable filled by `scanf`/`fscanf`/`sscanf` (`&n`), `fread(&n, ...)` or `read(fd, &n, ...)`, within the 20 lines above, or such a call written directly in the product;
- also the two-step form `size_t bytes = n * size; malloc(bytes)`.

A large count makes the product wrap around to a small value, the allocation succeeds, and the code that fills `n` elements overruns it.

**Severity:** Medium | **CWE:** [CWE-128](https://cwe.mitre.org/data/definitions/128.html) | **Languages:** c, cpp

## What Gets Flagged

```c
int count = atoi(argv[1]);
int *items = malloc(count * sizeof(int));          // FLAGGED

uint32_t n = ntohl(wire[0]);
recs = realloc(recs, n * sizeof(struct rec));      // FLAGGED

scanf("%d %d", &rows, &cols);
int *grid = new int[rows * cols];                  // FLAGGED
```

## What Is Not Flagged

- `calloc()` and `reallocarray()`, which check the multiplication.
- A count compared with `<`, `<=`, `>` or `>=` before the allocation, a `SIZE_MAX`/`INT_MAX` bound, `__builtin_mul_overflow` or `ckd_mul`.
- Counts that do not come from such a source (internal sizes, constants such as `MAX_ITEMS`).
- Counts that arrive through a function argument or a struct field (out of scope).

## Remediation

Use `calloc(n, size)` or `reallocarray(p, n, size)`, or check `n > SIZE_MAX / size` before multiplying.
