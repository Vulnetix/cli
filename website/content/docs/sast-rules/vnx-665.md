---
title: "VNX-665 – Improper Initialization"
description: "Reports a catch clause inside a Java static initializer whose body is empty or only prints, logs or prints the stack trace, leaving the class loaded with partly initialised static state."
---

## Overview

VNX-665 maps to [CWE-665: Improper Initialization](https://cwe.mitre.org/data/definitions/665.html). It reports a `catch` inside a `static { }` block whose body is empty or only calls `printStackTrace()`, `System.out/err.print*` or a logger. The catch line is reported.

Not reported: a catch that rethrows (`ExceptionInInitializerError`, `IllegalStateException`...), assigns a fallback value or returns, catches outside a static initializer (an empty catch in a method is a different weakness), comments.

**Severity:** Low | **CWE:** [CWE-665](https://cwe.mitre.org/data/definitions/665.html) | **Languages:** java

## Why This Matters

When a static initializer swallows the failure, the class loads anyway. Its keystore, connection or configuration stays `null`, and every later caller fails with a `NullPointerException` far from the real cause, or worse, runs with a missing security setting.

## What Gets Flagged

```java
static {
    try {
        STORE = KeyStore.getInstance("PKCS12");
        STORE.load(in, password());
    } catch (Exception e) {          // FLAGGED
    }
}
```

```java
// NOT FLAGGED
} catch (Exception e) {
    throw new ExceptionInInitializerError(e);
}
```

## Remediation

1. Rethrow as `ExceptionInInitializerError` so the class fails to load at the cause.
2. Or assign an explicit, safe fallback value in the catch.
3. Prefer lazy initialisation with explicit error handling over work in static blocks.
