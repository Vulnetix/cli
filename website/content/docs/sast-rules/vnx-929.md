## Overview

CWE-929 is an OWASP Top Ten 2013 category with no code shape of its own; this rule reports the concrete Java/Kotlin signal it was generated for, a collision-broken digest: MessageDigest.getInstance("MD5"/"MD2"/"MD4"/"SHA-1"/"SHA1"/"SHA"), the same name passed through a String constant assigned in the same file, Apache commons-codec DigestUtils.md5/md5Hex/sha1/sha1Hex/sha/shaHex/md2 (and getMd5Digest/getSha1Digest), and Guava Hashing.md5()/Hashing.sha1(). Not reported: SHA-2 and SHA-3 digests, algorithm names in comments and strings, and digests whose surrounding code names a non-security purpose (an ETag, checksum, CRC, cache key, fingerprint, de-duplication or the RFC 6455 WebSocket accept key). Whether the digest protects a password or signature is not decided here; VNX-327 reports that narrower case.

**Severity:** Medium | **CWE:** [CWE-929: OWASP Top Ten 2013 Category A1 - Injection](https://cwe.mitre.org/data/definitions/929.html) | **Languages:** Java, Kotlin

## Why This Matters

MD5 and SHA-1 collisions can be produced cheaply, and both are fast enough to brute-force passwords at billions of guesses a second. A token, signature or password hash built on them gives far less protection than it appears to.

## What Gets Flagged

```
MessageDigest md = MessageDigest.getInstance("MD5");
MessageDigest sha = java.security.MessageDigest.getInstance( "SHA-1" );
return DigestUtils.md5Hex(password);
return Hashing.md5().hashString(password, UTF_8).toString();
```

## What Is Not Flagged

```
MessageDigest md = MessageDigest.getInstance("SHA-256");
// ETag for a static asset, not a security use
String etag = DigestUtils.md5Hex(body);
```

## Remediation

1. Use SHA-256 or SHA-3 for integrity and signatures.
2. Use a password KDF (Argon2, bcrypt, scrypt or PBKDF2) for passwords.
3. Where MD5 or SHA-1 is required for a non-security purpose, name it (an ETag or checksum variable) so the intent is clear.
4. For a confirmed false positive, add a `vulnetix-ignore: VNX-929` comment on the line.
