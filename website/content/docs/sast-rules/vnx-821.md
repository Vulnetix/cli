title: "VNX-821 – Incorrect Synchronization"
description: "Java code synchronizes, but on a monitor that does not give the intended mutual exclusion. Reported: synchronized (new X()) (a fresh lock each call, so nothing is excluded); synchronized on a local variable assigned new ... in the same method; synchronized (Thread.currentThread()) (each thread locks itself); synchronized on a string literal, Boolean.TRUE/FALSE, Integer/Long/String.valueOf or .intern(), or a String/Integer/Long/Short/Byte/Boolean/Character field or variable, final or not (interned and cached values are shared with unrelated code); synchronized (getClass()) (a subclass instance locks a different Class object); synchronized on a java.util.concurrent Lock/ReentrantLock/ReadWriteLock/StampedLock/Semaphore object, field or local (its intrinsic monitor is unrelated to lock()/unlock()); synchronized on a non-final field that a method other than a constructor reassigns (threads end up holding different monitors); and a write to a static non-final field inside a non-static synchronized method, which locks the instance while the data is shared by every instance. Not reported: synchronized (this), on a final Object or collection field, on X.class, on a non-final field assigned only in a constructor, on a local obtained from a shared map or a lock-stripe array, static synchronized methods, a static write inside a synchronized (X.class) block, comments and strings."
---

## Overview

VNX-821 maps to [CWE-821: Incorrect Synchronization](https://cwe.mitre.org/data/definitions/821.html). The code takes a lock, but the lock object makes the synchronization useless or shares it with unrelated code.

**Severity:** Medium | **CWE:** [CWE-821](https://cwe.mitre.org/data/definitions/821.html) | **Languages:** java

## What Gets Flagged

```java
synchronized (new Object()) { n--; }          // FLAGGED: a new monitor every call

Object lock = new Object();
synchronized (lock) { ... }                   // FLAGGED: local lock

synchronized ("cache") { size++; }            // FLAGGED: interned literal shared JVM-wide
synchronized (Boolean.TRUE) { ... }           // FLAGGED
synchronized (getClass()) { ... }             // FLAGGED: subclasses lock a different object

private final ReentrantLock lock = new ReentrantLock();
synchronized (lock) { ... }                   // FLAGGED: use lock.lock()/unlock()

private final String LOCK = "LOCK";
synchronized (LOCK) { ... }                   // FLAGGED: interned String

private static int total;
public synchronized void add(int n) {
    total += n;                               // FLAGGED: instance lock, static data
}
```

Not flagged: `synchronized (this)`, `synchronized (lock)` on a `private final Object lock = new Object()`, `synchronized (Foo.class)`, `static synchronized` methods.

```java
// FLAGGED: every thread locks itself
synchronized (Thread.currentThread()) { entries.add(amount); }
```

Not flagged: a non-final lock field assigned only in the constructor, and `total++` inside `synchronized (Registry.class)` within an instance-synchronized method.

## Remediation

1. Lock on a dedicated `private final Object` field (static when the data is static).
2. Use `lock()`/`unlock()` on `java.util.concurrent` locks, never their monitor.
3. Lock static state on the class (`Foo.class`) or a static final lock.
