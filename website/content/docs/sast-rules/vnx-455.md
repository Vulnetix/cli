title: "VNX-455 – Non-exit on Failed Initialization"
description: "Reports C/C++ code that tests an initialisation call (sodium_init, curl_global_init, pthread_mutex_init, a project's own *_init) for failure and then only logs, so execution continues with an uninitialised library, context or lock."
---

## Overview

VNX-455 maps to [CWE-455: Non-exit on Failed Initialization](https://cwe.mitre.org/data/definitions/455.html). It reports an `if` whose condition tests an init/setup/startup function for failure (`!f()`, `< 0`, `== NULL`, `!= *_OK`...), directly or through a status variable assigned from the call just above, when the failure branch consists only of printf/fprintf/perror/syslog/std::cerr/log/warn statements. A failure branch that exits, returns, aborts, throws or sets a fallback, a success test that logs, and is*/has*Initialized predicates are not reported.

**Severity:** Medium | **CWE:** [CWE-455](https://cwe.mitre.org/data/definitions/455.html) | **Languages:** c, cpp

## Why This Matters

Code that runs after a failed initialisation uses a library, random-number generator, TLS context or lock in an undefined state. A crypto library that did not initialise can hand out predictable keys; a mutex that did not initialise does not exclude anyone.

## What Gets Flagged

```c
// FLAGGED: failure is only logged
if (sodium_init() < 0) {
    fprintf(stderr, "libsodium init failed\n");
}
generate_keys();

// NOT FLAGGED: the program stops
if (sodium_init() < 0) {
    fprintf(stderr, "libsodium init failed\n");
    exit(1);
}
```

## Remediation

1. Exit, return an error or abort in the failure branch of every initialisation check.
2. If a fallback is genuinely possible, record it in state that later code checks.
3. For confirmed false positives, add a `// vulnetix-ignore: VNX-455` comment on the line.
