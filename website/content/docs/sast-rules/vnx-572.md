---
title: "VNX-572 – Call to Thread run() instead of start()"
description: "Reports a Java or Kotlin Thread whose run() is called directly, so the work runs synchronously on the calling thread instead of on a new one."
---

## Overview

VNX-572 maps to [CWE-572: Call to Thread run() instead of start()](https://cwe.mitre.org/data/definitions/572.html). `Thread.run()` is an ordinary method call: it executes the thread's work on the current thread and returns when it finishes. No new thread is created. The caller blocks, and whatever the thread was meant to provide (concurrency, a watchdog, isolation of a slow or hostile task) is lost.

**Severity:** Low | **CWE:** [CWE-572](https://cwe.mitre.org/data/definitions/572.html) | **Languages:** java, kotlin

## What Gets Flagged

```java
new Thread(task, "report").run();

Thread worker = new Thread(task);
worker.run();

new Thread(() -> {
    for (String k : keys) {
        cache.load(k);
    }
}).run();
```

```kotlin
val t = Thread(work, "indexer")
t.run()
Thread { rebuild() }.run()
```

The receiver must be declared in the same file as a `Thread` (field, local, parameter, `var t = new Thread(...)`, `Thread.ofVirtual().unstarted(...)`, `val t = Thread(...)`) or as a class of the file that extends `Thread`.

## What Is Not Flagged

- `start()`.
- `run()` on a `Runnable` or any other type.
- `super.run()` inside a `run()` override.
- Kotlin's `run { }` scope function.
- The call in comments or string literals.

## Remediation

1. Call `start()` to run the work on the new thread, and `join()` if the caller must wait.
2. If the work should run on the current thread, call the `Runnable` directly and drop the `Thread`.
3. Prefer an `ExecutorService` for pooled background work.
