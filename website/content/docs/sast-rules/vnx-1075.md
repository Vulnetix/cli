description: "A C goto that jumps backwards to a label earlier in the same function, building a loop from an unconditional jump."
---

## Overview

VNX-1075 maps to [CWE-1075: Unconditional Control Flow Transfer outside of Switch Block](https://cwe.mitre.org/data/definitions/1075.html). It reports a C `goto L;` whose label `L:` is defined earlier in the same function (no column-zero closing brace between them, at most 150 lines above).

It does not report forward gotos to a cleanup or error label (the accepted C error-unwinding idiom), a backward goto into an error-handling tail section (the code after the label returns or jumps away at the label's own nesting level before reaching the goto, so the jump cannot loop), a same-named label in an earlier function, or goto text in comments (including a `/* */` block whose lines carry no leading `*`) and strings.

**Severity:** Low | **CWE:** [CWE-1075](https://cwe.mitre.org/data/definitions/1075.html) | **Languages:** c

## Why This Matters

A backward goto is a loop without a loop header: its condition and bound are hidden at the bottom, so it is easy to make it spin forever (an `EINTR` retry with no limit) or to re-run setup that should run once.

## What Gets Flagged

```c
retry:
    n = read(fd, buf, len);
    if (n < 0 && errno == EINTR)
        goto retry;                         // FLAGGED
```

Not flagged: `if (!buf) goto err_close;` with `err_close:` further down.

## Remediation

1. Write the loop as `for`, `while` or `do { } while`, with an explicit condition and, for retries, a bound.
