## Overview

VNX-1119 maps to [CWE-1119: Excessive Use of Unconditional Branching](https://cwe.mitre.org/data/definitions/1119.html). It reports a `goto label;` in C or C++ whose label is defined **above** it in the same function: a loop (`retry`, `again`, `restart`, `top`) written with unconditional jumps instead of `while`, `for` or `do`. A retry that reaches its label through a forward jump to an error handler is reported too.

Not reported:

- forward gotos to a cleanup or error label (`goto out;`, `goto err;`, `goto cleanup;`), the idiomatic C error-unwinding pattern;
- a backward goto between chained error handlers whose target ends in `return`, so control never comes back round;
- a label of the same name in an earlier function, computed gotos (`goto *ptr`), and gotos in comments or strings.

**Severity:** Low | **CWE:** [CWE-1119](https://cwe.mitre.org/data/definitions/1119.html) | **Languages:** c, cpp

## Why This Matters

Backward jumps are what make goto-heavy code hard to reason about. A retry loop written with `goto` has no visible bound, so it is easy to loop forever on a persistent error, or to jump back over an initialisation and re-enter with stale state (a freed buffer, a closed descriptor).

## What Gets Flagged

```c
ssize_t read_all(int fd, char *buf, size_t len)
{
    ssize_t n;
retry:
    n = read(fd, buf, len);
    if (n < 0 && errno == EINTR)
        goto retry;          /* FLAGGED: backward goto */
    return n;
}
```

```c
    if (!buf)
        goto cleanup;        /* NOT FLAGGED: forward jump to cleanup */
    ...
cleanup:
    free(buf);
```

## Remediation

1. Rewrite the backward jump as a `do { ... } while (cond);` or `for` loop with an explicit retry bound.
2. Keep `goto` for forward jumps to a single cleanup path, where it is the clearest construct C offers.
