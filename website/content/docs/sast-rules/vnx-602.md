---
title: "VNX-602 – Server trusts a client-supplied role or admin flag"
description: "Reports server code (Express/Koa, Django/Flask, PHP) that bases an authorisation decision on a role or admin flag taken from the request body, query, URL parameters, headers or unsigned cookies."
---

## Overview

VNX-602 maps to [CWE-602: Client-Side Enforcement of Server-Side Security](https://cwe.mitre.org/data/definitions/602.html). When the server checks a value the client sent, the client is the one enforcing the policy, and it can send whatever passes.

The rule reports a comparison, condition or ternary on a request value named for a role or privilege (`admin`, `isAdmin`, `is_admin`, `role`, `user_role`, `X-User-Role`, `isAuthenticated`, `loggedIn`, `authorized`, `privileges`, `accessLevel`, `userType`, `permissions`, `isStaff`, `superuser`), either directly or through a variable assigned from it within the 15 lines above. Sources: `req.body`, `req.query`, `req.params`, `req.headers`, `req.cookies` (Express/Koa); `request.COOKIES`, `GET`, `POST`, `args`, `form`, `cookies`, `headers`, `json`, `values`, `data` (Django/Flask); `$_COOKIE`, `$_GET`, `$_POST`, `$_REQUEST`, `$_SERVER` (PHP).

It does not report server-held identity (`req.user`, `req.session`, `request.user`, `$_SESSION`), signed cookies, the `Authorization` header, presence checks (`isset`, comparisons with null/undefined/None), a role written to a new record without a decision, browser UI code that reads a user object, or comments and string literals.

**Severity:** Medium | **CWE:** [CWE-602](https://cwe.mitre.org/data/definitions/602.html) | **Languages:** node, python, php

## What Gets Flagged

```javascript
if (req.body.isAdmin) { ... }                                  // FLAGGED
if (req.query.role === 'admin') { ... }                        // FLAGGED
const role = req.cookies.role;
if (role !== 'admin') { return res.status(403).end(); }        // FLAGGED

// NOT FLAGGED
if (req.user && req.user.role === 'admin') { ... }
if (req.session.isAdmin) { ... }
```

```python
if request.POST.get('is_admin') == "1":    # FLAGGED
if request.COOKIES.get('admin') == "1":    # reported by VNX-784, not VNX-602
```

```php
if ($_GET['role'] == 'admin') {            // FLAGGED
if ($_COOKIE['role'] == 'admin') {         // reported by VNX-784, not VNX-602
```

A privilege or login-state cookie compared or tested on the line that reads it, or assigned there to a variable that a condition uses within 15 lines, is a security decision on a cookie: [VNX-784](../vnx-784/) reports that line, so VNX-602 does not report it again. Body, query, URL-parameter and header values, and the decision line of a cookie read a few lines earlier, stay with VNX-602.

## Remediation

1. Take the user's role from the authenticated server-side session or a verified token, never from a field the client sends.
2. If a role must travel with the request, sign it (signed cookie, verified JWT claim) and verify the signature before use.
