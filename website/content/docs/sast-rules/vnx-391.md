title: "VNX-391 – Unchecked Error Condition"
description: "An exception is caught and silently discarded: an empty Java catch block (or one holding only a TODO or a discarded e.toString()), or a broad Python except whose whole body is pass."
---

## Overview

VNX-391 maps to [CWE-391: Unchecked Error Condition](https://cwe.mitre.org/data/definitions/391.html). It reports an exception that is caught and then thrown away. In Java that is a catch block whose body is empty, on one line or across lines holding only blanks, whose only statement is a discarded `e.toString()`/`e.getMessage()`, or which holds only a TODO/FIXME or auto-generated comment. In Python it is a bare `except:`, `except Exception` or `except BaseException` (alone or in a tuple) whose whole body is `pass` or `...`.

Not reported: a handler that logs, rethrows, returns or records anything; a Java catch variable named `ignored`, `ignore`, `expected` or `unused` (an explicit discard); a body with an explanatory comment, or a Python `pass` or `except` line carrying a trailing comment other than TODO/FIXME (`# nosec`, `# noqa`, a reason), which are documented decisions; a Python except of a specific type such as `ImportError` or `KeyError`; `contextlib.suppress`; test files, comments and strings.

**Severity:** Medium | **CWE:** [CWE-391](https://cwe.mitre.org/data/definitions/391.html) | **Languages:** java, python

## Why This Matters

A swallowed exception turns a failure into silent success. The caller carries on with half-written data, a missing configuration or an unauthenticated session, and nothing in the logs says why. Broad handlers also swallow programming errors, so bugs that would have crashed loudly in testing hide in production.

## What Gets Flagged

```java
try {
    ledger.write(invoice);
} catch (Exception e) {}            // FLAGGED

} catch (IOException e) {
    e.toString();                   // FLAGGED (catch line): result discarded
}
```

```python
try:
    os.remove(path)
except Exception:                   # FLAGGED
    pass
```

## Remediation

1. Catch the specific exception the call can raise, and handle it: retry, fall back, or return an error the caller checks.
2. If the failure is genuinely harmless, log it at debug level or name the variable `ignored` and add a comment saying why.
3. In Python, prefer `contextlib.suppress(SpecificError)` for a deliberate, narrow discard.
