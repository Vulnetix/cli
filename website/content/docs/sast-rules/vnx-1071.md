---
title: "VNX-1071 – Empty Code Block"
description: "A Java if, else, for, while, synchronized, try, finally or do block with nothing between its braces, or an if or for whose body is a stray semicolon."
---

## Overview

VNX-1071 maps to [CWE-1071: Empty Code Block](https://cwe.mitre.org/data/definitions/1071.html). It reports a Java control-flow block whose body is empty, on one line (`if (x) {}`) or across lines, and an `if` or `for` whose body is a stray semicolon (`if (token == null);`, `for (Item i : items);`), which makes the block after it run once, unconditionally. `while (...);` is not reported: spinning on a condition that does the work is a common idiom.

It does not report a block holding any statement or a comment (a comment records an intentional no-op), empty method and constructor bodies and lambdas (no-op overrides are legitimate), empty catch blocks (VNX-1069 owns those), try-with-resources, array initialisers, test sources, or the pattern inside strings and comments.

**Severity:** Low | **CWE:** [CWE-1071](https://cwe.mitre.org/data/definitions/1071.html) | **Languages:** java

## Why This Matters

An empty block usually marks unfinished or deleted logic: an authorisation check whose body was removed still reads like a check. A stray semicolon after `if` turns the guarded block into code that always runs.

## What Gets Flagged

```java
if (u.isAdmin()) {}                     // FLAGGED
} finally {                             // FLAGGED (empty body)
}
if (token == null);                     // FLAGGED (the next block always runs)
{
    deny();
}
```

## Remediation

1. Finish the block or delete it.
2. For a deliberate no-op, put a comment inside the braces saying why.
3. Remove the semicolon after an `if (...)` header.
