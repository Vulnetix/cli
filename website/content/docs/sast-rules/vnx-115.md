description: "Request values read as something other than what was sent: parseInt without a radix, Boolean()/!!/bool() of a request string, PHP loose comparison with secrets, strcmp() == 0 and non-strict in_array()."
---

## Overview

VNX-115 maps to [CWE-115: Misinterpretation of Input](https://cwe.mitre.org/data/definitions/115.html). It reports conversions and comparisons that interpret a request value differently from what the requester sent, when the value is used inline or through a variable assigned from the request in the 25 lines above:

- JavaScript/TypeScript `parseInt()` / `Number.parseInt()` of request data with no radix (`"0x10"` becomes 16).
- JavaScript `Boolean(x)` / `!!x` and Python `bool(x)` of a string request value (query, params, headers, cookies, form): `"false"` and `"0"` are true.
- PHP `==`/`!=` between request data and a token, password, hash, secret, signature, key, code or PIN (type juggling, `0e...` magic hashes); `strcmp()` of request data tested with `== 0` or `!` (an array argument returns NULL); `in_array()` of request data without the strict third argument.

Not reported: `parseInt(v, 10)`, `Number()`, explicit comparisons (`=== 'true'`, `.lower() == "true"`), `bool(request.args)`, JSON body values in the boolean checks, `===`, `hash_equals`, `password_verify`, `in_array(..., true)`, and loose comparison with an ordinary string.

**Severity:** Medium | **CWE:** [CWE-115](https://cwe.mitre.org/data/definitions/115.html) | **Languages:** node, php, python

## Why This Matters

When the program's reading of a value differs from the requester's, checks stop meaning what they say. `?include_deleted=false` turns the flag on; a reset token of `0e1234` loosely equals another magic-hash token; `password[]=x` makes `strcmp()` return NULL and the login succeed.

## What Gets Flagged

```javascript
const limit = parseInt(req.query.limit);        // FLAGGED: no radix
const isAdmin = Boolean(req.query.admin);       // FLAGGED: "false" is true
```

```python
include_deleted = bool(request.args.get("include_deleted"))   # FLAGGED
```

```php
<?php
if ($_GET['token'] == $stored) { /* ... */ }                    // FLAGGED
if (strcmp($_POST['password'], $admin_password) == 0) { }      // FLAGGED
$role = $_GET['role'];
if (in_array($role, ['viewer', 'editor'])) { }                 // FLAGGED
```

Not flagged: `parseInt(req.query.limit, 10)`, `req.query.admin === 'true'`, `request.args.get("x", type=str2bool)`, `hash_equals($stored, $_GET['token'])`, `in_array($_GET['role'], [...], true)`, `$_GET['page'] == 'home'`.

## Remediation

1. Always pass a radix to `parseInt`, or use `Number()` and check `Number.isInteger`.
2. Convert boolean flags explicitly: `v === 'true'`, `v.lower() in ('1', 'true', 'yes')`, or a typed request parser.
3. In PHP, compare secrets with `hash_equals()`, passwords with `password_verify()`, and use `===` and `in_array(..., true)` for everything else.
