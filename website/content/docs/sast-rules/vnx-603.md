---
title: "VNX-603 – Authentication decided in browser code"
description: "Reports browser JavaScript that decides authentication itself: a literal login or role flag written to localStorage, sessionStorage or document.cookie, such a flag read back to gate the page, or a password or PIN compared with a string literal."
---

## Overview

VNX-603 maps to [CWE-603: Use of Client-Side Authentication](https://cwe.mitre.org/data/definitions/603.html). Anything the browser decides, the user can change from the developer console.

The rule reports:

- a login or role flag written as a literal to `localStorage`/`sessionStorage` (`setItem('isLoggedIn', 'true')`, `sessionStorage.isAdmin = true`) or to `document.cookie` (`loggedIn=true`, `role=admin`);
- such a flag read back from storage and compared or tested to gate the page, directly or through a variable it was read into and a condition tests within the next 10 lines;
- a password, passcode or PIN (a variable so named, or the `.value` of an element whose id names one) compared with a non-empty string literal, in a file that uses the DOM and is not server code.

Flag names are `isLoggedIn`/`loggedIn`/`logged_in`, `isAuthenticated`/`authenticated`/`auth`, `isAdmin`/`admin`, `role`/`userRole`, and `isAuthorized`/`authorized`.

It does not report tokens stored or sent to the server (the server verifies them), flags set from a server response rather than a literal, clearing a flag (`removeItem`, `'false'`), unrelated preferences (theme, consent), empty-string checks, server-side password comparison (`bcrypt.compare`, `req.body`), or comments and prose inside string literals.

**Severity:** Medium | **CWE:** [CWE-603](https://cwe.mitre.org/data/definitions/603.html) | **Languages:** node

## What Gets Flagged

```javascript
localStorage.setItem('isLoggedIn', 'true');                 // FLAGGED
if (localStorage.getItem('isLoggedIn') !== 'true') { }      // FLAGGED
if (user === 'admin' && pass === 'S3cretPass!') { }         // FLAGGED
document.cookie = "loggedIn=true; path=/";                  // FLAGGED

// NOT FLAGGED
localStorage.setItem('token', res.accessToken);
fetch('/api/me', { headers: { Authorization: 'Bearer ' + token } });
localStorage.setItem('theme', 'dark');
```

## Remediation

1. Authenticate on the server and keep the result in a server-side session or a signed token.
2. Gate every protected page and API on the server; browser-side checks are for display only.
3. Never ship a password or PIN to the browser to compare against.
