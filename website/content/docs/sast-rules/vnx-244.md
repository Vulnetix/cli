---
title: "VNX-244 – Secret left in heap memory when it is released"
description: "Reports C/C++ free(), delete and realloc() of a buffer named as a password, passphrase, PIN, secret or key with no wipe in the lines before, and Java code that turns a char[] password into an immutable String."
---

## Overview

Heap memory that held a password or key keeps its contents after it is released. A heap dump, a core file, swap, or the next allocation that receives the same block can read the plaintext. This maps to [CWE-244: Improper Clearing of Heap Memory Before Release ('Heap Inspection')](https://cwe.mitre.org/data/definitions/244.html).

**Severity:** Medium | **CWE:** [CWE-244](https://cwe.mitre.org/data/definitions/244.html) | **Languages:** c, cpp, java

## What Gets Flagged

- C/C++: `free()`, `std::free()`, `g_free()`, `OPENSSL_free()`, `delete` and `delete[]` of a variable or field whose name ends in password, passwd, pwd, pw, passphrase, pin, secret, session_key, master_key, aes_key, private_key, enc_key, sym_key, key_material, plaintext, cleartext or credential(s), when no `memset`/`memset_s`/`explicit_bzero`/`OPENSSL_cleanse`/`sodium_memzero`/`SecureZeroMemory` names it in the 15 lines above.
- C/C++: `realloc()` of such a buffer, which frees the old block without wiping it.
- Java: `new String(field.getPassword())`, `String.valueOf(console.readPassword(...))`, which copy a clearable `char[]` into a `String` that can never be cleared.

```c
char *password = read_password_from_tty();
int ok = verify(user, password);
free(password);                                   // flagged
unsigned char *grown = realloc(kb->secret, n);    // flagged
```

```java
String password = new String(passwordField.getPassword());   // flagged
```

Not flagged: a buffer wiped before release (a plain `memset` that the optimiser may delete as a dead store is VNX-CWE1037-AUTO's concern), `sodium_free()`/`OPENSSL_clear_free()`, which wipe themselves, ordinary names such as `key`, `token` or `table`, a `char[]` cleared with `Arrays.fill`, comments, strings and test code. Garbage-collected languages without a reliable way to clear memory (Go, Python, JavaScript, PHP, Ruby) are not covered.

## Remediation

```c
explicit_bzero(password, strlen(password));
free(password);

/* or */
OPENSSL_clear_free(key, key_len);
```

```java
char[] password = passwordField.getPassword();
try {
    auth.login(user, password);
} finally {
    Arrays.fill(password, '\0');
}
```

To grow a secret buffer, allocate a new one, copy, wipe the old one and free it, instead of calling `realloc()`.
