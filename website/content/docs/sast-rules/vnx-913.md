---
title: "VNX-913 – Request Data Evaluated as Code"
description: "Reports eval/exec/compile in Python and eval, new Function and the vm module in JavaScript/TypeScript when the code they run comes from HTTP request data."
---

## Overview

HTTP request data becomes code the process runs (improper control of dynamically-managed code resources). In Python the rule reports the code argument of `eval()`, `exec()` and `compile()` carrying Flask, Django or DRF request data; in JavaScript/TypeScript it reports `eval()`, `new Function()`/`Function()`, `vm.runInNewContext`/`runInThisContext`/`runInContext`/`compileFunction` and `new vm.Script` given Express or Koa request data. The request value must appear in the call directly (also inside an f-string, template literal or concatenation) or through a variable assigned or destructured from it in the 15 lines above.

**Severity:** Medium | **CWE:** [CWE-913](https://cwe.mitre.org/data/definitions/913.html) | **Languages:** node, python

## Why This Matters

Code built from a request runs with the server's privileges: a client can read files, environment secrets and credentials, or start a shell.

## What Gets Flagged

```python
return str(eval(request.args.get("expr")))

code = request.form["snippet"]
exec(code, scope)
```

```javascript
const out = eval(req.query.expr);
const v = vm.runInNewContext(req.body.script, {});
```

Not flagged: `ast.literal_eval`, methods named eval (`model.eval()`, `redis.eval`), constant code strings, values passed through `int()`/`float()`/`parseInt()`/`Number()` first, values from configuration or the environment, comments and strings. VNX-94 covers code injection in more languages.

## Remediation

Do not evaluate client input. Parse the data it should carry (`json.loads`, `ast.literal_eval`, a numeric conversion) or evaluate expressions with a restricted expression library that has no access to the runtime.
