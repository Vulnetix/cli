---

## Overview

This rule reported HTTP request data that becomes code the process runs (CWE-913, improper control of dynamically-managed code resources): Python `eval()`, `exec()` and `compile()` given Flask, Django or DRF request data, and JavaScript/TypeScript `eval()`, `new Function()`/`Function()`, the `vm` module and `new vm.Script` given Express or Koa request data.

Every line it matched is also a [VNX-94](../vnx-94/) (code injection) finding: the same sinks, a superset of the request sources, the same one- and two-hop flows through assigned and destructured variables. Reporting both showed one problem twice, at two different severities. VNX-94 now owns these lines. It covers more languages (PHP and Ruby too), honours allowlist checks and numeric conversions, and reports at critical severity, which is the right severity for code a requester chooses. This rule therefore reports nothing. Its id is kept so that existing suppressions, baselines and policy references stay valid.

**Severity:** Medium | **CWE:** [CWE-913](https://cwe.mitre.org/data/definitions/913.html) | **Languages:** node, python

## Where These Findings Are Now Reported

```python
return str(eval(request.args.get("expr")))   # reported by VNX-94

code = request.form["snippet"]
exec(code, scope)                            # reported by VNX-94
```

```javascript
const out = eval(req.query.expr);                       // reported by VNX-94
const v = vm.runInNewContext(req.body.script, {});      // reported by VNX-94
```

Other forms of CWE-913 have their own rules: a request-chosen module for `require()`/`import()` is VNX-1027, request-chosen classes, modules and methods for reflection are VNX-470, and mass assignment is VNX-915. Non-constant evaluation with no visible request source is VNX-PY-002 and VNX-NODE-002.

## Remediation

Do not evaluate client input. Parse the data it should carry (`json.loads`, `ast.literal_eval`, a numeric conversion) or evaluate expressions with a restricted expression library that has no access to the runtime. See [VNX-94](../vnx-94/) for worked examples.
