title: "VNX-674 – Unconditional self-recursion or a disabled recursion guard"
description: "Reports accessors and methods that call themselves unconditionally with the same arguments (Python, JavaScript/TypeScript, Java), and Python sys.setrecursionlimit() raised to 50000 or more."
---

## Overview

VNX-674 maps to [CWE-674: Uncontrolled Recursion](https://cwe.mitre.org/data/definitions/674.html). It reports two concrete forms of recursion that nothing bounds:

1. **A function whose first statement calls itself with the same arguments.** Every call recurses until the stack overflows. The common cause is an accessor that forgot its backing field:
   - Python: an `@property` returning `self.<same name>`, an `@<name>.setter` assigning `self.<same name>`, a method returning `self.<same name>(<same parameters>)`.
   - JavaScript/TypeScript: a getter returning `this.<same name>`, a setter assigning `this.<same name>`, a method returning `this.<same name>(<same parameters>)`.
   - Java: a method whose first statement is `<same name>(<same parameters>)` or `this.<same name>(...)`.
2. **A disabled recursion guard.** `sys.setrecursionlimit()` raised to 50000 or more (or `10**5`+, `2**16`+, `sys.maxsize`). Deeply nested attacker input (JSON, GraphQL queries, XML) then overflows the C stack and kills the process instead of raising `RecursionError`.

**Severity:** Medium | **CWE:** [CWE-674](https://cwe.mitre.org/data/definitions/674.html) | **Languages:** python, node, java

## What Gets Flagged

```python
@property
def name(self):
    return self.name          # FLAGGED: should be self._name

sys.setrecursionlimit(100000) # FLAGGED
```

```javascript
set name(value) {
  this.name = value;          // FLAGGED: calls the setter again
}
```

```java
public String getId() {
    return getId();           // FLAGGED: should be this.id
}

public String getName() { return getName(); }   // FLAGGED
```

## What Is Not Flagged

- Accessors backed by another field (`self._name`, `this._name`, `this.id`).
- Delegation to another receiver or to `super`, overloads called with different or converted arguments (`log(msg, null)`, `count((int) n)`).
- Recursion with a base case or a depth check, smaller recursion limits, comments and string literals.

General recursion over untrusted nested data without a depth limit cannot be decided line by line and is not reported.

## Remediation

Use the backing field in accessors. Keep the default recursion limit and bound depth explicitly when walking untrusted structures:

```python
def walk(node, depth=0):
    if depth > MAX_DEPTH:
        raise ValueError("input nested too deeply")
    for child in node.children:
        walk(child, depth + 1)
```
