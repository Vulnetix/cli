## Overview

VNX-648 maps to [CWE-648: Incorrect Use of Privileged APIs](https://cwe.mitre.org/data/definitions/648.html). It reports two misuses of the POSIX identity calls (CERT POS36-C):

1. A user-id drop followed, within 15 lines of the same function, by a group call (`setgid`, `setegid`, `setregid`, `setresgid`, `setgroups`, `initgroups`).
2. A permanent drop to another user (`setuid`, `setreuid`, `setresuid` with an argument other than `getuid()`) in a file that never calls `setgroups`, `initgroups` or `setusercontext`.

**Severity:** Medium | **CWE:** [CWE-648](https://cwe.mitre.org/data/definitions/648.html) | **Languages:** c, cpp, python

## Why This Matters

Only a privileged process may change its group id. Once `setuid()` has given up root, the `setgid()` that follows fails, or succeeds only partly, and the process keeps root's group. A process that never calls `setgroups()` keeps the supplementary groups of the identity it started as, which for a daemon started by root often includes privileged groups.

## What Gets Flagged

Both findings are reported on the line of the user-id call (`setuid`, `setreuid`, ...), not on the group call that follows it.

```c
if (setuid(pw->pw_uid) != 0) exit(1);
if (setgid(pw->pw_gid) != 0) exit(1);          /* too late: already unprivileged */

if (setgid(pw->pw_gid) == -1) err(1, "setgid");
if (setresuid(pw->pw_uid, pw->pw_uid, pw->pw_uid) == -1)   /* no setgroups in the file */
```

```python
os.setuid(pw.pw_uid)
os.setgid(pw.pw_gid)
```

Not flagged: `setgroups(0, NULL); setgid(gid); setuid(uid);`, `os.initgroups(user, gid)` before the drop, `setuid(getuid())` in a setuid-root helper, `seteuid(0)` (see VNX-272) and temporary `seteuid` switches.

## Remediation

1. Drop in this order: `setgroups()` or `initgroups()`, then `setgid()`, then `setuid()`.
2. Check every return value (see VNX-273) and verify afterwards that `setuid(0)` fails.
3. Prefer `setresgid`/`setresuid` so that the real, effective and saved ids all change together.
