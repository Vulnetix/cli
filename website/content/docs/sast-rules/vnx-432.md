description: "Reports a C/C++ signal handler that does non-reentrant work (free, malloc, printf, syslog, exit, ...) and is installed for two or more signals with signal() or with a sigaction whose sa_mask is left empty, so one signal can interrupt the handler while it runs for another."
---

## Overview

VNX-432 maps to [CWE-432: Dangerous Signal Handler not Disabled During Sensitive Operations](https://cwe.mitre.org/data/definitions/432.html). When one handler serves several signals and nothing blocks the others while it runs, a second signal re-enters the handler half way through its own work: a global freed twice, a stdio buffer corrupted, a log write interleaved.

**Severity:** Low | **CWE:** [CWE-432](https://cwe.mitre.org/data/definitions/432.html) | **Languages:** c, cpp

## What Gets Flagged

- `signal()`/`std::signal`/`sigset`/`bsd_signal` registering the same function for two or more different signals.
- A `struct sigaction` whose `sa_handler`/`sa_sigaction` is that function, passed to `sigaction()` for two or more signals within thirty lines, with no `sigfillset`/`sigaddset` on its `sa_mask`.

In both cases only when the handler is defined in the same file and calls a function that is not async-signal-safe. The registration lines are reported.

```c
static void sh(int sig) { syslog(LOG_NOTICE, "signal %d", sig); free(global_buf); exit(0); }

signal(SIGHUP, sh);     // FLAGGED
signal(SIGTERM, sh);    // FLAGGED

sigfillset(&sa.sa_mask);
sa.sa_handler = on_shutdown;
sigaction(SIGINT, &sa, NULL);    // not flagged: the mask blocks the other signals
sigaction(SIGTERM, &sa, NULL);
```

Not reported: a handler installed for one signal, crash handlers shared between synchronous fault signals (SIGSEGV, SIGBUS, SIGFPE, SIGILL, SIGABRT), SIG_IGN/SIG_DFL, handlers that only set a `volatile sig_atomic_t` flag or call `write`/`_exit`, handlers defined in another file. A handler that writes an unprotected global is VNX-364.

## Remediation

1. Install handlers with `sigaction()` and `sigfillset(&sa.sa_mask)` so other signals are blocked while the handler runs.
2. Keep handlers minimal: set a `volatile sig_atomic_t` flag and do the work in the main loop.
