Java and Python."
---

## Overview

VNX-501 maps to [CWE-501: Trust Boundary Violation](https://cwe.mitre.org/data/definitions/501.html). The server-side session is trusted state: code that reads `session.getAttribute("role")` or `session["user_id"]` assumes the server put it there. Storing a value straight from the request in the session moves untrusted data across that boundary, so a later check that trusts the session trusts the attacker.

The rule reports:

- **Java:** `HttpSession.setAttribute()` / `putValue()` (on a session variable or on `request.getSession()`) whose key or value is `getParameter*`, `getHeader*`, `getCookies`, `getQueryString`, `getReader`, `getInputStream`, `getPathInfo`, `getRequestURI`, or a Spring `@RequestParam` / `@PathVariable` / `@RequestHeader` / `@CookieValue` / `@RequestBody` argument. The value may arrive inline or through up to four assignments in the 60 lines above, including a for-each over `getCookies()`, a single-line `if (...) x = y;`, a map entry read back under the same literal key, and a helper method of the same file that returns its parameter.
- **Python:** `session[...] = ...` (Flask `session`, `flask.session`, Django `request.session`) and `session.update()` / `setdefault()` with a key or value from `request.args/form/values/cookies/headers/json/data/GET/POST/COOKIES/META`, or from an object built from `request`, through the same kind of assignments (f-string interpolation included).

**Severity:** Medium | **CWE:** [CWE-501](https://cwe.mitre.org/data/definitions/501.html) | **Languages:** Java, Python

## What Gets Flagged

```java
// FLAGGED: request parameter becomes session state
String role = req.getParameter("role");
req.getSession().setAttribute("role", role);
```

```java
// FLAGGED: Spring request argument stored in the session
public String applyDiscount(@RequestParam("code") String code, HttpSession session) {
    session.setAttribute("discountCode", code);
```

```python
# FLAGGED
session["next_url"] = request.args.get("next")
request.session["lang"] = request.GET["lang"]
```

## What Is Not Flagged

- Constants and server-generated values (`session.setAttribute("nonce", UUID.randomUUID().toString())`).
- A value checked first by a line that names it with `.contains()`, `.matches()`, `re.match`, a `valid*`/`sanitize*` call or `in ALLOWED`.
- A session written after a password check or `authenticate()` call: the identity the server established.
- A map read under a different key than the one the request value was stored under, and a same-file helper whose return value is not derived from its parameters.
- A name that the enclosing method or function (at most 120 lines up) proves holds a constant where the session is written: a literal it was last assigned on every path; the branch an `if`/`else` or conditional expression takes when its condition folds to a constant (integer literals and integer locals assigned once, or in Python a literal tested with `in` / `not in` against a string local); the case a `switch` or `match` on a constant selects; the element a list index or a map, dict or `ConfigParser` key actually holds when that is a literal; in Python, a copy (`saved = label`) of what the name held at that line; the result of a same-file method or function whose every return is constant.
- Reading the session, comments and string literals.

```python
coupon = request.form.get("coupon", "")
fields = {"currency": "EUR"}
fields["coupon"] = coupon
currency = fields.get("currency")
session["cart.currency"] = currency   # not flagged: that key holds "EUR"
code = fields.get("coupon")
session["cart.coupon"] = code         # flagged
```

A value stored in a list or a Python dict is followed to a later read of that collection. Anything the analysis cannot resolve stays reported: a condition on run-time data, a helper in another file, a collection passed to a call.

## Remediation

1. Validate the value against an allowlist or a strict pattern before it enters the session.
2. Prefer storing a server-side lookup result (the user record found by id) over the raw request text.
3. Keep authorisation state (roles, ownership) derived on the server, never copied from the request.
