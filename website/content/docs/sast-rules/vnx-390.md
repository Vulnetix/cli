---
title: "VNX-390 – Detection of Error Condition Without Action"
description: "A Java catch block that is empty, or whose only statement evaluates the exception and discards the result, so a detected failure is silently dropped."
---

## Overview

VNX-390 maps to [CWE-390: Detection of Error Condition Without Action](https://cwe.mitre.org/data/definitions/390.html). It reports a catch block whose body is empty (on one line, `catch (E e) {}`, or across lines with only blank lines before the closing brace), and a catch block whose only statement evaluates the exception and drops the value (`e.toString();`, `e.getMessage();`).

Not reported: a catch block that logs, rethrows, returns, restores the interrupt flag or does anything else; an empty block with a comment explaining why; an exception variable named `ignored`, `ignore`, `expected`, `unused` or `_`; test sources; comments and string literals.

**Severity:** Low | **CWE:** [CWE-390](https://cwe.mitre.org/data/definitions/390.html) | **Languages:** java

## Why This Matters

Swallowing an exception lets the program continue with whatever partial state the try block left: a half-written file, a missing configuration value, an unauthenticated connection. Nothing records that it happened, so the failure surfaces later and elsewhere.

## What Gets Flagged

```java
} catch (IOException e) {          // FLAGGED
}

} catch (Exception e) {}           // FLAGGED

} catch (JSONException e) {        // FLAGGED
    e.toString();
}
```

Not flagged: `catch (IOException e) { log.warn("cannot read", e); }`, `catch (InterruptedException e) { Thread.currentThread().interrupt(); }`, `catch (NumberFormatException ignored) {}`, an empty block containing `// optional file, defaults apply`.

## Remediation

1. Log the exception, rethrow it (wrapped if needed), or handle the failure explicitly.
2. If ignoring it is correct, name the variable `ignored` and add a comment saying why.
