## Overview

VNX-468 maps to [CWE-468: Incorrect Pointer Scaling](https://cwe.mitre.org/data/definitions/468.html). Reports pointer arithmetic in C/C++ that multiplies an offset by sizeof() on a pointer or array whose element is wider than one byte (int, long, double, *_t, struct), which the compiler already scales, so the offset lands sizeof(T) times too far. Byte pointers (char, uint8_t, void), allocation and length arguments, and member expressions are not reported.

**Severity:** Medium | **CWE:** [CWE-468](https://cwe.mitre.org/data/definitions/468.html) | **Languages:** c, cpp

## Why This Matters

This weakness class (Incorrect Pointer Scaling) creates a concrete exploit surface: the rule searches for the concrete source-level patterns most commonly associated with CWE-468 and surfaces them for review. Each finding should be evaluated in context — the rule catches the pattern, not the context.

## What Gets Flagged

```c
// FLAGGED: values is int *, the compiler already scales by sizeof(int)
total += *(values + i * sizeof(int));

// FLAGGED: struct pointer advanced by a byte count
r += sizeof(struct record);

// NOT FLAGGED: byte arithmetic on an unsigned char buffer
memcpy(out + i * sizeof(uint32_t), &words[i], sizeof(uint32_t));
```
