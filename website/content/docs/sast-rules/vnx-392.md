---
title: "VNX-392 – Missing Report of Error Condition"
description: "A Python web handler catches an exception and returns an error body (jsonify, JsonResponse, HttpResponse, Response, Sanic json or a dict) without an error status, so the client receives 200 OK for a failed request."
---

## Overview

VNX-392 maps to [CWE-392: Missing Report of Error Condition](https://cwe.mitre.org/data/definitions/392.html). It reports, inside an `except` block, a `return` of `jsonify(...)`, `JsonResponse(...)`, `JSONResponse(...)`, `HttpResponse(...)`, `Response(...)` or `make_response(...)`, or of a dict literal in a Flask, FastAPI, Django or Starlette module, whose content says the request failed (error, fail, invalid, not found, denied, unauthorized, forbidden, exception, missing, or the exception itself) and which sets no error status: no `status=`/`status_code=` argument and no `(body, 4xx)` tuple, or one that explicitly says 200 (`status=200`, `(body, 200)`, `HTTPStatus.OK`). A call broken across lines is read as one statement.

Not reported: a response that sets a status, `abort()` or `raise`, a re-rendered HTML template (a form shown again with its error), a dict returned from a module that is not a web handler, test files, comments and strings.

**Severity:** Low | **CWE:** [CWE-392](https://cwe.mitre.org/data/definitions/392.html) | **Languages:** python

## Why This Matters

Clients, proxies, retries, monitoring and caches decide success by the status code, not by reading the body. An error answered with 200 is cached as a good response, never retried, never alerted on, and treated as success by any client that does not parse the body. Writing `'status': '500'` into the JSON does not change what is sent on the wire.

## What Gets Flagged

```python
try:
    order.save()
except ValueError as e:
    return jsonify({"error": str(e)})                      # FLAGGED

except Cart.DoesNotExist:
    return JsonResponse({'message': 'failed', 'status': '500'})  # FLAGGED
```

Not flagged:

```python
except ValueError as e:
    return jsonify(error=str(e)), 400
except OSError:
    return JsonResponse({"error": "storage unavailable"}, status=503)
```

## Remediation

1. Return the matching 4xx/5xx status with the error body: `return jsonify(error=...), 400`, `JsonResponse(..., status=400)`.
2. Or raise an HTTP exception (`abort(404)`, `HTTPException`) and let the framework produce the response.
